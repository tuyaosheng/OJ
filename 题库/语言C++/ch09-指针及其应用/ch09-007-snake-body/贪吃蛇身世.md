# 贪吃蛇身世——讲解稿

## 一、题目解读

蛇每吃一个食物就在**头部**长一节——这正是链表**头插法**的具象画面。最后从头到尾输出，因为最后吃的在最前面，结果就是输入的逆序。

## 二、思路分析

链表和数组的本质区别：数组的"下一个"靠下标 +1，链表的"下一个"靠**指针**。节点在内存里可以东一个西一个，全靠 next 指针串起来。

头插三步（画图讲）：

1. `new` 出新节点，填上数据；
2. 新节点的 next **先**指向旧头——先接住后面的整条蛇；
3. head 再改指新节点。

**顺序反了（先改 head）整条蛇就丢了**——这是链表第一课要刻进骨头里的话。

## 三、代码讲解

- `Node *head = nullptr` 表示空表，插入 n 次后 head 指向最后吃的那节；
- 遍历模板 `for (Node *p = head; p != nullptr; p = p->next)`——终止条件是 `p != nullptr` 而不是数下标；
- 输出用 first 标志控制空格，行末不留多余空格。

诚实地说：本题用数组存下来倒序输出也能 AC。但**练的就是链表**——第 22 章链式栈、第 24 章二叉树，节点+指针的功夫全在这三行头插里。

## 四、易错点

1. 头插顺序反了（先 `head = p` 再 `p->next = head`）→ 自己指自己，链断；
2. 遍历条件写 `p->next != nullptr` → 少输出最后一节；
3. 忘了初始化 `head = nullptr` → 野指针，遍历崩溃；
4. n 最多 10^4，new 一万个节点毫无压力，不必 delete（程序结束系统回收；工程里要还，竞赛里从权）。

## 五、小结

头插法 = 逆序；以后想"倒着来"除了数组反转，还有链表这条路。节点+指针的画图能力，就是第三部分数据结构的门票。
