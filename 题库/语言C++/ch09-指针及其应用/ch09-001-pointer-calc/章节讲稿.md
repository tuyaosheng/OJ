## 开场：掀开变量的"地址"底牌

前面八章你一直把变量当成"带名字的盒子"用：`int a = 10;`，你只关心盒子叫 `a`、里面装的是 `10`。今天要多问一句：**这个盒子放在哪儿？** 计算机的内存是一长条连续的空间，每一个字节都有一个编号，这个编号就是**地址**。变量 `a` 不只是"名字+值"，它背地里还有第三个属性：**门牌号**。

**指针，就是一个专门用来存"门牌号"的变量**。C++ 里两个符号把这件事说清楚：

- `&`：问"你住哪"——取地址；
- `*`：拿着地址"按门牌号上门"——解引用，找到那个盒子本人。

黑板上写：

```cpp
int a = 10;
int *p = &a;   // p 里存的不是 10，是 a 的门牌号
*p = 20;       // 按门牌号上门，把住在里面的那个数改成 20
```

`*p = 20` 执行完，`a` 的值会变成什么？——`20`。**`p` 和 `a` 是两个不同的盒子（各有各的地址），但 `*p` 这个写法能穿过 `p`，直接摸到 `a` 本人**。这句话现在听着抽象，切到 `内存地址演示.html` 的"取地址与解引用"页签，把这三行代码逐步点开：先看 `a` 这个盒子怎么凭空出现、值是 10；再看 `p=&a` 执行后，`p` 盒子里冒出一个地址值，同时画面上出现一支箭头从 `p` 指向 `a`；最后看 `*p=20` 执行时，箭头闪一下，`a` 盒子里的值真的从 10 跳成了 20——**指针不是抽象符号，它是"一个盒子指向另一个盒子"这么直观的一件事**。

坦白说：真上竞赛，直接写裸指针的场合不算多（引用、STL 更常用）。但指针是理解**数组名的真相、传参能不能改外面、动态开内存、以及第三部分链式数据结构**的钥匙。本章的目标不是让你以后处处用指针，是让你**看得懂、写得对、不发怵**。

## 【例1】指针加乘：用指针访问两个变量

把刚才的玩具例子换成真题：输入两个整数 `a` 和 `b`，要求**通过指针**访问它们，算出和与积。

```cpp
int a, b;
cin >> a >> b;
int *pa = &a, *pb = &b;
long long sum  = (long long)(*pa) + (*pb);
long long prod = (long long)(*pa) * (*pb);
```

带真数字走一遍，比如 `a = 6, b = 7`：`pa` 存的是 `a` 的地址，`pb` 存的是 `b` 的地址。`*pa` 按地址找到 `a`，取出值 `6`；`*pb` 找到 `b`，取出值 `7`。`sum = 6 + 7 = 13`，`prod = 6 * 7 = 42`。**从头到尾没有一处直接写 `a` 或 `b`**，全部通过指针"绕一手"拿到值——这道题不图别的，就图让你亲手写一遍 `&` 和 `*`，手指头记住这两个符号该往哪打。

停下来问一句："`(long long)` 这个强制转换加在 `*pa` 前面而不是加在 `sum` 前面，为什么？"——如果两个 `int` 相乘时已经溢出了，**转换发生得太晚也没用**，两个 `int` 相乘的那一刻就已经在 `int` 的范围里出错了；把其中一个操作数提前转成 `long long`，乘法就会按 `long long` 的规则做，这是防溢出的老话题，第 6 章讲阶乘、第 11 章讲高精度时都反复念叨过。

## 【例2】指针与数组：数组名就是首地址

**这是本章最容易让人愣一下、又最重要的一句话：数组名，本质上就是数组第一个元素的地址**。`a` 约等于 `&a[0]`。既然数组名就是一个地址，指针当然可以拿它当起点，一路往后走着访问整个数组：

```cpp
int a[5] = {3, 1, 4, 1, 5};
long long sum = 0, maxv = a[0];
for (int *p = a; p < a + 5; p++) {
    sum += *p;
    if (*p > maxv) maxv = *p;
}
```

黑板上摆出 `a = [3, 1, 4, 1, 5]`，把 `p` 想象成一根手指，从 `a[0]` 那格开始，每次往右挪一格：

`p` 指向 `a[0]=3`：`sum = 0+3 = 3`，`3 > maxv(3)`？不成立，`maxv` 还是 3。`p` 指向 `a[1]=1`：`sum = 3+1 = 4`，`1>3`不成立。`p` 指向 `a[2]=4`：`sum=4+4=8`，`4>3`成立，`maxv` 更新成 4。`p` 指向 `a[3]=1`：`sum=8+1=9`，`1>4`不成立。`p` 指向 `a[4]=5`：`sum=9+5=14`，`5>4`成立，`maxv` 更新成 5。`p` 再往后挪，`p == a+5`，超出范围，循环停止。最终 `sum=14, maxv=5`。

这里必须停下来问穿本章最核心的一个误解："`p++` 到底往前走了几个字节？" 学生大概率会说"1个字节"。**错，走的是"一个 `int` 的大小"**（通常 4 字节），因为 `p` 的类型是 `int*`，编译器知道"指针加一"该跳过多大一块——这就是为什么 `*(a+i)` 和 `a[i]` 是完全等价的两种写法：**下标 `a[i]`，说穿了就是"指针算术 `*(a+i)`" 的一层糖衣**，只是写起来更顺眼。

切 `内存地址演示.html` 的"指针遍历数组"页签，把 `[3,1,4,1,5]` 敲进去，看那支箭头怎么一格一格往右挪，`sum` 和 `maxv` 的数字怎么跟着实时更新——这跟刚才黑板上手算的五步一模一样，只是换成了动画。

## 【练1】指针传参：终于能改动"外面"的变量了

第 6 章讲函数的时候留了一个悬念："函数里改形参，外面那个变量不会跟着变——这是值传递"。现在揭晓怎么打破这条规矩。

先看一个最小的反例。假设有这样一个（本章练习真正代码之外的）值传递版 swap：

```cpp
void badSwap(int x, int y) { int t = x; x = y; y = t; }
int a = 3, b = 7;
badSwap(a, b);   // 调用完，a 还是 3，b 还是 7，什么都没变
```

`badSwap` 里的 `x, y` 只是 `a, b` 的两份拷贝，函数在自己的栈帧里怎么倒腾这两份拷贝，`a` 和 `b` 本尊毫不知情，函数一返回，这两份拷贝连同它们所在的栈帧一起烟消云散。

现在换成指针版，这次是真交出"门牌号"，而不是交出"值"：

```cpp
void mySwap(int *x, int *y) { int t = *x; *x = *y; *y = t; }
int a = 3, b = 7;
mySwap(&a, &b);   // 调用完，a 变成 7，b 变成 3，真的换过来了
```

同样的 `a=3, b=7`，这次传进去的是 `&a` 和 `&b`——两个地址。函数内部的 `x` 存的是 `a` 的地址，`y` 存的是 `b` 的地址。`t = *x`：按 `x` 的地址找到 `a`，取出 `3`，存进 `t`。`*x = *y`：按 `y` 的地址找到 `b`，取出 `7`，写回 `x` 指向的地方——也就是**直接把 `a` 改成了 `7`**。`*y = t`：把 `t` 里的 `3` 写回 `y` 指向的地方——**直接把 `b` 改成了 `3`**。函数一返回，`a` 真的变成了 7，`b` 真的变成了 3。

**这就是本章最重要的"啊哈"时刻**：值传递交出去的是"值的拷贝"，函数怎么改都够不着外面；指针传参交出去的是"地址"，函数拿着这张门牌号，能直接闯进调用者的地盘去改东西。切 `内存地址演示.html` 的"指针传参"页签，画面会把两版 `swap` 摆在一起对照：值传递那一版，子调用栈帧里的箭头怎么也够不到调用者的盒子，函数返回后调用者的两个盒子原封不动；指针传参那一版，子调用栈帧里的指针箭头直接穿过去指向调用者的盒子，函数一执行，调用者的盒子当场改变，函数返回后改动**留下来了**。两版数据完全一样（`a=3,b=7`），画面并排放，一眼看出差别在哪。

本章练习"三数排序"就是这个技巧的实战：输入三个数，用指针传参写一个 `sort3`，让三个变量最终满足从小到大：

```cpp
void sort3(int *a, int *b, int *c) {
    if (*a > *b) mySwap(a, b);
    if (*a > *c) mySwap(a, c);   // 这时 *a 已经是最小
    if (*b > *c) mySwap(b, c);   // *b <= *c
}
```

带 `a=3, b=9, c=5` 走一遍：`*a>*b`？`3>9` 不成立，跳过。`*a>*c`？`3>5` 不成立，跳过。`*b>*c`？`9>5` 成立，交换 `b,c`：`b` 变 5，`c` 变 9。最终 `a=3, b=5, c=9`，恰好从小到大——三次判断、最多一次交换，比三个数写三个 `if-else` 分支清楚得多。

顺带对照第 6 章："C++ 里如果不是必须写指针，正常应该优先用引用 `void mySwap(int &x, int &y)`——引用是更安全的指针糖，效果一样，还不用担心解引用空指针。但本章要求你能看懂、能写指针版，因为教材、老代码、以及后面要学的链表，指针是绕不开的。"

## 【例3】动态内存：内存是借来的，用完要还

前面所有数组，大小都是编译的时候就定死的。如果 `n` 是运行时才读进来的，数组开多大？可以用 `new` 在程序运行时**现场申请**一块内存：

```cpp
long long *b = new long long[n + 1];   // 现开一块能装 n+1 个 long long 的内存
// ... 用法和普通数组一模一样，下标、遍历都行
delete[] b;                             // 用完必须还回去
```

拿 `n=4`，输入 `a = [3, 1, 4, 2]` 走一遍前缀和：`b[0] = 0`（约定俗成的哨兵）。`b[1] = b[0] + a[1] = 0 + 3 = 3`。`b[2] = b[1] + a[2] = 3 + 1 = 4`。`b[3] = b[2] + a[3] = 4 + 4 = 8`。`b[4] = b[3] + a[4] = 8 + 2 = 10`。最终 `b = [0, 3, 4, 8, 10]`——`b[i]` 就是前 `i` 个数的和，这正是第 10 章要正式讲的前缀和思想，这里先用指针/动态数组的外壳提前碰一次面。

问学生一句实在话："这道题不用 `new`，直接开个 `long long b[100005]` 的全局数组，行不行？"——**行，而且竞赛里这样做的人更多**，全局数组更省心、不用操心配对释放。`new` 在这道题里的意义，不在于"非用不可"，而在于让你亲手体会一次"内存是运行时问操作系统借的，借了要还"这件事——**`new[]` 配 `delete[]`，`new` 配 `delete`，这个配对关系本章要求刻在脑子里**，链表、二叉树这些以后天天用 `new` 的结构，全靠这个习惯不出内存泄漏。

## 【练2】指针与字符串：双指针从两头往中间走

字符串倒序：把一个字符数组头尾翻过来。两个指针，一个在开头 `l`，一个在结尾 `r`，往中间碰头，边走边交换：

带 `s = "abcde"`（下标 0~4）走一遍：`l` 指向下标 0（`a`），`r` 指向下标 4（`e`），交换，字符串变成 `"ebcda"`；`l` 移到 1，`r` 移到 3：`l` 指向 `b`，`r` 指向 `d`，交换，变成 `"edcba"`；`l` 移到 2，`r` 移到 2，`l` 和 `r` 碰头了，**中间这个字符不用换（换自己等于没换）**，循环停止。最终 `"edcba"`，就是 `"abcde"` 倒过来。这是第 5 章判断回文时"头尾双指针"手法的直接复用，只是这次真的用指针变量去写，而不是用下标变量。

## 【练3】数组中第一个质数：函数返回一个"位置"

在数组里从左到右找第一个质数，找到返回它的下标，找不到返回 `-1`（如果写成返回指针版本，找不到就返回 `nullptr`）。逻辑很直白：遍历 + 判素 + 一遇到就交，但这道题真正的教学点在收尾那一下——**返回指针的函数，调用完必须先判空，才能解引用**，就像现实中"先看有没有找到人，再决定要不要跟他握手"，跳过判空直接解引用一个 `nullptr`，是运行时崩溃里最常见的一种。

## 顺带一提：贪吃蛇的单链表头插法（练4）

链表是本章"指针 + 结构体"合体的产物，还没在讲义主线里正式展开，但练习 4 提前让你摸一次链表最基本的操作——**头插法**：

```cpp
struct Node { int val; Node *next; };
Node *head = nullptr;
Node *p = new Node;
p->val = x;
p->next = head;   // 新节点的 next 先指向原来的头
head = p;          // head 再改指向新节点，插入完成
```

贪吃蛇每吃一个食物，就在**头部**长一节。假设依次吃了 `5, 2, 8` 三个食物：吃 `5` 时链表是空的，新建节点 `5`，它的 `next` 指向 `nullptr`（原来的 `head`），然后 `head` 指向这个节点——链表变成 `5`。吃 `2` 时，新建节点 `2`，它的 `next` 指向刚才那个 `head`（也就是节点 `5`），然后 `head` 改指向节点 `2`——链表变成 `2 → 5`。吃 `8` 时，新建节点 `8`，`next` 指向当前 `head`（节点 `2`），`head` 改指向节点 `8`——链表变成 `8 → 2 → 5`。从头到尾输出：`8 2 5`，正好是吃的顺序倒过来——**最后吃的在头，最先吃的在尾**，这正是头插法的天然效果，不用额外写代码去倒序。

切 `内存地址演示.html` 的"链表头插法"页签，把 `5, 2, 8` 依次点进去，看每次新节点的箭头怎么先指向旧的 `head`，再看 `head` 这个箭头怎么挪到新节点身上——两支箭头谁先动谁后动，顺序不能反，这是本章遗留给第三部分（栈、队列、链式结构）的地基。

## 学生最容易栽的坑

1. 野指针：声明了但没初始化就直接解引用——指针必须指向有效对象，暂时没地方指就赋 `nullptr`；
2. 解引用前不判空：`*p` 之前先 `if (p != nullptr)`，尤其是"返回指针，找不到给 nullptr"这类函数用完之后；
3. `new[]` 要配 `delete[]`，单个 `new` 要配单个 `delete`，配错或者忘记释放，都会埋下隐患；
4. 指针类型不匹配还硬转——本章一律不允许，类型信息是"指针加一该跳多远"的依据，乱转会跳错步长；
5. `int *p, q;`——只有 `p` 是指针，`q` 只是普通 `int`！每个变量前都要单独写星号；
6. 返回**局部变量**的地址——函数一结束，栈帧上那个盒子就没了，返回的地址成了野指针，这是最经典的坑之一；
7. 双指针循环条件把 `l < r` 写成 `l <= r`，会在正中间那个字符/元素上多做一次"自己换自己"——结果没错，但值得想清楚为什么没错。
