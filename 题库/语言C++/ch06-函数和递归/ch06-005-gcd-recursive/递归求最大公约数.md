# 讲解稿：递归求最大公约数（ch06-005）

## 一、题目解读

用**递归**求两个正整数的最大公约数。课件例 6.12。第 3 题我们用循环写过辗转相除，这次换递归写——同一个算法，两种表达，正好对比"迭代 vs 递归"。

## 二、思路分析

欧几里得（辗转相除）的数学事实：**gcd(m, n) = gcd(n, m mod n)**。也就是说，两个数的最大公约数，等于"较小数"和"余数"的最大公约数——问题规模在缩小。什么时候停？当 n 变成 0，此时 m 就是答案（任何数和 0 的最大公约数是它自己）。

翻译成递归两要素：
- **边界**：n == 0 → 返回 m；
- **递推**：否则 → gcd(n, m % n)。

短短一行递推，把辗转相除的"反复取余"表达得无比优雅——这就是递归的美：**定义即实现**。

## 三、代码讲解

```cpp
int gcd(int m, int n)
{
    if (n == 0) return m;        // 边界：余数为 0，m 就是答案
    return gcd(n, m % n);        // 递推：转化为规模更小的同类问题
}
```

跟 `gcd(12, 18)` 走一遍：
- gcd(12,18) → gcd(18, 12%18=12) → gcd(18,12)
- gcd(18,12) → gcd(12, 18%12=6)
- gcd(12,6) → gcd(6, 12%6=0)
- gcd(6,0) → n==0，返回 6 ✓

即使一开始 m < n（如 12 和 18），第一步 `m % n = 12` 会自动把大小顺序调正，无需特判——递归自己摆平了。

对比第 3 题的循环版：循环版用 while 反复更新变量，递归版用函数自调用。两者等价，但递归更接近数学定义、更短；循环版不占用调用栈、更省。**两种都要会写**。

## 四、易错点

1. 边界判断写成 `m == 0`——方向错了，辗转相除是让 n（余数）归零。
2. 递推参数顺序写反 `gcd(m % n, n)`——虽然某些情况也能凑对，但标准写法是 `gcd(n, m % n)`，别记混。
3. 忘了边界导致无限递归。

## 五、小结

递归版辗转相除一行搞定，是"递归优雅性"的最佳范例。把它和第 3 题的循环版摆在一起看，你就理解了：**递归和循环是同一件事的两种写法**——递归"向下拆解"，循环"向前推进"。以后遇到"问题能拆成同类小问题"的场景，优先想想递归。
