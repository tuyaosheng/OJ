## 开场：为什么突然要学"函数"

先不讲定义，先制造一个麻烦。回想第 4 章判断区间内有多少个素数，你写的核心逻辑大概是这样一段循环，判断某个数是不是素数。现在如果一道新题要求你"输出前 20 个素数"，你打算怎么办？把那段循环再复制一遍粘到新地方？如果这道题里要判断素数的地方有三处，是不是要粘三遍？粘完之后如果发现判断逻辑写错了一个符号，是不是三个地方都要改，还很可能漏改一处？

这就是函数要解决的问题：**把一段反复要用的逻辑，包起来，起个名字，需要的时候喊它一声就行**。函数三件事：叫什么名（函数名）、要什么原料（参数）、干完活交回什么（返回值）。写一次，到处调用，改一次，处处生效。

函数还带来一个副产品：**函数可以调用它自己**。这叫**递归**，本章只是入门，第 14 章才是真正的主场，但递归这道坎，早一点迈过去，后面学搜索、动态规划都会轻松很多。

## 函数的定义与调用：拿判断素数练手（例1）

黑板上写题目要求：给一个整数，判断是不是素数。函数写出来：

```cpp
bool isPrime(int n) {
    if (n < 2) return false;                    // 1 和更小的数都不是素数
    for (long long i = 2; i * i <= n; i++)
        if (n % i == 0) return false;            // 找到约数，肯定不是素数
    return true;                                  // 循环走完没找到约数，是素数
}
```

别急着看代码，先手算两个具体的数，跟学生一起过一遍函数内部实际发生了什么。

**先算 `isPrime(15)`**：`n = 15`，不小于 2，进循环。`i = 2`：`2*2 = 4 ≤ 15` 成立，`15 % 2 = 1`，不是约数，`i` 变 3。`i = 3`：`3*3 = 9 ≤ 15` 成立，`15 % 3 = 0`——找到约数了，**函数立刻 `return false`，循环不往下走了**。`isPrime(15)` 返回 `false`。

**再算 `isPrime(13)`**：`n = 13`。`i = 2`：`4 ≤ 13`，`13 % 2 = 1`，继续。`i = 3`：`9 ≤ 13`，`13 % 3 = 1`，继续。`i = 4`：`16 ≤ 13`？不成立，**循环直接结束，一次约数都没找到**。走到最后一行 `return true`。`isPrime(13)` 返回 `true`。

这时候问一句："`i` 为什么只要试到 `i*i <= n`，不用试到 `n` 本身？" 让学生回忆第 4 章讲过的道理：如果 `n` 有一个大于 `sqrt(n)` 的约数，必然还搭配一个小于等于 `sqrt(n)` 的约数，后者一定先被枚举到——这是函数封装前就该懂的优化，封装只是换了个包装。

再问一句关于函数本身的："如果我在 `isPrime` 函数里面把参数 `n` 改成别的值，比如硬塞一行 `n = 0;`，外面调用它的那个变量会不会跟着变成 0？"——不会。**参数 `n` 是调用时传进来的值的一份拷贝**，函数里怎么折腾这份拷贝，函数外面那个原始变量都不知情。这条规矩现在只需要记住，第 9 章讲指针传参、以及本章练习"三数排序"的引用版，才是真正要"改外面变量"的时候，到时候再回头对照这句话，会恍然大悟。

切到 `函数调用栈演示.html` 的"函数调用"页签，输入 15，点几下"下一步"，看 `main` 和 `isPrime` 两个栈帧怎么分工：`main` 喊一声 `isPrime(15)`，新栈帧压进去，循环跑完再把 `false` 带回来，栈帧随即消失，`main` 里的变量根本没被碰过。

## 函数复用：一个函数被调好几次（练1、练2）

函数最直接的好处不是"少打字"，是**同一段逻辑可以被反复借用，而且互不干扰**。组合数 `C(m,n) = m!/(n!·(m-n)!)`，写一个 `fact(k)` 算阶乘：

```cpp
long long fact(int x) {
    long long s = 1;
    for (int i = 2; i <= x; i++) s *= i;
    return s;
}
```

算 `C(5,2)`：先调 `fact(5)`——`s` 从 1 开始，依次乘 2、3、4、5，得到 `120`。再调 `fact(2)`：乘 2，得到 `2`。再调 `fact(3)`：乘 2、3，得到 `6`。三次调用互不干扰，各自的 `s` 都是各自函数里的局部变量，谁也看不见谁。最后 `C(5,2) = 120 / (2 × 6) = 120 / 12 = 10`。同一个函数被调三次，比复制三段阶乘循环干净得多。

最小公倍数练习里，把这个"函数调函数"再往前推一步：`lcm(x,y) = x / gcd(x,y) * y`，先求 `gcd`，再拿结果去算 `lcm`。手算一遍 `x=4, y=6`：`gcd(4,6)` 用辗转相除（这里先用循环版体会一下，例3 会讲同一个定义的递归版）——`a=4,b=6`：先 `r = 4%6 = 4`，`a` 变 6，`b` 变 4；再 `r = 6%4 = 2`，`a` 变 4，`b` 变 2；再 `r = 4%2 = 0`，`a` 变 2，`b` 变 0；`b` 变成 0，循环停，返回 `a = 2`。所以 `gcd(4,6)=2`，`lcm = 4/2 * 6 = 2*6 = 12`。

停下来问一句："这句代码为什么写成 `x/gcd(x,y)*y`，而不是 `x*y/gcd(x,y)`？两个数学上不是一样的吗？" 让学生算一下 `x*y` 在 `x,y` 很大的时候会不会先溢出 `int`——**除法放前面，先把数变小，再乘，能延后溢出发生的时机**，这是竞赛代码里一个很小但很容易被问到的细节。

## 递归入门：先学会"跟着调用栈走一遍"（例2、例3）

递归说穿了就两件事——记住这两条，后面十几章的递归题都逃不出这个框架：

1. **边界**：规模小到某个程度，不用再递归，直接给答案；
2. **自身调用，且规模一定要变小**，不然递归永远停不下来。

**先看递归求幂（例2）**：`power(x,n)`，边界是 `n==0` 时返回 1，否则 `power(x,n) = x * power(x,n-1)`。

```cpp
long long power(int x, int n) {
    if (n == 0) return 1;
    return (long long)x * power(x, n - 1);
}
```

黑板上手算 `power(2,4)`，分两个阶段讲，**递归的"递去"和"归来"**：

**递去（一路往下喊，栈越叠越高）**：`power(2,4)` 要等 `power(2,3)` 的结果，先不能算；`power(2,3)` 要等 `power(2,2)`；`power(2,2)` 要等 `power(2,1)`；`power(2,1)` 要等 `power(2,0)`；`power(2,0)` 碰到边界 `n==0`，**不用再往下等了，直接返回 1**。这一路压栈，压了 5 层。

**归来（一路往回交作业，栈一层层被拆掉）**：`power(2,0)` 交出 `1`；`power(2,1)` 拿到这个 `1`，算 `2 * 1 = 2`，交出去；`power(2,2)` 拿到 `2`，算 `2 * 2 = 4`，交出去；`power(2,3)` 拿到 `4`，算 `2 * 4 = 8`，交出去；`power(2,4)` 拿到 `8`，算 `2 * 8 = 16`，最终交给 `main`。答案 `16`，跟直接算 `2^4` 对得上。

切到 `函数调用栈演示.html` 的"递归求幂"页签，输入 `x=2, n=4`，点"下一步"先看栈一路叠高（每次调用挂起、等下一层），叠到底之后再看栈一层层塌下来（每层拿到孩子的返回值，乘一下，交给上一层）——这个"叠高再塌下来"的画面，就是以后遇到任何递归题都要在脑子里过一遍的东西。

**再看递归求最大公约数（例3）**：`gcd(m,n)`，边界 `n==0` 时返回 `m`，否则 `gcd(m,n) = gcd(n, m%n)`。手算 `gcd(24,18)`：`gcd(24,18)` 调 `gcd(18, 24%18)` 也就是 `gcd(18,6)`；`gcd(18,6)` 调 `gcd(6, 18%6)` 也就是 `gcd(6,0)`；`gcd(6,0)` 碰到边界 `n==0`，直接返回 `6`。

归来阶段问一句刁钻的："`gcd(18,6)` 拿到 `gcd(6,0)` 交上来的 `6` 之后，它自己还要不要做点什么运算，才能交给上一层？"——**不用，原样往上传就行**。这跟刚才 `power` 归来时"还要乘一下"完全不一样：`power` 的每一层在归来路上都要干活（乘 `x`），而 `gcd` 一旦递到最底、拿到答案，剩下的每一层只是"把这张纸条原封不动往上递"。这种"归来阶段不用再计算，答案已经在最底层算完"的递归，叫**尾递归**，先混个脸熟，不要求现在就能一眼分辨，只要求看得出"这一次递归的归来阶段到底做没做事"。

切 `函数调用栈演示.html` 的"递归求最大公约数"页签，输入 `24` 和 `18`，对照着刚才黑板上的三步走一遍——特别让学生盯着"归来"阶段的动画，看每一层是不是真的什么都没算，只是把值往上传。

## 递归枚举：一棵"选或不选"的树（练3）

子集和问题：给一个数组，能不能选出若干个数（可以一个都不选，也可以全选），让它们的和恰好等于 `m`。核心代码：

```cpp
void dfs(int i, long long sum) {
    if (found) return;
    if (i > n) { if (sum == m) found = true; return; }
    dfs(i + 1, sum + a[i]);   // 选第 i 个
    dfs(i + 1, sum);          // 不选第 i 个
}
```

拿 `a = [2, 3, 5]`（`n=3`），`m=5` 走一遍，黑板上画一棵树，一步步问学生"这一步该往哪个分支走"：

`dfs(1,0)` 处理第 1 个数（值 2），先走"选"这条路：`dfs(2,2)`。再处理第 2 个数（值 3），还是先走"选"：`dfs(3,5)`。再处理第 3 个数（值 5），还是先走"选"：`dfs(4,10)`——这时候 `i=4 > n=3`，到底了，检查 `sum=10` 是不是等于 `m=5`？不是，这条路死了，函数返回。

代码退回到 `dfs(3,5)` 那一层，它还有第二条没走的路——"不选"第 3 个数：`dfs(4,5)`。`i=4 > n=3`，到底了，检查 `sum=5` 是不是等于 `m=5`？**是！** `found` 被设成 `true`，答案找到：选第 1 个（2）和第 2 个（3），不选第 3 个（5），`2+3=5`。

问学生："`if (found) return;` 这一句删掉，程序还会不会算对？"——答案还对，但会白白把剩下没探索完的分支也跑一遍，浪费时间。这一句叫**剪枝**：已经拿到答案了，没必要再往下凑。3 个数一共 `2³=8` 种选法（每个数选或不选），这棵树刚才只走了 4 个节点就找到了答案，剩下 4 种选法根本没被展开——这就是"剪枝"省下来的计算量，第 15 章搜索回溯会把这个思想用到极致。

## 顺带一提：迷你汉诺塔的递归公式（练4）

练习 4 是《原神》里的齿轮谜题，本章只要求递归求出**最少步数**，公式是 `T(1)=1`，`T(n) = 2·T(n-1) + 1`：

```cpp
long long T(int n) {
    if (n == 1) return 1;
    return 2 * T(n - 1) + 1;
}
```

手算一下：`T(1)=1`，`T(2)=2×1+1=3`，`T(3)=2×3+1=7`，`T(4)=2×7+1=15`。跟公式 `2ⁿ-1` 对一下：`2⁴-1=15`，吻合。这道题不要求写出每一步具体怎么移，只求步数——真正"每一步怎么移"的完整版，留到第 14 章递归算法专章再彻底解决，现在先熟悉"递归公式直接翻译成代码"这一件事就够了。

## 学生最容易栽的坑

1. 递归忘写边界，或者边界条件永远碰不到——无限递归，栈溢出崩掉；
2. 函数里改了形参，以为函数外面那个变量也跟着变了——值传递，改的只是拷贝；
3. 阶乘、幂算大了直接爆 `int`：`13!` 就已经超了，记得开 `long long`；
4. `a/gcd*b` 写成了 `a*b/gcd`——运算顺序换一下，溢出的时机就不一样；
5. 函数写在 `main` 后面却没有提前声明，编译报"未声明的标识符"；
6. 全局变量和函数里的局部变量重名，改的其实是局部那个，改完百思不得其解为什么外面没变化。
