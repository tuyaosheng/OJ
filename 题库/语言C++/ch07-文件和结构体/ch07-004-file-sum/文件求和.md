# 讲解稿：文件求和（ch07-004）

## 一、题目解读

读入若干个整数求和——但**不告诉你有多少个**，读到数据末尾为止。课件例 9.1（从文件读到 EOF）的思想。这题教一个非常实用的技巧：**读到文件末尾（EOF）自动停止**。

## 二、思路分析

以前的题都先给个 n，我们循环 n 次。可现实中（尤其读文件时）常常不知道数据量，只知道"读到没有为止"。C++ 的解法优雅得出奇：

```cpp
while (cin >> x) { ... }
```

`cin >> x` 这个表达式本身有个"真假值"：读取成功为真、读到末尾（EOF）失败为真变假。于是这个 while 的意思就是"**只要还能读进来，就继续**"，数据一读完，循环自动结束。

课件里的文件版是 `freopen("in.txt","r",stdin)` 把输入重定向到文件，再 `while (scanf(...) != EOF)`。在 OJ 上评测机已经把测试数据接到标准输入了，我们直接 `while (cin >> x)` 即可，原理完全一样。

## 三、代码讲解

```cpp
long long sum = 0;
int x;
while (cin >> x)     // 读取成功则继续，遇 EOF 停止
    sum += x;
cout << sum << endl;
```

- `while (cin >> x)` 是处理"不定量输入"的黄金写法，务必记住；
- sum 用 **long long**：最多 10 万个数、每个到 10⁶，总和可达 10¹¹，远超 int；
- 数据可能分布在多行——没关系，`cin >>` 跳过所有空白（空格、换行、制表符），一个个数照读不误。

测试点特意安排了单行、多行、只有一个数、含正负抵消等情况，验证 EOF 循环在各种排布下都正确。

## 四、易错点

1. 非要先读个 n——题目根本没给 n，读了会把第一个数据当数量，全错。
2. sum 用 int——大数据溢出。
3. 误以为多行需要特殊处理换行——`cin >>` 自动跳空白，不用管。
4. 写成 `while (!cin.eof())` 再读——这种写法会在最后多读一次、多算一个残值，是经典 bug；**直接把读取放进条件** `while (cin >> x)` 才对。

## 五、小结

`while (cin >> x)` 一句话搞定"读到末尾"，是数据量未知时的标配。它和课件的 freopen 文件读法本质相同——OJ 的标准输入就相当于一个"文件"。这个技巧在读边数不定的图、词频统计等题里天天用得到。

## 附：本机文件版（了解即可）
课件的 freopen 写法在本地调试很方便：`freopen("in.txt","r",stdin);` 之后所有 `cin` 都从 in.txt 读。但**提交到 OJ 前要删掉这行**，否则评测机找不到 in.txt 会出错。
