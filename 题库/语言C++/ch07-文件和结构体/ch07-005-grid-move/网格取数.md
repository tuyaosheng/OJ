# 讲解稿：网格取数（ch07-005）

## 一、题目解读

N×N 网格，每格一个数。从起点 (x,y) 沿给定方向（上/下/左/右）一直走到出界，把路上格子的数加起来。课件例 7.6。本题引入一个贯穿后续搜索章节的利器：**方向数组**。

## 二、思路分析

"沿一个方向走"，本质是每步给坐标加一个固定增量：
- 上：行 −1，列不变 → (−1, 0)
- 下：行 +1，列不变 → (+1, 0)
- 左：行不变，列 −1 → (0, −1)
- 右：行不变，列 +1 → (0, +1)

如果用 4 个 if 分别处理四个方向，代码又长又容易抄错。聪明的做法是把增量存进两个数组 `dx[]`、`dy[]`，方向 d 对应 `dx[d]`、`dy[d]`——一句 `x += dx[d]; y += dy[d];` 通吃四个方向。这就是**方向数组**技巧，第 15、16 章的 DFS/BFS 会疯狂使用它（那里是四个/八个方向一起试）。

主循环：只要 (x,y) 还在网格内，就累加当前格、走一步；一旦出界，循环停止。

## 三、代码讲解

```cpp
int dx[5] = {0, -1, 1, 0, 0};   // 下标 1=上,2=下,3=左,4=右
int dy[5] = {0, 0, 0, -1, 1};
...
while (x >= 1 && x <= n && y >= 1 && y <= n)  // 在网格内
{
    sum += g[x][y];
    x += dx[d];
    y += dy[d];
}
```

- 数组下标 0 空着不用，让 1~4 正好对应题目的方向编号，读起来清爽；
- **边界判断** `x>=1 && x<=n && y>=1 && y<=n`：四个条件缺一不可，漏一个就可能访问越界；
- sum 用 long long：最大路径 1000 格、每格 100，和才 10 万，其实 int 够——但网格类题目习惯性防溢出无妨；
- 二维数组 `g[1005][1005]` 开在全局，约 100 万个 int（4MB），在 256MB 限制内。

样例从 (2,2) 向右：经过 5、6，和为 11。测试点含 1×1 网格、贴边起步、以及 1000×1000 大网格（验证效率和不越界）。

## 四、易错点

1. 边界只判了两个方向（如只判 x 没判 y）——越界访问，RE 或 WA。
2. 方向增量填错（上下、左右搞反）。
3. 行列含义弄混：题目说 x 是行、y 是列，`g[x][y]` 别写成 `g[y][x]`。
4. 把"出界后的格子"也算进去——循环条件放对了就不会。

## 五、小结

方向数组 `dx[]/dy[]` 把"移动"从繁琐的 if 判断变成简洁的下标运算，是网格类题目的通用武器。今天是"单方向直走"，第 15、16 章会升级成"四方向/八方向同时搜索"——底层就是今天这套增量思想。边界判断务必四条都写全。
