## 上课怎么开场

黑板上写一个学生的信息：姓名"李明"，语文 88，数学 90，总分 178。问学生："如果全班 50 个人，你打算怎么存这些信息？"通常会有人说"开 4 个数组：`name[50]`、`chinese[50]`、`math[50]`、`total[50]`"。

顺着往下问："现在要按总分从高到低排名，排序的时候你要交换第 3 个人和第 8 个人的位置，这四个数组是不是都要跟着交换？漏改一个会怎样？"——让学生自己说出答案："姓名和分数对不上号了，张三的名字配上了李四的分数。"这就是**平行数组**最大的隐患：本来是同一个人的信息，散落在好几个数组里，靠"下标必须严格同步"这一件事硬撑着，稍微漏改一处就"张冠李戴"。

**结构体**要解决的就是这一件事：把姓名、语文、数学、总分这些**属于同一个人的信息**，捆成一个整体。以后排序、交换，都是整条记录一起搬，不会再有"数据错位"的问题。这一章还搭配着讲**文件读写**，应付"数据在文件里而不是键盘输入"的题目形式。

## 结构体定义与使用：把一条记录捆在一起（例1）

```cpp
struct Student {
    string name;
    int total;             // 总分 = 语文 + 数学
};
Student s[105];             // 结构体数组：一整排"学生记录"
```

`s[i]` 就是第 i 个学生的整条记录，`s[i].name`、`s[i].total` 用点号取出具体的某个字段。**结构体数组和普通数组唯一的区别，是每个格子里装的不是一个数，而是一整包数据**——访问方式没变，还是下标；变化的是"格子里装的东西"。

## sort + 自定义比较：从"只比总分"到"三级排序"（例1 → 例2）

例1 只要求按总分从高到低排，用 `stable_sort` 加一个比较函数就够：

```cpp
bool cmp(const Student &a, const Student &b) { return a.total > b.total; }
stable_sort(s, s + n, cmp);
```

但如果两个人总分一样呢？例1 用的是 `stable_sort`——**稳定排序**保证总分相同的两个人，排序前谁在前面，排序后还是谁在前面，也就是"总分相同按输入顺序"。例2（奖学金）把规则升级成三级：总分相同比语文，语文也相同比学号。这时候比较函数要一层一层往下判：

```cpp
bool cmp(const Stu &a, const Stu &b)
{
    if (a.total != b.total)     return a.total > b.total;      // 第一关：总分降序
    if (a.chinese != b.chinese) return a.chinese > b.chinese;   // 第二关：语文降序
    return a.id < b.id;                                        // 第三关：学号升序（保底，不会再有并列）
}
```

**多关键字排序的模板就是这句话："不相等就分胜负，相等交给下一层判"**，最后一层通常用一个绝对不会重复的字段（比如学号）保底，保证结果唯一确定。

光讲代码抽象，来看一组真实数据。5 个学生按输入顺序编号（学号）：

| 学号 | 姓名 | 语文 | 数学 | 总分 |
|---|---|---|---|---|
| 1 | 李明 | 88 | 90 | 178 |
| 2 | 王芳 | 90 | 88 | 178 |
| 3 | 张伟 | 75 | 95 | 170 |
| 4 | 赵敏 | 90 | 80 | 170 |
| 5 | 孙悦 | 90 | 88 | 178 |

**先用例1 的规则（只比总分，稳定排序）**：总分 178 的有学号 1、2、5，总分 170 的有学号 3、4。稳定排序只看总分，同分的人保持原来的相对顺序，所以结果是：

```
李明(178) 王芳(178) 孙悦(178) 张伟(170) 赵敏(170)
```

停一下问学生："王芳语文考了 90，李明只考了 88，两人总分一样，可王芳凭什么排在李明后面？"——因为例1 的规则压根没看语文，只看总分，稳定排序唯一能做的就是"保留原来谁在前面"。

**现在换成例2 的三级规则**：总分 178 这一组，比语文——李明 88，王芳 90，孙悦 90，王芳和孙悦语文打平，进入第三级比学号——王芳学号 2 小于孙悦学号 5，王芳排前面。这一组最终顺序是"王芳、孙悦、李明"。总分 170 这一组，比语文——赵敏 90 大于张伟 75，赵敏排前面。最终结果：

```
王芳(178) 孙悦(178) 李明(178) 赵敏(170) 张伟(170)
```

两种规则排出来的顺序完全不一样，尤其是"李明"——只比总分时排第 1，加上语文这一关直接掉到总分组的最后一名。**这就是为什么奖学金这种题不能偷懒只写一行 `a.total > b.total`，题目给的每一条排名规则都必须原样翻译进 cmp 里，漏一层、顺序错一层，排出来的名次就全错**。

到这里切 `结构体排序演示.html`，里面默认放的就是这 5 个学生的数据，两种规则来回切换点"下一步"，看插入排序怎么一步步比较、挪动卡片，最后钉上名次——跟黑板上这两张表完全对应。

务必强调一句纪律：`cmp` 必须是**严格弱序**，只能写 `>` 或 `<`，**绝不能写 `>=` 或 `<=`**——写了它们，`sort` 在某些实现下会越界访问甚至崩溃（运行错误），这是这一节最容易忽视但最致命的细节。

## 排名的正确姿势：不是所有"求名次"都要处理并列（练1）

【练1】求排名的题面是：给 N 个**互不相同**的整数，输出每个数从小到大排第几名。注意这里数字互不相同，不需要考虑"并列名次"，但也不能直接排完序就完事——题目要你按**原来的输入顺序**给出每个数的名次，排完序之后位置全变了，怎么对应回去？

办法是排序前先记下每个数原来站在哪个位置：

```cpp
struct Node { int val, pos; };   // pos: 这个数原来在第几个位置
bool cmp(const Node &a, const Node &b) { return a.val < b.val; }
sort(a, a + n, cmp);
for (int i = 0; i < n; i++)
    rankArr[a[i].pos] = i + 1;   // 排序后排在第 i 个（从0数）的数，名次是 i+1，塞回它原来的位置
```

拿具体数字走一遍：原始输入 `40 10 30 20`（下标 0~3）。按值从小到大排序后变成 `10(原下标1) 20(原下标3) 30(原下标2) 40(原下标0)`。排序后第 0 个位置的 10，名次是 1，塞回原下标 1；第 1 个位置的 20，名次是 2，塞回原下标 3；第 2 个位置的 30，名次是 3，塞回原下标 2；第 3 个位置的 40，名次是 4，塞回原下标 0。按原下标 0~3 顺序输出名次数组，结果是：

```
4 1 3 2
```

验证一下：40 是这组数里最大的，理应排第 4 名，原下标 0 位置的输出确实是 4；10 最小排第 1 名，原下标 1 位置输出确实是 1——对上了。**这一招"给每条记录多存一个原始位置，排序完再按位置放回去"，是结构体+排序最常见的用法之一，后面再遇到"要排序又要记住原来是谁"的题，都是这个套路。**

## 文件读写：两种姿势，一个坑（例3）

`cin >> x` 已经用了两章，本节新增的是"数据不知道有多少个，读到没有为止"。手算一遍数据流 `5 7 -3 10`，然后文件结束：

```
读 5   → sum = 5
读 7   → sum = 12
读 -3  → sum = 9
读 10  → sum = 19
再读一次 → 读取失败（已到文件末尾），循环结束
```

代码：

```cpp
long long sum = 0;
int x;
while (cin >> x) sum += x;   // 读失败（到文件末尾）自动跳出循环
cout << sum << endl;
```

`while (cin >> x)` 的判断依据是"这次读取有没有成功"，读到文件末尾自然失败，循环干净地停下来，不用额外去猜有多少个数据。**这里有一个几乎每届都有人踩的坑**：如果写成 `while (!fin.eof())`，会多读一次——因为 `eof()` 标志要等到"尝试读取失败"之后才会被置位，最后一个数字 10 读完的那一刻 `eof()` 还是 false，循环又进了一轮，再读一次却读不到新数据，导致 sum 被最后一个数重复计算，多加了一次 10，答案变成错误的 29。**只用 `while (cin >> x)` 这一种写法，永远不要用 `eof()` 做循环条件。**

真正在文件里读写有两种姿势：**`freopen`**（竞赛标配）——`freopen("data.in", "r", stdin);` 之后代码里照常用 `cin`，等于是"把输入的水龙头从键盘接到了文件上，代码一个字都不用改"；**`fstream`**——`ifstream fin("data.in"); fin >> x;` 更"正规"，需要同时操作多个文件时用这个。OJ 上交题一般不需要 `freopen`（数据走标准输入），但本地调试时非常好用，交题前记得删掉或注释掉。

## 结构体 + 二维/多字段综合（练2、练3）

【练2】网格取数：文件（或标准输入）给一个二维网格和起点、方向，从起点开始一直往一个方向走、把沿途格子的数加起来，走出网格就停。举个小例子，3×3 网格：

```
1 2 3
4 5 6
7 8 9
```

从 (2,1)（第2行第1列，值是4）开始一路向右走：`(2,1)=4，累加=4` → 走到 `(2,2)=5，累加=9` → 走到 `(2,3)=6，累加=15` → 再走一步到 `(2,4)`，已经超出网格（只有 3 列），停止。答案 15。这道题是"文件读入 + 二维数组 + 循环边界判断"三件事的综合，核心代码就是循环体里"先加当前格，再按方向挪一步，检查还在不在网格里"：

```cpp
while (x >= 1 && x <= n && y >= 1 && y <= n) { sum += g[x][y]; x += dx[d]; y += dy[d]; }
```

【练3】账号统计是结构体思想的另一种用法：不一定要开 `struct`，但"从一串混杂的记录里，按字段拆出信息、分别统计"是同一件事。比如身份证号第 17 位（下标 16，因为下标从 0 开始数）是性别码，奇数为男、偶数为女——拿身份证号 `"123456789012345678"` 举例，从左往右数到下标 16 这一位是字符 `'7'`，奇数，判定为男；如果换成 `"123456789012345668"`，下标 16 这一位变成 `'6'`，偶数，判定为女。QQ 号则是另一类记录，只管累加求平均。两类记录混在同一份输入里，用一个 `if` 分支各自处理各自的统计变量——这也是"同一份数据，不同字段各司其职"的一次实战。

## 学生最容易栽的坑

1. `cmp` 写 `>=`/`<=` → 严格弱序被破坏，`sort` 可能崩溃（运行错误）——只准写 `>` 或 `<`。
2. 平行数组排序漏搬一列 → 数据错位（用结构体从根上避免这个问题）。
3. 多关键字排序漏掉某一层判断，或者层与层的顺序写反——例2 里"李明"排位的巨大差异就是最好的反面教材。
4. `while (!fin.eof())` 多读一次——只用 `while (cin >> x)` 或 `while (fin >> x)` 这种"以读取是否成功"为条件的写法。
5. freopen 交 OJ 前记得删掉/注释（本地调试用），忘删会导致提交后读不到数据。
6. string 成员参与 `scanf`/`printf` 系列会出错——结构体里只要有 `string` 字段，就统一用 `cin`/`cout`，别混用 `scanf`。
7. 按字段拆分记录时下标算错一位（比如身份证号性别位算成第 16 位而不是下标 16 即第 17 位），统计结果全错但编译和运行都不会报错。
