## 上课怎么开场

先别急着讲语法。在黑板上写一句中文："请帮我在墙上写下'欢迎光临'四个字。" 问学生："这句话谁都能听懂，对吧？" 然后转头问："那如果我对着这台电脑说同样的话，它能写吗？"

学生多半会笑，但这个笑点正是问题所在：电脑听不懂中文，也听不懂英文——它只认识一种极其死板、一个字都不能差的"命令"。今天要学的 C++，就是一门专门写给电脑听的"命令语言"。它啰嗦、较真、一个分号都不能少，但换来的好处是：只要你把话"翻译"对了，电脑一定不折不扣地照办，不会理解错，也不会打折扣。

这就是编程的本质：**把你脑子里的想法，翻译成计算机能一字不差执行的指令**。今天的任务很小——只翻译一句话："Hello World!"，但翻译这句话要用到的骨架，以后写一万行代码也是同一套骨架。

## 程序骨架：先把"信封"写对（例1）

黑板上写下完整代码：

```cpp
#include <iostream>
using namespace std;
int main()
{
    cout << "Hello World!" << endl;
    return 0;
}
```

先不讲这几行是什么意思，先问一个问题："这段代码一共 6 行，运行的时候，是不是 6 行都会在屏幕上'冒出来点什么'？" 让学生猜。多数人第一反应会觉得"应该每行都做点事"，但**真相是：这 6 行里只有第 5 行会在屏幕上留下痕迹，其余 5 行都是幕后准备工作，一个字都不会出现在屏幕上**。

逐行拆开看：

- 第 1 行 `#include <iostream>`：把"输入输出"这个工具箱搬进来，不搬这一行，`cout` 根本不认识。
- 第 2 行 `using namespace std;`：这个工具箱里的东西都装在一个叫 `std` 的抽屉里，这句话相当于说"以后直接喊名字，不用每次都加抽屉前缀"。
- 第 3、4 行 `int main() {`：**程序真正开始跑的地方**——不管文件里写了多少行别的东西，电脑永远从 `main` 的花括号里第一句开始执行。
- 第 5 行 `cout << "Hello World!" << endl;`：**唯一产生输出的一行**，把双引号里的文字送到屏幕上，`endl` 负责换行。
- 第 6 行 `return 0;`：告诉操作系统"我正常结束了"，不会在屏幕上显示任何东西。

现在切到 `代码执行演示.html` 的"Hello World"页签，点"下一步"，让学生亲眼看着代码指针从第 1 行走到第 6 行——**只有走到那一句 `cout` 的时候，右边的控制台才会跳出一行字**，其余几步屏幕纹丝不动。这个"到底哪一行才真正产生输出"的直觉，很多学生要在这里第一次建立起来，值得多点几次"下一步"，让大家看清楚"执行"和"输出"不是一回事。

这三句"咒语"——`#include<iostream>`、`using namespace std;`、`int main()`——从今天起先背下来，以后每个程序都长这个骨架，区别只在花括号里写什么。顺带交代一句：写好的 `.cpp` 文件要经过"编译"才能变成能跑的程序，编译不通过就是"翻译不通"，报错信息一大堆，永远先看**第一条**，后面的往往是第一条错误带出来的连锁反应，改完第一条常常其余全部消失。

## 输出的花样：把"图形"翻译成一行行 cout（例2）

出一道题：在屏幕上画一个这样的小菱形：

```
  *
 ***
*****
 ***
  *
```

先别写代码，先问："这道题会用到几条 cout？" ——5 条，一行图形对应一行 cout，这是本题最重要的翻译原则：**多行输出就是多条输出语句，图形有几行，cout 就写几条**。

接下来带着学生数格子，不是套公式，是老老实实数：第 1 行，星号左边有几个空格？2 个，星号有几个？1 个。第 2 行呢？1 个空格，3 个星号。第 3 行呢？0 个空格，5 个星号。数到这里就能发现规律：**越靠近中间，空格越少、星号越多**，而且第 4、5 行和第 2、1 行**完全对称**。翻译成代码，每一行都是一条独立的 `cout`：

```cpp
cout << "  *" << endl;      // 2 个空格 + 1 个星号
cout << " ***" << endl;     // 1 个空格 + 3 个星号
cout << "*****" << endl;    // 5 个星号
cout << " ***" << endl;     // 和第 2 行对称
cout << "  *" << endl;      // 和第 1 行对称
```

强调一句题目里最容易被忽略的要求：**每行末尾不能有多余的空格**。学生很容易在星号后面顺手敲个空格再换行，这种"看不见的错误"在评测系统里是会判错的，因为评测比较的是字符串本身，不是"看起来像不像"。

切到 `代码执行演示.html` 的"字符菱形"页签，一步步点"下一步"，让学生看控制台是怎么一行一行被"画"出来的——每点一次对应一条 `cout` 语句，正好呼应"图形有几行、cout 就几条"这句话。

## 输入与变量初见：完整走一遍输入→计算→输出（例3）

前两道例题都是"我说什么你输出什么"，没有输入。例3 第一次要求程序**先看题目给的数，再算，再输出**——这是以后几乎每一道题的固定呼吸节奏：**读入 → 计算 → 输出**。

题目：长方形的长为 `a`、宽为 `b`（整数），求周长和面积。代码：

```cpp
int a, b;
cin >> a >> b;                        // 空格、换行都能分隔
int c = (a + b) * 2;                  // 周长
int s = a * b;                        // 面积
cout << c << " " << s << endl;
```

拿具体数字走一遍，假设输入是 `3 5`：

```
int a, b;                a = ?      b = ?
cin >> a >> b;           a = 3      b = 5     ← 按顺序把输入的两个数依次装进 a、b
int c = (a+b)*2;         c = (3+5)*2 = 16
int s = a*b;             s = 3*5 = 15
cout << c << " " << s;   屏幕输出：16 15
```

问一句容易被忽略的："如果我把 `cin >> a >> b;` 这一行和 `cout` 那一行顺序对调，会发生什么？" ——代码依然能编译通过，但 `a`、`b` 此时还没被赋值，是一个"垃圾值"，算出来的 `c`、`s` 完全不可预测。**代码是严格从上到下、一句一句执行的**，用到一个变量之前，必须保证它已经被赋过值。

再强调一句以后每道题都要盯着的规矩：**输出格式必须和题目一字不差**——这道题周长和面积之间只有一个空格，多一个空格、少一个换行，评测都算错，不是"结果对就行"。

切到 `代码执行演示.html` 的"长方形周长面积"页签，在输入框填两个数（比如 3 和 5），点"下一步"看变量框是怎么从"空"被 `cin` 填上数字的，再看 `c`、`s` 两个框怎么被算出来，最后一步才轮到控制台冒出结果——这个先后顺序和黑板上的表格完全对应。

## 两个实用运算，为后面章节埋种子

练习题里会用到两个运算，提前露个脸：

**乘法应用**（电影票）：一张票 10 元，`x` 个人，总价 `10 * x`，没有陷阱，练的是"把文字应用题翻译成一个表达式"的手感。

**整除与取余**（分苹果）：`n` 个苹果每袋装 `m` 个，能装几整袋、还剩几个？拿 `n=13, m=4` 走一遍：`13 / 4` 在 C++ 里是**整数除法**，直接舍掉小数部分得 `3` 袋；`13 % 4` 是余数，`13 - 3×4 = 1`，剩 1 个。两个运算符 `/` 和 `%` 从今天起要当兄弟一起记：**商乘除数加余数，永远等于原数**（`n/m*m + n%m == n`），这条恒等式后面章节反复会用到，尤其是"拆位"这类题目。

## 学生最容易栽的坑

1. 中文标点——中文输入法下敲出来的 `；`、`"` 编译器不认，一律切英文输入法；
2. 忘记分号、大括号不配对——报错一长串，永远先看**第一条**；
3. 输出多一个空格、少一个换行——和样例逐字符对，不要凭"看起来差不多"；
4. `int` 相除是整除：梯形面积这类要保留小数的题，记得用 `double`，`(a+b)*h/2.0` 里那个 `.0` 不能省；
5. 变量还没被 `cin` 读入就拿去计算——顺序写反，值是垃圾数。
