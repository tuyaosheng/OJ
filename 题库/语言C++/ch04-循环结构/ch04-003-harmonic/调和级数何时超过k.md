# 讲解稿：调和级数何时超过k（ch04-003）

## 一、题目解读

求最小的 n，使 1 + 1/2 + 1/3 + … + 1/n ≥ k。课件例 4.7（k=5）的一般化版本。结构上和上一题一模一样——while 累加到条件满足；新加的考点是**分数累加中的整数除法陷阱**。

## 二、思路分析

还是"次数未知"的 while 模式：和 s 从 0 开始，n 从 1、2、3…往上走，每次加 1/n，直到 s ≥ k 停止。

**头号大坑**：这一项写成 `1 / n` 的话——1 和 n 都是 int，整数除法！n=1 时得 1，n≥2 时**全是 0**。于是 s 永远停在 1，k≥2 时死循环。正确写法：`1.0 / n`，让分子是浮点数，除法就成了浮点除法。

第二个看点是**数学直觉**：调和级数是发散的（能超过任何 k），但慢得惊人——k=5 要加 83 项，k=10 要 12367 项，k=15 要 **183 万**项。运行一下程序，"级数发散但增长像蜗牛"这句抽象的话就变得看得见摸得着。这也解释了为什么题目把 k 限制在 15：k=20 就要 2.7 亿项了。

## 三、代码讲解

```cpp
double s = 0;
long long n = 0;
while (s < k)
{
    n++;
    s += 1.0 / n;     // 1.0 保证浮点除法
}
cout << n << endl;
```

- 条件 `s < k`：题目要"≥ k"，所以"还没达到"是 `<`（对比上一题的"超过/`<=`"，又是抠字眼）；
- s 必须是 double；n 用 long long（183 万在 int 内，习惯性防御）；
- 有同学担心浮点误差：调和级数的部分和永远不会恰好等于整数 k（数学上可以证明），而 double 的误差远小于部分和与整数的距离，所以判断安全。

## 四、易错点

1. **`1 / n` 整数除法**——本题的灵魂大坑，症状是超时（死循环被 OJ 掐掉）。
2. s 声明成 int 或 float：int 直接错，float 精度到后期不够（183 万项累加），用 double。
3. 条件把 `<` 写成 `<=`：会多加一项。

## 五、小结

两个收获：常数参与浮点运算要写成 `1.0`、`2.0` 的形式；"程序跑不停 = 先查循环条件是不是永远为真"。调和级数这题还是极好的"用程序做数学实验"的例子——很多数学结论，跑一遍循环就有体感了。
