# 讲解稿：三个数的最大值（ch03-003）

## 一、题目解读

输入三个整数，输出最大的那个。两个数比大小谁都会，三个数就有讲究了——方法好不好，决定了以后能不能推广到一百个数、一万个数。

## 二、思路分析

课件例 3.7 给的思路是"打擂台"：

1. 先让 a 站上擂台，当擂主（`maxn = a`）；
2. b 上台挑战：如果 b 比擂主大，b 当新擂主（`if (b > maxn) maxn = b;`）；
3. c 上台挑战：同样处理。

三个人都上过台之后，擂台上站的就是最大值。

为什么不用"a 比 b 和 c 都大就是 a，否则 b 比 a 和 c 都大就是 b……"那种写法？也能写对，但条件又长又容易漏（三个数相等时特别容易出错）。打擂台每一步只做一次比较，思路清晰，而且——**n 个数求最大值，打擂台照样两行循环搞定**，这是它真正的价值。

## 三、代码讲解

```cpp
int maxn = a;            // a 先当擂主
if (b > maxn) maxn = b;  // b 挑战
if (c > maxn) maxn = c;  // c 挑战
cout << maxn << endl;
```

注意这里是两个**并列的 if**，不是 if/else：b 和 c 都要各自挑战一次，互不影响。

看几个测试点的设计意图：
- `9 9 9`：三数相等——打擂台自然输出 9，不需要特判；
- `-5 -2 -9`：全是负数——擂台初值取的是 a（第一个数）而不是 0，所以没问题。**如果你把 maxn 初值写成 0，这组就错了**（输出 0，可 0 根本不在三个数里）！这是"初值要取自数据本身"的经典教训。

## 四、易错点

1. `maxn` 初值设为 0——全负数据直接判错。初值永远用第一个数。
2. 第二个 if 写成 `else if`——c 就没机会挑战了。
3. 数据到 10 亿，int 刚好装下；若题目改成两数相加再比，就要警惕溢出。

## 五、小结

打擂台三要素：**初值取第一个数、逐个挑战、胜者留台**。下一章学了循环和数组，同样的思路能处理一万个数。这题还有个"作业彩蛋"：把代码改成求最小值，只需把 `>` 换成 `<`，回家试试。
