# 讲解稿：合并果子（ch08-006）

## 一、题目解读

n 堆果子，每次合并两堆、花费等于两堆之和，求合成一堆的最小总花费。课件第四节优先队列，NOIP2004 名题。本题是 **优先队列（堆）+ 贪心** 的黄金组合。

## 二、思路分析

**贪心策略**：每次都合并当前**最小的两堆**，总花费最小。直觉上，越小的堆应该越早合并——因为一堆果子会被反复计入后续每次合并的花费，让小的多参与、大的少参与，总账最省。

难点在于"每次找最小的两堆"。如果每次都扫一遍找最小，是 O(n²)，n=10 万会超时。用 **优先队列（小根堆）**：它能在 O(log n) 时间弹出当前最小值。流程：
1. 所有堆入小根堆；
2. 弹出两个最小的，合并，花费累加进答案；
3. 把合并后的新堆压回堆；
4. 重复到只剩一堆。

## 三、代码讲解

```cpp
priority_queue<int, vector<int>, greater<int>> pq;   // 小根堆
...
while (pq.size() > 1)
{
    int a = pq.top(); pq.pop();
    int b = pq.top(); pq.pop();
    ans += a + b;                // 本次合并花费
    pq.push(a + b);              // 新堆放回
}
```

- **`priority_queue<int>`** 默认是**大根堆**（最大的在顶）；要小根堆，写成 `priority_queue<int, vector<int>, greater<int>>`——`greater<int>` 反转比较，最小的浮到堆顶；
- `pq.top()` 取堆顶（最小），`pq.pop()` 删堆顶，`pq.push()` 插入，都是 O(log n)；
- 循环到 `size() > 1`，剩一堆就结束；
- **答案用 long long**：n=10 万堆、每堆 2 万，总花费可达 10⁹ 量级以上，int 会溢出。

## 四、易错点

1. 忘了改小根堆，用默认大根堆——每次合并最大的两堆，答案错。
2. 累加"花费"和"新堆值"混淆：花费是 a+b（计入答案），同时 a+b 作为新堆压回——两处都要 a+b。
3. ans 用 int 溢出。
4. 每次线性找最小——O(n²) 超时，必须用堆。

## 五、小结

优先队列让"反复取最值"变成 O(log n)，是贪心类题目的利器。本题的贪心策略（每次并最小两堆）+ 小根堆实现，是必会模板，第 25 章"堆"还会深入。至此第一部分（语言 C++）的 STL 技巧告一段落——你已经握有 sort、string、set、queue、priority_queue 这套现成武器库。
