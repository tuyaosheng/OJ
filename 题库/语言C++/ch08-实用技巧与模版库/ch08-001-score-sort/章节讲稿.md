## 开场：别再手搓这些轮子了

前面几章你已经手写过排序（第 4 章冒泡/选择）、手管过数组大小、手写过字符串的逐字符处理。这些都是"知道原理"必须经过的阶段。但从这一章开始，遇到"排序""去重""先进先出""每次取最小"这几件事，**不用再自己写循环了**——C++ 标准库（STL）早就把这些高频操作封装好了，而且封装得比你随手写的版本更不容易出 bug。

这里要先破除一个误会："用 STL 是不是投机取巧？" 不是。竞赛里 STL 是基本功，不是作弊——它替你消灭的是"数组开多大""排序写错边界"这类低级失误，省下的脑力用来想真正的算法。这一章的任务，就是把手里的这几件趁手工具认全、用熟。

## sort + 比较函数：拿成绩排序练手（例1）

题目要求：给一批学生的姓名和分数，按分数从高到低排；分数相同的，按姓名字典序从小到大排。先看数据结构和排序调用：

```cpp
struct Student { string name; int score; };

bool cmp(const Student &a, const Student &b) {
    if (a.score != b.score) return a.score > b.score;
    return a.name < b.name;
}

sort(a, a + n, cmp);
```

黑板上摆 5 个学生，手动走一遍排序过程会发生什么（`sort` 内部具体用什么算法，标准没有规定，可能是快排的变种，我们不追究——但**比较函数 `cmp` 到底被怎么调用、返回值怎么决定顺序**，这个可以看得明明白白）：

```
Amy   95
Ben   88
Cindy 88
Dan   76
Eva   95
```

排序的本质，就是反复问 `cmp(x, y)`："x 应该排在 y 前面吗？" 挑几组关键的问答让学生自己判断：

- `cmp(Amy, Eva)`：两人分数都是 95，分数相等，比第二条规则——名字字典序，`"Amy" < "Eva"` 成立，`cmp` 返回 `true`，**Amy 应该排在 Eva 前面**。
- `cmp(Ben, Cindy)`：两人分数都是 88，比名字，`"Ben" < "Cindy"` 成立，返回 `true`，**Ben 排 Cindy 前面**。
- `cmp(Ben, Amy)`：`88 != 95`，比分数，`88 > 95` 不成立，返回 `false`，**Ben 不该排 Amy 前面**（也就是 Amy 该在 Ben 前面）。

把这些两两比较的结论拼起来，最终顺序是：`Amy(95) → Eva(95) → Ben(88) → Cindy(88) → Dan(76)`。**`cmp` 返回 `true`，意思是"第一个参数应该排在前面"**，`sort` 帮你把这上千次、上万次的两两比较自动安排好，你只要把"谁该排前面"这一句规则写对就行。

问学生一句容易翻车的地方："如果 `cmp` 写成 `return a.score >= b.score;`，多了一个等号，会出什么问题？"——`sort` 要求比较函数满足严格弱序，`a==b` 时 `cmp(a,b)` 和 `cmp(b,a)` 不能同时为 `true`，多这个等号会让"两个相等的元素互相认为自己该排在对方前面"，`sort` 内部逻辑会被搞乱，可能死循环或者结果错乱——**`sort` 的比较函数里，相等的情况永远不要返回 `true`**。

切到 `STL排序演示.html` 的"sort 比较器"页签，把这 5 个学生的数据点开演示，每一步会高亮当前正在比较的两个学生、显示 `cmp` 的返回值，再看这次比较导致谁和谁换了位置——比较函数不再是一段抽象文字，是看得见的一次次真实调用。

## string 全家桶：拼接与反转（例2）

字符串在 C++ 里终于像个"一等公民"，不用再靠字符数组和 `strlen` 手忙脚乱。题目要求：`s1` 接上反转后的 `s2`。比如 `s1="abc"`, `s2="xyz"`：先把 `s2` 反转成 `"zyx"`，再和 `s1` 拼接，得到 `"abczyx"`。

```cpp
reverse(s2.begin(), s2.end());   // "xyz" -> "zyx"
string ans = s1 + s2;            // "abc" + "zyx" -> "abczyx"
```

问学生："`reverse` 这个函数名是不是很眼熟？" ——是的，和 `sort` 一样来自 `<algorithm>`，一个头文件里装的都是这种"作用在一段区间上"的通用算法，传入 `begin()` 和 `end()` 两个位置就能用，不管这段区间是字符串、数组还是后面要学的 `vector`。这是 STL 的设计哲学：**算法和容器分开，同一个 `sort`、同一个 `reverse`，换个容器照样能用**。

顺带过一遍 `string` 其余的常用操作：`s.size()` 长度、`s.substr(pos,len)` 取子串、`s.find("ab")` 查找（找不到返回一个很大的数 `string::npos`，不是 `-1`，这个坑第五节要专门提）、逐字符处理仍然用 `s[i]`——第 2 章练的 ASCII 功夫全都用得上，只是不用再自己管字符数组开多大了。

## set：自动排序又自动去重（例3）

去重排序题——给一批可能重复的整数，从小到大输出不重复的那些。手写的话要么先排序再删重复相邻项，要么开个布尔数组标记出现过。用 `set` 三行搞定：

```cpp
set<int> st;
st.insert(x);   // 重复插入自动被忽略
for (int v : st) cout << v << " ";  // 遍历天然是从小到大
```

举个具体的输入 `5 3 5 1 3 2 5` 走一遍插入过程：插入 `5`，集合变成 `{5}`；插入 `3`，集合变成 `{3,5}`（**插入的同时自动排好序**，不是按输入顺序存的）；再插入 `5`，集合发现已经有 `5` 了，**什么都不做**，还是 `{3,5}`；插入 `1`，变成 `{1,3,5}`；再插入 `3`，已存在，忽略；插入 `2`，变成 `{1,2,3,5}`；再插入 `5`，已存在，忽略。最终遍历输出 `1 2 3 5`——去重和排序两件事，`insert` 一步到位。

提一句 `map<string,int>` 顺带用："如果要统计每个名字出现了几次呢？" `mp[name]++`，一行搞定按名字计数，第 7 章练习"账号统计"用 `map` 重写只要五行。**先会用，底层是红黑树、`insert`/`find` 都是 O(log n)，原理留到大学数据结构课再深挖**，现阶段记住"能用、够快"就行。

## queue 与 stack：排队和撤销的两种脾气（例4）

医院排队叫号：`1 x` 表示编号 x 的病人入队，`2` 表示队首病人被叫号出队。这就是**先进先出**（FIFO），`queue` 的 API 直译这个规则：

```cpp
queue<int> q;
q.push(x);      // 排到队尾
q.front();      // 看队首是谁
q.pop();        // 队首出队
```

拿一串具体操作走一遍：`1 101`（101 入队，队列 `[101]`）、`1 102`（102 入队，队列 `[101,102]`）、`2`（队首 101 出队并输出，队列变成 `[102]`）、`1 103`（103 入队，队列 `[102,103]`）、`2`（队首 102 出队并输出，队列 `[103]`）、`2`（队首 103 出队并输出，队列空）。输出顺序 `101 102 103`——**谁先来谁先走**，跟现实排队一模一样。

对比一下 `stack`（**后进先出**，撤销操作的直译）：`push` 进栈顶，`pop` 也从栈顶弹，最后进来的最先出去。这两个容器本章只要求认得 API、知道"先进先出"和"后进先出"分别对应哪个，思想上真正展开要等到第 22、23 章的栈、队列专章，以及第 18 章广度优先搜索——**这里先混个脸熟，用的时候不发懵**。

切到 `STL排序演示.html` 的"queue 排队叫号"页签，把刚才这串操作敲进去，看队列怎么一头进一头出。

## priority_queue：永远先弹出最该弹的那个（练2）

合并果子：n 堆果子，每次只能选两堆合并，代价是这两堆的总数之和，问合并成一堆的最小总代价。策略是每次都挑**当前最小的两堆**合并：

```cpp
priority_queue<int, vector<int>, greater<int>> pq;   // 小根堆：堆顶永远是当前最小值
pq.push(x);
int mn = pq.top(); pq.pop();
```

拿经典例子 `[1, 2, 9]` 走一遍：堆里是 `{1,2,9}`，堆顶最小的是 `1`。取出堆顶两个最小值 `1` 和 `2`，合并代价 `1+2=3`，把合并后的 `3` 重新丢进堆，堆变成 `{3,9}`。再取堆顶两个最小值 `3` 和 `9`，合并代价 `3+9=12`，丢回堆里变成 `{12}`。堆里只剩一堆，结束。**总代价 `3+12=15`**。

问学生一句本质问题："为什么每次要挑最小的两堆，而不是随便挑两堆合并？" 直觉解释：**每一堆果子被合并的次数越多，它就被重复计入总代价的次数越多**；越小的堆应该越早合并、越晚被"卷入"后面的大额合并，这样它被重复计的次数才会少。完整证明属于贪心算法的范畴，第 16 章会正式讲，这里先建立"小根堆 = 随时能拿到当前最小值"这个工具感。

追问一句容易读错的地方："三个参数的写法 `priority_queue<int, vector<int>, greater<int>>` 里，`vector<int>` 是干什么的？" ——它是堆底层存数据用的容器，绝大多数时候照抄不用改；真正决定"大根堆还是小根堆"的是第三个参数，**默认不写第三个参数就是大根堆（堆顶最大）**，要小根堆必须显式写 `greater<int>`，这行代码本章要求能背下来。

切 `STL排序演示.html` 的"priority_queue 合并果子"页签，把 `1 2 9` 输进去，看堆顶怎么一直吐出当前最小的两个数、又怎么把合并结果放回去参与下一轮。

## 学生最容易栽的坑

1. `v.size()` 返回的是无符号数：空容器时 `v.size()-1` 不会得到 -1，而是一个巨大的正数——用前先判空；
2. vector 下标越界不像数组那样必然崩溃，行为未定义、有时"看起来正常"——用前确认 `i < v.size()`；
3. `set`/`map` 遍历顺序是**排好序的**，不是插入的先后顺序，别拿它当"记录插入历史"的容器用；
4. `priority_queue` 默认是**大根堆**，要小根堆必须写三个参数 `<int, vector<int>, greater<int>>`；
5. `sort` 的比较函数相等情况返回了 `true`（比如写成 `>=`），违反严格弱序，结果可能错乱甚至运行异常；
6. `unique` 必须先 `sort` 再用，而且要配合 `erase` 才是真正删除了重复元素；`cin >> s` 遇空格就停，整行输入要用 `getline(cin, s)`，还要注意和 `>>` 混用时残留的换行符（`cin.ignore()`）。
