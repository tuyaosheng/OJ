# 第 28 章 并查集 —— 章节讲稿

## 一、为什么需要并查集

前两章学的图遍历（DFS/BFS）能判断"两个点是否连通"，但面对**动态变化**的关系——不断有新的连接加进来，同时又要不断地查询"这两个点现在连通了吗"——每次查询都重新遍历一次太慢了。**并查集**专门为这类"合并 + 查询是否属于同一集合"的场景而生，是一种极其精简却极其高效的数据结构。

## 二、并查集的核心结构

把每个集合看成一棵树，`fa[x]` 表示 $x$ 的父节点（根节点的 `fa` 是它自己）：

- `find(x)`：顺着父指针一路走到根，代表 $x$ 所在的整个集合。
- `merge(x, y)`：把其中一个根接到另一个根下面。

## 三、两个关键优化

- **路径压缩**（例1）：`find` 的时候顺手把沿途的点都直接接到根上，让树越用越扁平。
- **按大小/按秩合并**（例2、练2）：合并时优先把"小树"接到"大树"下面（而不是随意谁接谁），避免树越长越高。两者结合，单次操作的均摊复杂度趋近于 $O(1)$（严格地说是反阿克曼函数 $O(\alpha(n))$，可以当作常数看待）。

## 四、本章的六类考点

1. **并查集基本操作**（例1）：合并 + 判断是否同一集合，边操作边查询（"在线"处理）。
2. **连通块计数与规模统计**（例2、练2）：统计一共有几个集合、每个集合多大——只需要在合并时维护一个 `size` 数组，合并时把两个集合的大小相加。
3. **离线批量处理**（例3）：有些题目会先给一批"合并"信息，再给一批"查询"，把两批操作分开处理（先全部合并完，再统一回答所有查询）往往比"边合并边查询"更符合题目本身的结构。
4. **加边判环**（例4）：逐条加边时，如果某条边的两个端点在加入之前就已经在同一个集合里，说明加上这条边会形成环——这是并查集判断"图是否是森林"最直接的应用，也是下一章"最小生成树 Kruskal 算法"的核心子过程。
5. **排序 + 并查集**（练1）：很多题目需要"按某种顺序（时间、权值）依次处理边，边处理边用并查集判断连通性"，这个套路会在下一章学 Kruskal 算法时被反复用到。
6. **带权并查集 / 扩展域并查集**（练3、练5）：不仅要知道"两个点是否在同一集合"，还要知道"它们之间具体是什么关系"（比如相同阵营还是敌对阵营）。给每个节点维护一个"相对于父节点的关系值"，合并、查询时都要同步维护这个关系，是并查集里最有技巧性的部分。

## 五、易错点小结

- `find` 一定要写成路径压缩的版本，否则最坏情况会退化成 $O(n)$。
- `merge` 操作的对象是两个点各自的**根**，不是两个点本身。
- 带权并查集在路径压缩时，"关系值"也要跟着同步更新，这是最容易出错的地方。
- 判断"是否会成环"要在**加边之前**查询两端点是否已经同根，加完边之后再查就晚了。
