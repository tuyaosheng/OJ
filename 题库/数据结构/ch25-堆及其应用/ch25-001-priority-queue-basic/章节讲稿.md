# 第 25 章 堆及其应用 —— 章节讲稿

## 一、为什么要学堆

前一章学的二叉搜索树能快速查找、插入任意值，但如果我们只关心"当前所有数据里的最大值/最小值是谁"，用完全体的二叉搜索树有点大材小用。**堆**专门为这类需求而生：它是一棵**完全二叉树**（上一章学过这个概念——除最后一层外都是满的，最后一层从左到右连续排列），并且满足**堆序性质**：

- **小根堆**：每个节点的值都 $\le$ 它孩子的值（堆顶是全局最小值）。
- **大根堆**：每个节点的值都 $\ge$ 它孩子的值（堆顶是全局最大值）。

因为是完全二叉树，堆可以直接用**数组**存储（下标 $i$ 的孩子是 $2i, 2i+1$，或者 $2i+1, 2i+2$，取决于是否从 $1$ 开始编号），不需要像普通二叉树那样用指针，省内存又省事。

## 二、两种使用方式

1. **直接用 STL `priority_queue`**（例1）：C++ 标准库已经把堆封装好了，`push`/`pop`/`top` 都是 $O(\log n)$（`top` 是 $O(1)$）。绝大多数比赛和实际开发都直接用这个，不需要重复造轮子。
2. **手写数组实现**（例2）：理解堆的内部原理——插入时"上浮"（新元素放到数组末尾，不断和父节点比较、交换，直到满足堆序性质或到达堆顶）、删除堆顶时"下沉"（把数组最后一个元素搬到堆顶，然后不断和较小的孩子比较、交换，直到满足堆序性质或到达叶子）。理解了原理，才能应对"堆的某个位置的值被修改了，怎么重新调整"这类进阶操作（这是后面学 Dijkstra 最短路等算法时会用到的技巧）。

## 三、本章的六类考点

1. **堆的基本操作**（例1、例2）：插入、查询/弹出最值，分别用 STL 和手写两种方式实现，体会"会用"和"懂原理"的区别。
2. **堆排序**（例3）：把堆本身直接用作一种排序算法——先把所有数建成大根堆，再不断把堆顶（当前最大值）和数组末尾交换、缩小堆的范围、重新下沉调整，$n$ 次之后整个数组就有序了。这是 $O(n \log n)$ 排序算法里少数"原地排序、不需要额外数组"的代表。
3. **贪心 + 堆：合并果子**（例4）：很多"每次选最小的几个、合并、再放回去继续选"的贪心问题，都可以用堆来维护"当前候选集合的最值"，避免每次都重新扫描一遍找最小值。这是堆在贪心算法里最经典的应用套路。
4. **用堆求 Top-K**（练1）：只关心"最大的 K 个数是谁"时，不需要给全部 n 个数排序（$O(n\log n)$），维护一个大小恒为 K 的小根堆即可，把复杂度降到 $O(n \log K)$——当 K 远小于 n 时非常划算。
5. **堆的动态调度类应用**（练2、练4）：无论是"任务分配给最空闲的机器"还是"游戏道具冷却计时"，本质都是"数据不断变化、但要随时能查出当前极值是谁"的场景，用堆维护一个"动态变化的候选集合"是标准解法。练4 还会教你如何往堆里存放"一对信息"（而不只是单个数字）并自定义比较规则。
6. **对顶堆与多路归并**（练3、练5）：练3 用两个堆（一个大根堆、一个小根堆）配合维护"数据流的中位数"，是堆的进阶技巧；练5 用堆做多路归并——这正是后面学图论最短路（Dijkstra 算法）会用到的核心工具，提前打好基础。

## 四、易错点小结

- STL 默认 `priority_queue<int>` 是大根堆，小根堆要写 `priority_queue<int, vector<int>, greater<int>>`。
- 手写堆的下标计算（从 0 开始还是从 1 开始编号）容易搞混，务必固定一种约定并在插入/删除函数里保持一致。
- 弹出/查看堆顶前一定要判空。
- 堆里存放自定义类型（如 pair、结构体）时，如果不指定比较规则，默认按第一个字段比较——需要时要显式重载 `<` 或提供比较函数对象。
