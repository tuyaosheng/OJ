# 第 23 章 队列 —— 章节讲稿

## 一、队列是什么

队列（Queue）是一种**只能在一端进、另一端出**的线性表结构：进的一端叫**队尾**，出的一端叫**队首**。特点是**先进先出**（FIFO, First In First Out）——最早进队的元素，最早出队。

生活中的例子：排队买票、银行叫号、打印机的任务队列（先提交的任务先打印）。

上一章的栈是"后进先出"，这一章的队列是"先进先出"——两者接口形态很像（都是"只能在受限的位置操作"），但语义正好相反，学习时可以对照着记。

## 二、三种实现方式

1. **STL `queue<T>`**：单端队列，只能"队尾进、队首出"，直接 `push`/`pop`/`front`/`back`/`size`。
2. **STL `deque<T>`**（双端队列，double-ended queue）：两端都能进能出，`push_back`/`push_front`/`pop_back`/`pop_front`，比 `queue` 更灵活，单调队列必须用它实现。
3. **数组模拟循环队列**：开一个固定大小的数组，用 `front`、`rear` 两个下标标记队首和队尾，入队 `rear = (rear + 1) % 容量`，出队 `front = (front + 1) % 容量`——**取模**运算让数组"首尾相连"，避免数组前面空出来的位置被浪费。

## 三、本章的五类考点

1. **队列 / 双端队列的基本操作**（例 1、例 2）：入队、出队、查询队首/队尾/大小，先把 API 用熟。
2. **循环队列**（例 3、练 3）：用固定大小数组模拟队列的底层实现，核心是下标取模；练 3 专门练习"队首=队尾"这个位置到底是"空"还是"满"的经典陷阱——只看下标是分不清的，必须额外维护一个 `size` 计数器（或者故意少用一个格子）来消除歧义。
3. **单调队列**（例 4）：队列里的元素保持单调（递增或递减），最经典的用途是 `O(n)` 求"滑动窗口最大/最小值"——暴力做法是对每个窗口都扫一遍 `O(nk)`，单调队列能把它优化到 `O(n)`，因为每个元素最多入队出队各一次。必须用 `deque` 实现，因为要同时支持"队尾弹出更劣的元素再入队"和"队首弹出滑出窗口的元素"。
4. **循环报数类应用**（练 1、练 5）：约瑟夫问题是最经典的例子——用队列模拟"报数、出圈"的过程：把还没出局的人依次入队，每次把队首"轮转" `k-1` 次（弹出再压入队尾），第 `k` 次直接弹出且不放回。练 5 用类似的"轮转 + 淘汰/放回"逻辑包了一层游戏皮肤。
5. **多队列调度模拟**（练 2）：现实中常常不止一个队列（比如银行有多个窗口），需要按某种规则（比如"选当前排队人数最少的窗口"）决定新元素进哪个队列——这是队列在实际调度问题里最常见的用法。

## 四、队列 vs 栈 vs 递归

- 栈是"后进先出"，天然适合"需要撤销、回溯"的场景（递归本身就是用系统栈实现的）。
- 队列是"先进先出"，天然适合"按到达顺序处理、不能插队"的场景，也是**广度优先搜索（BFS）**的核心数据结构——BFS 每次从队首取出一个节点、把它的邻居加入队尾，保证了"离起点近的先被处理"（第 18 章已经系统学过 BFS，这里不再重复出这类题）。
