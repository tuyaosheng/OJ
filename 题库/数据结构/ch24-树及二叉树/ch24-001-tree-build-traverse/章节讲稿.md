# 第 24 章 树及二叉树 —— 章节讲稿

## 一、为什么要学树

前两章学的栈、队列都是**线性结构**——数据一个接一个排成一条线。但很多真实问题天然是"分叉"的：文件系统的目录、公司的组织架构、比赛的淘汰赛对阵表……这类"一对多"的层级关系，用**树**这种非线性结构来建模最自然。

**二叉树**是最简单、最常用的树——规定每个节点最多有两个孩子（左孩子、右孩子）。本章围绕二叉树展开，二叉树学透了，后面的堆、图论里的很多结构都是它的推广。

## 二、二叉树的存储与本章统一的输入约定

二叉树最自然的存储方式是链式结构：

```cpp
struct Node {
    int val;
    Node *left, *right;
};
```

但输入数据是一串数字，没法直接写指针。本章统一采用**扩展先序遍历**作为输入格式：在先序遍历（根→左→右）的基础上，把每一个空位置也输出一个 `-1` 占位。因为先序遍历"先访问根"的特点，读到的第一个数一定是（子）树的根，紧跟着的一段就是整棵左子树的扩展先序序列，再后面就是整棵右子树的扩展先序序列——这让递归建树变得非常自然：

```cpp
Node* build() {
    int v = a[pos++];
    if (v == -1) return nullptr;
    Node* root = new Node{v, nullptr, nullptr};
    root->left = build();   // 递归消耗左子树对应的那一段数字
    root->right = build();  // 再递归消耗右子树对应的那一段数字
    return root;
}
```

（例 4 是唯一的例外：那道题直接给"前序+中序"两个完整序列，不需要 `-1` 占位，因为两种序列合在一起本身就足以唯一确定树的形状。）

## 三、本章的六类考点

1. **建树 + 深度优先遍历**（例1）：先序/中序/后序遍历都是"根、左、右"三者的不同排列顺序，用递归写非常简洁，核心是理解"递归到空节点就返回"这个边界。
2. **层序遍历 / 广度优先遍历**（例2）：和前三种遍历完全不同的思路——不用递归，而是借助上一章学的**队列**："取队首、访问、把孩子按顺序入队"，保证严格按层、从左到右的顺序访问。
3. **树的性质统计**（例3）：深度、节点数、叶子数，都是"空树返回边界值，非空树用根节点的贡献 + 左右子树答案合并"的递归模式，是理解二叉树递归算法最核心的思维模型。
4. **遍历序列重建**（例4）：反过来，已知两种遍历序列（必须是"中序 + 另一种"，光有先序+后序无法唯一确定树），可以唯一确定第三种。关键技巧是用哈希表 $O(1)$ 定位根在中序序列中的位置，避免 $O(n^2)$ 超时。
5. **树的结构判定与变形**（练1 完全二叉树判断、练2 镜像翻转）：判断树的形状是否满足某种性质，或者对树做结构上的变换，同样是递归 + 分治的思路。
6. **不同的建树方式——二叉搜索树**（练3）：不用 `-1` 占位输入，而是按照"比当前节点小就往左、否则往右"的规则依次插入构造，插入完成后中序遍历一定是有序的——这是二叉搜索树（BST）区别于普通二叉树的核心性质，也是后面学习平衡树、字典树等结构的基础。

此外练4是一道"表达式树"应用题（游戏背景），练5是本章的综合提高题（树上最大路径和），把递归分治的思想用到极致。

## 四、易错点小结

- 递归函数一定要先处理空节点（`if (!root) return ...;`），否则会访问空指针。
- 层序遍历必须用队列，不能用递归实现。
- 由两种遍历序列重建第三种时，必须用哈希表加速查找根的位置，否则大数据会超时。
- 二叉搜索树的插入顺序不同，树的形状（从而效率）差异很大——有序数据插入会退化成一条链。
