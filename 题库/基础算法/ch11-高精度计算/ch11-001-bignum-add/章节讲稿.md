## 上课怎么开场

黑板上先写一道题：`1234 + 5678`，随口问一句："这谁不会？三年级都会。" 等学生笑完，接着写第二道：`9999999999999999999 + 1`（20 个 9）。

"这道题呢？直接 `long long` 存得下吗？" 让学生算一下 `long long` 的上限——大约 9.2×10¹⁸，19 位。这个数是 20 个 9，已经超了。有学生会说"那用更大的类型"，可以顺势问："那 100 位呢，1000 位呢？总有一个类型不够用的时候。"

再补一刀：算 100 的阶乘，`100!` 有 158 位。**不是数字大小超了 int，是超了所有内置类型**，`__int128` 也就 39 位，照样不够。这时候问题才算问到位：**当没有任何一种类型能装下这个数的时候，怎么算？**

答案回到你从小就会的办法：**列竖式**。竖式为什么好使？因为它从来不要求"一口气把整个数存进一个格子里"——每一位单独占一个格子，运算规则只看相邻两位。计算机没有能装下 158 位数的寄存器，但它有数组，**数组里一格存一位，就是竖式的格子**。这就是本章要学的高精度计算，核心思想一句话：**大数拆成一位一位存，运算规则照抄小学竖式**。

## 存储：为什么数字要倒着放进数组

写 `1234` 在黑板上，问学生："如果我用 `a[0]=1, a[1]=2, a[2]=3, a[3]=4` 这样正着存，个位在哪？" ——下标 3。"那两个长度不一样的数相加，比如 `123 + 45`，个位对不对得上？" 让学生自己发现问题：`123` 的个位在 `a[2]`，`45` 的个位在 `b[1]`，两个数组的"个位下标"不一样，加法从哪位开始都对不上。

再试倒着存：`a[0]=4, a[1]=3, a[2]=2, a[3]=1`。这次不管数多长，**下标 0 永远是个位**，两个数天然对齐。而且进位天然往下标增大的方向走（`a[i]` 进到 `a[i+1]`），不会向左越界出负下标。这不是规定，是**顺着竖式运算的方向倒推出来的存法**——竖式从个位往高位算，数组就该让个位在"好走的那一头"。

字符串读进来是正着的（`"1234"`），要转存成数组时做个反转：`a[i] = s[len-1-i] - '0'`。输出的时候反过来，从最高位往低位打印，别忘了去掉前导零。这一条存储约定后面加减乘全都要用，记不住就翻回这段。

## 高精度加法（例1）：手把手走一遍 1234 + 5678

黑板上竖着写：

```
   1 2 3 4
 + 5 6 7 8
 ---------
```

不算，先问学生："个位是几加几？" 4+8=12，写 2，进 1。这一步先别急着讲代码，让学生跟着喊出后面几位：十位 3+7+1(进位)=11，写1进1；百位 2+6+1=9，写9不进位；千位 1+5=6，写6。答案 6912。

现在把这个手算过程翻译成代码，翻译的关键是**进位怎么在数组里传递**：

```cpp
int carry = 0;
for (int i = 0; i < len; i++) {
    int sum = a[i] + b[i] + carry;
    c[i] = sum % 10;   // 本位只留个位数字
    carry = sum / 10;  // 进位留到下一轮循环用
}
if (carry > 0) c[len++] = carry;  // 循环跑完，进位还没处理完，得多补一位
```

对照黑板上的手算：`sum % 10` 就是"写的那个数字"，`sum / 10` 就是"进的那个数字"——因为两个个位数加一个进位，最大 `9+9+1=19`，进位永远只会是 0 或 1，这也是为什么代码里不用担心进位会进出两位。

这里停下来问一句："如果两个数长度不一样呢，比如 `123 + 45`，`b[3]` 是什么？"——是 0，因为数组是全局的，C++ 自动把没赋值的部分清成 0，短的数高位天然补 0，不需要特殊处理。

再问一句容易被漏掉的："`999 + 1`，循环跑 3 轮之后 `carry` 是多少？"——是 1，而 `c` 数组还是 `[0,0,0]`。如果这时候直接输出就是 `000`，是错的。**这就是为什么 `if (carry > 0)` 那一行不能省**：加法的结果位数，可能比两个加数里最长的那个还多一位。

到这里可以切到 `高精度演示.html` 的"加法"页签，把 `1234` 和 `5678` 输进去，一步步点"下一步"，让学生看动画里进位是怎么从个位格子飘到十位格子上面的——跟刚才黑板上写的完全对应,只是换成了数组下标的语言。

## 高精度减法（例2）：加法的镜像，多两个麻烦

减法比加法多出两件事：**结果可能是负数**，**要借位**。先处理第一件：`45 - 123` 得到负数，高精度数组不好存负号，所以**永远让大数减小数**，如果发现 `a < b`，就交换两个数、在结果前面添个负号。比较大小的办法：先比位数，位数一样再从最高位往低位逐位比。

借位怎么处理？黑板写 `1000 - 999`：

```
  1 0 0 0
- 0 9 9 9
 ---------
```

从个位开始：0-9，不够减，找十位borrow一个变成10，10-9=1；十位现在是-1（借出去了）再减9，还是不够，再借，变成9，9-9=0；百位同理借位后是9，9-9=0；千位1-0（已被借掉一次）=0。结果 `0001`，也就是 1。代码：

```cpp
int borrow = 0;
for (int i = 0; i < len; i++) {
    int x = a[i] - b[i] - borrow;
    if (x < 0) { x += 10; borrow = 1; } else borrow = 0;
    c[i] = x;
}
```

减法还有一个加法没有的收尾动作：**去前导零**。`1000 - 999 = 1`，四位数减出来变成一位数，高位的三个 0 要清掉，但结果如果恰好是 0（比如 `5-5`），至少要留一位，不能什么都不输出。

到这一步切 `高精度演示.html` 的"减法"页签，重点让学生盯着借位的箭头看：借位跟进位方向相反，是从高位"借"到低位来用。

## 高精度 × 单精度（例3）：进位可能不止 1

算阶乘的时候会遇到"大数 × 一个普通整数"，比如 `9! = 8! × 9`。这里进位跟加减法不一样：`9 × 9 = 81`，一位乘出来能到两位数，**进位可能不止 1，可能是几十**。所以代码里这一句必须用 `+=` 不能用 `=`：

```cpp
int carry = 0;
for (int i = 0; i < lenA; i++) {
    int prod = a[i] * m + carry;
    c[i] = prod % 10;
    carry = prod / 10;   // 这里 carry 可能是两位数，下一轮还得再拆
}
while (carry > 0) { c[lenA++] = carry % 10; carry /= 10; }  // 进位本身可能要再进位
```

问学生一句："如果 `carry` 算出来是 23，是不是只往前进 1 位就完了？"——不是，`c[i+1] += ...` 之后 `carry` 还可能继续大于 9，所以最后那个 `while` 循环不是加法里 `if` 就能打发的，得反复拆到 `carry` 变 0。这是本节最容易埋雷的一句，值得在黑板上多停十秒。

## 高精度 × 高精度（例4）：错位相加

这是本章压轴，先别看公式，先手算 `123 × 45`：

```
      1 2 3
  ×     4 5
  ---------
    6 1 5      ← 123 × 5
  4 9 2        ← 123 × 4，注意整体往左错一位
  ---------
  5 5 3 5
```

问学生："第二行为什么要往左错一位再加？"——因为它其实是 `123 × 40`，不是 `123 × 4`，往左错一位就是乘了 10。这是小学就学过的规则，高精度乘法只是把它做得更彻底：**不是按整行错位，而是按每一个数位单独错位**。

用下标去看：`a` 的第 `i` 位代表 `10^i`，`b` 的第 `j` 位代表 `10^j`，两者相乘是 `10^(i+j)`，所以这一对数字的贡献要落在结果的第 `i+j` 位。代码只有一行核心：

```cpp
for (int i = 0; i < lenA; i++)
    for (int j = 0; j < lenB; j++)
        c[i + j] += a[i] * b[j];   // 先把所有贡献都堆到对应位置，不急着处理进位
```

拿 `123 × 45` 走一遍（`a[0]=3,a[1]=2,a[2]=1`，`b[0]=5,b[1]=4`）：`c[0]=3×5=15`，`c[1]=3×4+2×5=12+10=22`，`c[2]=2×4+1×5=8+5=13`，`c[3]=1×4=4`。这时候 `c` 数组是 `[15,22,13,4]`，**每一格都可能超过 9，先别管，这是故意的**——双重循环只管往对应格子里堆数字，堆完了统一处理一遍进位：

```cpp
int carry = 0;
for (int i = 0; i < lenA + lenB; i++) {
    c[i] += carry;
    carry = c[i] / 10;
    c[i] %= 10;
}
```

`[15,22,13,4]` 走一遍进位清理：`15→5进1`，`22+1=23→3进2`，`13+2=15→5进1`，`4+1=5→5不进`。结果 `[5,3,5,5]`，倒回来读就是 `5535`，和黑板上手算的 `5535` 对上了。

这一段是全章最容易讲飞的地方，务必切 `高精度演示.html` 的"高精度乘法"页签，先演示"错位累加"阶段（看每个格子怎么变成两位数），再点进"统一进位"阶段（看这些两位数怎么被拆成最终答案）——两个阶段分开看，学生才不会把"乘"和"进位"混成一团。

## 复杂度与开多大数组，一句带过

加、减、乘单精度都是 O(n)，高精度乘高精度是 O(n·m)（双重循环）。数组开多大：n 位数乘 m 位数结果最多 n+m 位；n! 的位数大致是 `Σlog₁₀i`，100! 是 158 位，本章数组开到 500 甚至 600 完全够用，不用抠size，宁可开大不要开小。

## 学生最容易栽的坑

带过几届课下来，这几个错误年年都有人犯：

1. 拿 `int` 或 `long long` 读入 500 位的数——读入那一刻就已经溢出了，跟后面算得对不对没关系，一开始就错了。
2. 加法/乘法算完，忘了处理最后剩下的 `carry`——`999+1` 输出成 `000`，这个坑几乎每个人第一次写都会踩。
3. 存的时候倒了、输出的时候忘了倒回来，或者反过来——输出一个反过来的数字，比如该输出 `579` 结果输出了 `975`。
4. 减法忘记去前导零，或者去过头把结果 `0` 也去没了——至少留一位。
5. 乘单精度那句 `carry` 处理写成 `=` 而不是 `+=`，或者忘了乘完还要用 `while` 把 `carry` 榨干。
6. 写成函数反复调用时（比如阶乘之和），数组忘记清零，上一次的残留数字污染了这一次的结果。
