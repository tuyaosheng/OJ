# 讲解稿：高精度乘单精度（ch11-003）

## 一、题目解读

给一个最多 500 位的大数 a，和一个不超过 10000 的小数 b，求 a × b。

这是乘法的"入门版"：**只有一个数是大数**，另一个小到 `int` 装得下。先把这种情形吃透，下一题的"大数 × 大数"就水到渠成了。

## 二、思路分析

### 竖式回顾

算 `123 × 12`，小学做法是把 12 拆成 2 和 10 分别乘……但那样要做两轮再相加，太麻烦。

对于"大数 × 小数"，有个更直接的办法：**用 b 去乘 a 的每一位**。

算 `123 × 12`（倒序存 a 为 `[3,2,1]`）：

| 步骤 | 计算 | 本位留 | 进位 |
|------|------|--------|------|
| i=0（个位） | 3 × 12 + 0 = 36 | 6 | 3 |
| i=1（十位） | 2 × 12 + 3 = 27 | 7 | 2 |
| i=2（百位） | 1 × 12 + 2 = 14 | 4 | 1 |
| 收尾 | 进位 1 还剩 | 1 | 0 |

结果倒序为 `[6,7,4,1]`，正着读就是 **1476**。验算：123 × 12 = 1476 ✓

### 关键洞察一：进位可以很大

注意上表 i=0 那行：`3 × 12 = 36`，进位是 **3**，不是加法里那个只能是 0 或 1 的进位！

事实上，`a[i]` 最大 9，`b` 最大 10000，所以 `a[i] * b` 最大是 `9 × 10000 = 90000`。加上进位，中间值可能到五位数。**进位也可能是一个多位数**。

这带来一个重要后果——**循环结束后不能只补一位**：

```cpp
// 错误写法：只补一位
if (carry > 0) c[len++] = carry;    // carry 可能是 9000，一位放不下！

// 正确写法：一位一位全部展开
while (carry > 0)
{
    c[len] = carry % 10;
    carry /= 10;
    len++;
}
```

这是本题和加法最大的区别，**也是最容易错的地方**。

### 关键洞察二：会溢出吗？

`a[i] * b + carry` 最大能到多少？粗略估计，`9 × 10000 + 进位 ≈ 9 万多`，离 `int` 的 21 亿差着十万八千里。**用 int 完全安全**。

但要养成"随手估上界"的习惯：如果 b 能到 10^9，那 `9 × 10^9` 就爆 int 了，必须换 `long long`。**每次写乘法都问一句"最大能到多少"**，这个习惯能帮你躲掉无数溢出 bug。

## 三、代码讲解

```cpp
int carry = 0;

for (int i = 0; i < la; i++)
{
    int cur = a[i] * b + carry;   // 本位的"总值"（可能是五位数）

    c[i] = cur % 10;              // 本位只留个位数字
    carry = cur / 10;             // 剩下的全部进位给高位
}

int len = la;

// carry 可能是多位数，必须一位一位全部展开
while (carry > 0)
{
    c[len] = carry % 10;
    carry /= 10;
    len++;
}

// 去前导零，至少保留一位
while (len > 1 && c[len - 1] == 0)
    len--;
```

这里的结构叫**"先算出本位总值，再拆成 本位 + 进位"**——`% 10` 取本位，`/ 10` 取进位。这个模式在所有高精度运算里都通用，非常值得记住。

### 为什么一定要去前导零？

考虑 `b = 0` 的情况：`99999 × 0`。循环里每位都算出 0，c 数组是 `[0,0,0,0,0]`，进位也是 0。如果不去前导零，会输出 **`00000`**——直接 WA。

去掉前导零后，`len` 变成 1，输出单个 **`0`**，正确。

同理 `a = 0` 时也是一样。这两个边界（乘数为 0、被乘数为 0）是本题最爱考的坑，**测试数据里一定有**。

## 四、易错点

1. **收尾的进位只补一位** —— `while` 写成 `if`。当 b 较大时（比如乘 10000），进位是个多位数，一位根本放不下，答案会缺一大截。**这是本题第一大坑。**
2. **忘记去前导零** —— `b = 0` 时输出 `00000`。**第二大坑。**
3. **数组开小** —— 大数乘 10000，位数会增加 4~5 位，要留够余量。
4. **溢出**（本题不会，但要有意识）—— 如果 b 的范围更大，`a[i] * b` 就得用 `long long`。
5. 忘记 b 要用**整数**读入（它是小数，不需要 string）。

## 五、小结

高精度 × 单精度的套路：

1. 大数倒序存数组，小数正常读成 `int`；
2. 遍历大数的每一位：`cur = a[i] * b + carry`，**`% 10` 留本位，`/ 10` 作进位**；
3. **循环结束后用 `while` 把剩余进位逐位展开**（不是 `if`！）；
4. 去前导零，倒序输出。

和加法比，最大的变化是"**进位不再只是 0 或 1，而可能是一个多位数**"。理解了这一点，就理解了乘法的本质——它是一种"放大"运算，中间值会膨胀，必须小心处理。

下一题，我们把 b 也变成大数，正式挑战**高精度乘高精度**。届时会引出整个高精度算法中最精妙的一条规律：**`i + j`**。
