# 讲解稿：高精度乘法（ch11-004）

## 一、题目解读

给两个最多 500 位的大数 a、b，求 a × b。

这是本章的**核心题**。上一题里 b 还是个小整数，现在两边都是庞然大物，竖式该怎么模拟？

## 二、思路分析

### 从竖式中发现规律

先看小学竖式怎么算 `123 × 45`：

```
      1 2 3
    ×   4 5
    ---------
      6 1 5      ← 123 × 5
    4 9 2        ← 123 × 4，但要左移一位！
    ---------
    5 5 3 5
```

关键就在那句"**要左移一位**"。为什么？因为 4 在十位上，它实际代表 40，所以乘出来的结果要放大 10 倍——体现在竖式上就是**错开一位**。

这个"错位"到底错多少？我们把它精确化。

### 核心规律：i + j

回忆倒序存储的那个隐藏福利：**下标 i 上的数字，真实数值是 `a[i] × 10^i`**。

（比如 a = 123 倒序存成 `[3,2,1]`，`a[2] = 1` 代表的就是 1 × 10² = 100。）

那么，a 的第 i 位乘以 b 的第 j 位，实际算的是：

**(a[i] × 10^i) × (b[j] × 10^j) = (a[i] × b[j]) × 10^(i+j)**

`10^(i+j)` 是什么意思？意思是这个乘积**应该落在结果的第 i + j 位上**！

于是竖式里那个含糊的"错位"，变成了一条精确的规律：

> ### a 的第 i 位 × b 的第 j 位 → 加到结果的第 (i + j) 位
> 这就是高精度乘法的**灵魂**。

用三行代码就能写出来：

```cpp
for (int i = 0; i < la; i++)
    for (int j = 0; j < lb; j++)
        c[i + j] += a[i] * b[j];
```

漂亮吧？所有的"错位相加"，浓缩成了 `c[i + j] +=` 这一个下标。

### 策略：先累加，后进位

你可能会问：`c[i+j]` 累加着累加着，不就变成一个很大的数了吗？一位怎么装得下？

**装不下就先不装。** 这正是本题最巧妙的策略——

> **第一步：不管进位，让每个 `c[k]` 随便变成多大都行，先把所有乘积累加进去。
> 第二步：全部加完之后，再从低位到高位扫一遍，统一处理进位。**

为什么可以这样？因为加法和进位是可以**分离**的。我们最后总能通过一次扫描，把"每位可能很大"的数组，整理成"每位都是 0~9"的规范形式：

```cpp
for (int i = 0; i < len - 1; i++)
{
    c[i + 1] += c[i] / 10;      // 超出个位的部分，全部进给高一位
    c[i] %= 10;                 // 本位只留一位
}
```

这比"边乘边进位"清晰太多了，也不容易出错。**先累加、后进位——请记住这个套路。**

### 会溢出吗？

老规矩，估上界：`c[k]` 最多被累加多少次？最坏情况下 500 次（a、b 都是 500 位）。每次加的最大值是 `9 × 9 = 81`。

所以 `c[k]` 最大约 `500 × 81 = 40500`——离 int 上限远得很，**安全**。

但请注意这个结论是有条件的：如果位数达到几万，`位数 × 81` 就可能爆 int，那时就得换 `long long`。**永远记得估上界。**

### 结果有多长？

`la` 位的数乘 `lb` 位的数，结果最多 `la + lb` 位（比如 `99 × 99 = 9801`，2+2=4 位）。所以数组第二维要开到 `la + lb`，本题即 1000 以上，我开了 1100。

## 三、代码讲解

完整流程只有三步，每步一个循环：

```cpp
// 第一步：错位相加（不管进位）
for (int i = 0; i < la; i++)
    for (int j = 0; j < lb; j++)
        c[i + j] += a[i] * b[j];

int len = la + lb;

// 第二步：统一进位
for (int i = 0; i < len - 1; i++)
{
    c[i + 1] += c[i] / 10;
    c[i] %= 10;
}

// 第三步：去前导零
while (len > 1 && c[len - 1] == 0)
    len--;
```

**为什么去前导零特别重要？** 因为我们把 `len` 初始设成了 `la + lb`，这是**最长可能**长度。但实际结果往往没那么长——比如 `12 × 12 = 144`，只有 3 位，而 `la + lb = 4`，最高位是 0，必须砍掉。

而 `0 × 12345 = 0` 更极端：整个数组全是 0，不去前导零会输出一长串 `0000000000`。

**复杂度**：O(la × lb) = 500 × 500 = 25 万次，转瞬即成。

## 四、易错点

1. **`c` 数组开小了** —— 只开 500，结果需要 1000 位，高位被截断。**数组必须开到 `la + lb` 以上。**
2. **忘记去前导零** —— 这题因为 `len` 初值取的是最长可能长度，**几乎必然**出现前导零，不处理必错。
3. **边乘边进位，逻辑写乱** —— 强烈建议用"先累加、后进位"两段式，清晰又安全。
4. **忘了 `c` 要清零**（如果不是全局数组）—— 局部数组不会自动清零，累加前必须 `memset`。本题用全局数组，自动为 0。
5. **溢出意识缺失** —— 本题 int 够用，但要能自己算出"最大 40500"这个上界，而不是碰运气。

## 五、小结

高精度乘法，记住三件事：

1. **核心规律：`c[i + j] += a[i] * b[j]`** —— 倒序存储让下标 i 天然代表 10^i，于是错位相加变成了简单的下标相加。这是全章最精妙的一行代码。
2. **策略：先累加、后进位** —— 把两件事分开做，代码清爽、不易错。
3. **收尾：结果最长 `la + lb` 位，务必去前导零。**

到这里，高精度的加、减、乘三大运算就全部拿下了。（除法要用到"试商"，更复杂一些，属于进阶内容，本章暂不涉及。）

接下来两题，我们不再单纯地"实现一个运算"，而是把高精度**当作工具**去解决真正的问题——**阶乘之和**和**数楼梯**。你会看到，前面几题写的函数，是怎么被反复调用、组合成更大的程序的。这才是学习高精度的真正目的。
