# 讲解稿：阶乘之和（ch11-005）

## 一、题目解读

给定 n（≤ 100），求 **S = 1! + 2! + 3! + … + n!**。

前面四题，每题只做**一次**运算。这题不一样：它要我们把高精度**当成工具，反复使用**。这才是高精度真正的用法。

**先确认必须用高精度。** 阶乘增长有多快？

| k | k! | 位数 |
|---|-----|------|
| 10 | 3628800 | 7 位 |
| 20 | 约 2.43 × 10^18 | 19 位（`long long` 的极限） |
| 25 | 约 1.55 × 10^25 | 26 位（**爆了**） |
| 100 | 约 9.33 × 10^157 | **158 位** |

`long long` 撑到 20! 就到头了。而 n 可以到 100，答案有 158 位——**必须高精度**。

## 二、思路分析

### 笨办法的问题

最直接的想法：写个函数算 k!，然后循环 n 次，每次都算一遍再加起来。

```
for k = 1 to n:
    算出 k! （从 1 乘到 k）
    sum += k!
```

能过，但很浪费——算 5! 时要乘 5 次，算 6! 时又从头乘 6 次……其实 6! 只是 5! 再乘个 6 而已，前面的功都白费了。

### 好办法：利用递推

阶乘有一个**递推性质**：

> **k! = (k−1)! × k**

也就是说，**上一个阶乘乘以 k，就是下一个阶乘**。所以我们只要维护一个"当前阶乘"变量 `fac`，一路滚下去：

```
fac = 1        // 0! = 1，作为起点
sum = 0

for k = 1 to n:
    fac = fac × k      // 由 (k-1)! 变成 k!  —— 高精度 × 单精度
    sum = sum + fac    // 把 k! 累加进答案   —— 高精度 + 高精度
```

一共只需 n 轮，每轮做**一次乘法 + 一次加法**。干净利落。

### 需要哪两样武器？

看上面的伪代码，需要两个高精度操作：

| 操作 | 是什么 | 哪一题学过 |
|------|--------|-----------|
| `fac × k` | 高精度 **×** 单精度（k ≤ 100，是小数） | 第 3 题 |
| `sum + fac` | 高精度 **+** 高精度 | 第 1 题 |

**前面写过的代码，现在直接复用！** 这就是为什么我们要一题一题打基础——它们不是孤立的练习，而是可以拼装的**零件**。

## 三、代码讲解

本题的重点是**把高精度操作封装成函数**。这是竞赛中的标准做法，能让主程序清晰得像伪代码一样。

### 零件① 高精度 × 单精度

```cpp
void mulSmall(int a[], int &len, int k)
{
    int carry = 0;

    for (int i = 0; i < len; i++)
    {
        int cur = a[i] * k + carry;
        a[i] = cur % 10;        // 本位留个位（原地修改）
        carry = cur / 10;
    }

    while (carry > 0)           // 进位可能多位，逐位展开
    {
        a[len] = carry % 10;
        carry /= 10;
        len++;
    }
}
```

和第 3 题一模一样，只是改成了**原地修改**（直接改 `a` 数组）。注意 `int &len` —— 用**引用**传参，这样函数内部改变了位数，外面也能看到。这是 C++ 的一个关键语法点。

### 零件② 高精度 + 高精度

```cpp
void addBig(int a[], int &lenA, int b[], int lenB)
{
    int len = max(lenA, lenB);
    int carry = 0;

    for (int i = 0; i < len; i++)
    {
        int s = a[i] + b[i] + carry;
        a[i] = s % 10;
        carry = s / 10;
    }

    if (carry > 0) { a[len] = carry; len++; }

    lenA = len;
}
```

也和第 1 题一样，改成把结果存回 `a`。

### 主程序

零件备齐，主程序就短得可爱：

```cpp
fac[0] = 1;     // fac = 1（即 0!）
sum[0] = 0;     // sum = 0

for (int k = 1; k <= n; k++)
{
    mulSmall(fac, facLen, k);           // fac = fac * k  →  fac 现在是 k!
    addBig(sum, sumLen, fac, facLen);   // sum = sum + k!
}
```

三行核心逻辑，和前面的伪代码严丝合缝。**好的封装，能让代码读起来就是思路本身。**

### 两个初始值别搞反

- `fac` 初始 = **1**。因为它要被连续乘，起点必须是乘法单位元 1。**若写成 0，那么 0 乘任何数都是 0，全盘皆错。**
- `sum` 初始 = **0**。它要被连续加，起点是加法单位元 0。

**规模估算**：100! 有 158 位，数组开 300 绰绰有余。总运算量约 `100 轮 × 158 位`，一万多次，瞬间完成。

## 四、易错点

1. **`fac` 初始值写成 0** —— 结果恒为 0。**本题最经典的错误。**
2. **数组开小** —— 100! 有 158 位，若只开 100 会越界，导致高位丢失或程序崩溃。
3. **传参忘了用引用 `int &len`** —— 函数里位数增长了，外面却不知道，后续计算全用旧长度，答案被截断。**这个 bug 很隐蔽，值得警惕。**
4. **每次都重新算 k!** —— 虽然本题 n 小、也能过，但这是没抓住"递推"这个核心思想。养成好习惯。
5. 忘了 `mulSmall` 里进位要用 `while` 展开（第 3 题的老坑）。

## 五、小结

本题的价值不在于"又一个高精度运算"，而在于展示了**高精度的正确使用姿势**：

1. **把每种高精度运算封装成函数**（`mulSmall`、`addBig`……），形成自己的"高精度工具库"；
2. 遇到大数问题时，**用这些函数搭积木**，主程序只负责表达算法逻辑；
3. 善用**递推**（`k! = (k−1)! × k`）避免重复计算。

竞赛中，很多选手会提前准备好一份高精度模板（加、减、乘、比较、输出），考场上直接粘贴使用。你现在做的，正是在打造属于自己的那份模板。

最后一题**数楼梯**，我们会把"递推 + 高精度"这个组合推向极致——用 5000 项的斐波那契数列，算出一个 1000 多位的答案。
