# 讲解稿：数楼梯（ch11-006）

## 一、题目解读

一段 n 级的楼梯，每次可以迈 **1 级**或 **2 级**，问从地面走到第 n 级共有多少种走法？（n ≤ 5000）

这是本章的**压轴题**，把"**递推**"和"**高精度**"两大主题焊在了一起。它也是一道极其经典的题——你会在无数教材里见到它的身影。

## 二、思路分析

### 第一步：找出递推关系

先别急着写代码，我们**手算小数据**找规律：

| n | 走法 | 种数 |
|---|------|------|
| 1 | (1) | 1 |
| 2 | (1,1) (2) | 2 |
| 3 | (1,1,1) (1,2) (2,1) | 3 |
| 4 | (1,1,1,1) (1,1,2) (1,2,1) (2,1,1) (2,2) | 5 |

1, 2, 3, 5, ... 有点眼熟？再算一个 n=5，会得到 8。**1, 2, 3, 5, 8, 13…** —— 这是**斐波那契数列**！

但我们不能靠"眼熟"做题，要能**证明**它。用一个非常重要的思维方式：**关注最后一步**。

> 要走到第 n 级，最后一步只有两种可能：
> - 从第 **n−1** 级迈 1 级上来；
> - 从第 **n−2** 级迈 2 级上来。
>
> 这两种情况**不重不漏**地覆盖了所有走法（因为最后一步要么是 1 级要么是 2 级，没有第三种）。
>
> 所以：**到第 n 级的方案数 = 到第 n−1 级的方案数 + 到第 n−2 级的方案数**

写成递推式：

**f[i] = f[i−1] + f[i−2]**

这个"**看最后一步，把大问题拆成小问题**"的思路，正是**递推**乃至**动态规划**的精髓。请务必体会。

### 第二步：定好边界

递推式有了，还要有**起点**。

- **f[1] = 1**：只有一级台阶，只能迈 1 级，1 种走法。
- **f[0] = 1**：⚠️ **这是全题最容易错的地方！**

为什么 f[0] = 1 而不是 0？"0 级台阶"意味着人已经站在目的地了，**什么都不做**——这本身算作 **1 种**方案（数学上叫"空方案"）。

如果你把 f[0] 设成 0，那么 f[2] = f[1] + f[0] = 1 + 0 = 1，可实际上 n=2 有 2 种走法！**整个数列从这里开始全线崩塌。**

验证一下正确的边界：f[2] = f[1] + f[0] = 1 + 1 = 2 ✓，f[3] = f[2] + f[1] = 2 + 1 = 3 ✓，f[4] = 3 + 2 = 5 ✓。完美对上手算结果。

### 第三步：意识到必须用高精度

斐波那契数长得有多快？它大约以每项 **1.618 倍**（黄金比例）的速度增长。

- f[90] 就已经超过 `long long` 了；
- **f[5000] 有整整 1046 位！**

所以本题的完整解法 = **递推关系** + **高精度加法**。前面五题的功夫，全用上了。

## 三、代码讲解

### 用滚动数组省内存

最直白的写法是开一个二维数组 `f[5005][1100]`，每行存一个高精度数。算一下内存：`5005 × 1100 × 4 字节 ≈ 22 MB`，在 256 MB 限制内，**能过**。

但我们注意到：算 f[i] 只需要 f[i−1] 和 f[i−2]，**更早的项再也用不到了**。既然如此，何必把 5000 项全存下来？

只保留**最近两项**即可，这个技巧叫**滚动数组**：

```cpp
int prev2[L], prev1[L], cur[L];   // 分别是 f[i-2], f[i-1], f[i]
```

内存从 22 MB 骤降到几 KB。虽然本题不卡内存，但这个技巧在很多题里是**救命**的，值得现在就养成习惯。

### 核心循环

```cpp
for (int i = 2; i <= n; i++)
{
    // 高精度加法：cur = prev1 + prev2
    int len = max(len1, len2);
    int carry = 0;

    for (int j = 0; j < len; j++)
    {
        int s = prev1[j] + prev2[j] + carry;
        cur[j] = s % 10;
        carry = s / 10;
    }

    if (carry > 0) { cur[len] = carry; len++; }
    lenC = len;

    // 滚动：把 prev1 挪给 prev2，把 cur 挪给 prev1
    for (int j = 0; j < len1; j++) prev2[j] = prev1[j];
    len2 = len1;

    for (int j = 0; j < lenC; j++) prev1[j] = cur[j];
    len1 = lenC;
}
```

内层就是第 1 题的高精度加法，一字不差。外层负责递推和滚动。

**滚动的顺序不能反！** 必须**先**把 `prev1` 存进 `prev2`，**再**把 `cur` 存进 `prev1`。如果先写 `prev1 = cur`，那 `prev1` 的旧值就被覆盖了，`prev2` 再也拿不到它——递推链就断了。

### 别忘了特判 n ≤ 1

```cpp
if (n <= 1) { cout << 1 << "\n"; return 0; }
```

n = 0 和 n = 1 时答案都是 1，且循环根本不会执行（`i` 从 2 开始），所以要单独处理。**边界特判永远是最后一道保险。**

**复杂度**：外层 5000 轮，内层最多 1046 位，约 500 万次基本运算，运行时间约 15 ms，非常宽裕。

## 四、易错点

1. **f[0] = 0** —— 本题**头号杀手**。必须是 1（空方案也是一种方案）。
2. **数组第二维开小** —— f[5000] 有 1046 位，开 1000 都不够，要开 1100 以上。
3. **滚动顺序写反** —— 先覆盖了 `prev1`，导致 `prev2` 拿到错误的值。
4. **忘记特判 n ≤ 1** —— 循环不执行，输出未初始化的垃圾值。
5. **用 `long long` 硬扛** —— n 稍大就溢出。看到 n = 5000 就该立刻警觉：**这个答案会有多大？**

## 五、小结

**数楼梯**这道题，是本章最好的收官：

- **递推思想**：关注"最后一步"，把 n 级楼梯的问题，拆成 n−1 级和 n−2 级的子问题。这是**递推 / 动态规划**的思维起点。
- **高精度**：当答案大到内置类型装不下时，用数组存数、模拟竖式。
- **滚动数组**：只保留必要的历史状态，把空间从 O(n × 位数) 压到 O(位数)。

回头看这一整章，我们走过的路是：

**加法**（进位）→ **减法**（借位、负数、前导零）→ **乘单精度**（多位进位）→ **乘高精度**（`i+j` 错位相加）→ **阶乘之和**（封装复用 + 递推）→ **数楼梯**（递推 + 高精度 + 滚动数组）

从"实现一个运算"，到"把运算当工具解决问题"——这正是从**学语法**迈向**学算法**的关键一步。
