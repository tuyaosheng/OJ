# 讲解稿：高精度减法（ch11-002）

## 一、题目解读

给两个最多 500 位的非负整数 a、b，求 a − b。

存储方式和上一题一模一样：`string` 读入、倒序存进数组。但减法比加法**多出三个麻烦**，这三个麻烦就是本题的全部考点：

1. **结果可能是负数**（a < b 时）；
2. 某一位**不够减**，要向高位**借位**；
3. 算完可能出现**前导零**（`1000 − 999 = 0001`）。

我们一个一个拆解。

## 二、思路分析

### 麻烦一：负数怎么办？——"永远大减小"

最笨的办法是分情况讨论，写两套逻辑。但有个非常漂亮的技巧：

> **如果 a < b，就交换它们，改算 b − a，最后在答案前面补一个负号。**

因为 `a − b = −(b − a)`。这样一来，**减法函数内部永远是"大的减小的"，结果永远非负**，完全不用操心负数！

所以第一步是**比大小**。怎么比两个 500 位的数？

```cpp
bool greaterEqual(const string &sa, const string &sb)
{
    if (sa.size() != sb.size())
        return sa.size() > sb.size();   // 位数多的就大
    return sa >= sb;                    // 位数相同，字典序比较即可
}
```

- **位数不同**：位数多的那个大（前提是没有前导零，题目已保证）。
- **位数相同**：直接用字符串比较！为什么可以？因为**等长**的数字串，字典序和数值大小是一致的——从最高位开始逐字符比，第一个不同的位就决定了胜负，这正是我们比较数值的方式。（注意：等长是前提。`"9"` 和 `"100"` 字典序 `"9" > "100"`，但数值 9 < 100，所以必须先判位数！）

### 麻烦二：不够减怎么办？——借位

还是小学竖式。算 `52 − 8`：个位 2 减 8 不够，向十位**借 1**（十位的 1 相当于个位的 10），个位变成 12，12 − 8 = 4；十位被借走 1，变成 4。答案 44。

代码：
```cpp
int t = a[i] - b[i] - borrow;    // borrow 是上一位借走的 1

if (t < 0)                       // 本位不够减
{
    t += 10;                     // 向高位借 1，本位就多了 10
    borrow = 1;                  // 记住：高位要少 1
}
else
{
    borrow = 0;
}

c[i] = t;
```

`borrow` 和加法里的 `carry` 是完全对称的：一个是"进位"（往上加），一个是"借位"（往上减）。

因为我们保证了"大减小"，所以**最高位一定够减**，循环结束后 `borrow` 必然是 0，不会出现"借到最后没得借"的窘境。这就是"永远大减小"这个技巧的又一个好处。

### 麻烦三：前导零

算 `1000 − 999`，逐位减完得到数组 `[1,0,0,0]`（倒序），倒着输出就是 `0001`——多了三个前导零！

处理办法：从最高位往下扫，把开头的 0 都砍掉：

```cpp
int len = la;
while (len > 1 && c[len - 1] == 0)
    len--;
```

**注意那个 `len > 1` 的条件**，它至关重要。如果写成 `while (c[len-1] == 0) len--`，那么算 `5 − 5 = 0` 时，会把唯一的那个 0 也砍掉，`len` 变成 0，最后什么都不输出！加上 `len > 1`，就保证**至少留一位**，结果为 0 时正确输出单个 `0`。

## 三、代码讲解

主流程串起来就是四步：

```cpp
// 第一步：保证大减小
bool negative = false;
if (!greaterEqual(sa, sb))
{
    swap(sa, sb);
    negative = true;    // 记住结果是负的
}

// 第二步：倒序存数组（同加法）

// 第三步：逐位相减 + 借位
for (int i = 0; i < la; i++) { ... }

// 第四步：去前导零 + 输出
while (len > 1 && c[len - 1] == 0) len--;

if (negative && !(len == 1 && c[0] == 0))
    cout << "-";
```

最后那个输出条件要特别讲一下。为什么不是简单的 `if (negative) cout << "-"`？

设想一个刁钻的情况：如果代码里 `greaterEqual` 用了 `>` 而不是 `>=`，那么 `5 − 5` 时会判定 "a 不大于 b"，于是交换、`negative = true`。可结果是 0 啊！这时就会输出 **`-0`**，一个不存在的数，直接 WA。

所以稳妥的写法是：**只有当结果不为 0 时才打负号**。条件 `!(len == 1 && c[0] == 0)` 正是在判断"结果不是 0"。

（当然，本题的 `greaterEqual` 用的是 `>=`，相等时不交换，`negative` 保持 false，本来就不会输出 `-0`。但多一层保险总没错——**防御性编程**在竞赛里能救命。）

## 四、易错点

1. **比较两个数时只比字典序，没先比位数** —— `"9"` vs `"100"`，字典序会错判 9 更大。**必须先比长度。**
2. **忘记去前导零** —— 输出 `0001`。
3. **去前导零时把 0 砍光了** —— 忘记 `len > 1`，`5−5` 输出空行。
4. **输出 `-0`** —— 结果为 0 却带了负号。
5. **忘记交换后要加负号**，或者交换了 `sa`/`sb` 却忘了 `la`/`lb` 也要跟着变（本题在 swap 之后才取 `size()`，就是为了避免这个坑）。

## 五、小结

高精度减法 = 加法的镜像，但多了三道关：

| 关卡 | 对策 |
|------|------|
| 结果可能为负 | **先比大小，永远大减小**，最后补负号 |
| 某位不够减 | **借位**：`t += 10; borrow = 1;` |
| 前导零 | 从高位砍 0，但**至少保留一位** |

"永远大减小"是核心思想——**用一次交换，把一个复杂的问题（有正有负）转化成一个简单的问题（只有非负）**。这种"归约"的思路，在算法设计中会反复出现。
