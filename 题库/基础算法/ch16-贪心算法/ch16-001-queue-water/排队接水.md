# 排队接水——讲解稿

## 一、题目解读

n 个人排队用同一个水龙头，顺序你来定，目标是让"平均等待时间"最短。这是贪心算法的入门经典模型——**看似要枚举所有排列（n! 种），实际上一句话就能给出答案**。

## 二、思路分析

先感性猜一下：打水快的人应该排前面，这样后面的人不用等太久。那到底该怎么排？答案是**严格按打水时间从小到大排**。

**证明（交换论证）**：假设某个排队方案里，有相邻两人 A（前）、B（后），且 A 的时间比 B 长。把两人交换位置：

- A、B 两人之外的所有人，等待时间完全不变（他们前面的人的时间总和没变）；
- A、B 两人之间：交换前，B 在等一个"慢"的 A；交换后，A 在等一个"快"的 B——两人等待时间之和变小了。

所以**只要队伍中存在"前面比后面慢"的相邻两人，交换一定不会变差**。反复交换直到没有这种情况，就是从小到大排好序的状态——这就是最优解。

## 三、代码讲解

```cpp
sort(t, t + n);
long long total = 0, wait = 0;
for (int i = 0; i < n; i++) {
    total += wait;
    wait += t[i];
}
```

`wait` 滚动累计"目前排在前面的人一共用了多久"，每个人的等待时间就是轮到他时的 `wait` 值。不需要真的算出每个人的等待时间再求和，一边扫一边累加即可，O(n)。

## 四、易错点

1. 以为要枚举全排列——数据范围 n≤1000 时 1000! 是天文数字，根本不可能；
2. 忘记排序，直接按输入顺序算——那不是最优解；
3. `total` 用 int 存：n=1000、t=1000 时 total 最大约 5×10⁸，虽然 int 也许卡线能装下，但养成 **long long** 的习惯更安全；
4. 输出忘记保留两位小数。

## 五、小结

"排序 + 交换论证"是贪心算法最基础也最常用的证明手段：假设最优解不是排好序的，找一对"逆序"的元素交换，证明交换后不会变差，从而说明排好序就是最优。后面几乎所有排序类贪心都用这个思路。
