# 矿车配对——讲解稿

## 一、题目解读

矿车一次最多装 2 块矿石、总重不超限，求最少车数。这是"纪念品分组"模型的具象化（同类问题在很多地方都会遇到：行李打包、船只载客等），用**双指针**贪心解决。

## 二、思路分析

排好序后，看两端：**最重的那块（w[j]）无论如何都必须占一辆车**——因为它是当前剩下的矿石里最重的，没有比它更重的能跟它一起去挤占别的车。既然这辆车已经"注定要发"了，不如问一句："能不能顺便把最轻的那块（w[i]）也捎上？"——如果 `w[i] + w[j] <= W`，那就捎上，一举两得；捎不上，最轻的那块留着以后再配对（它比其他矿石轻，以后更容易凑对）。

这个策略保证了**每一辆已经确定要发的车都尽量满载**，不会有"明明能多装一块却浪费了车次"的情况，所以车辆数最少。

## 三、代码讲解

```cpp
sort(w, w + n);
int i = 0, j = n - 1, cars = 0;
while (i <= j) {
    if (i < j && w[i] + w[j] <= W) i++;   // 配对成功，轻的那个指针前移
    j--;                                   // 重的这个一定发车了
    cars++;
}
```

`i < j` 这个条件防止只剩最后一块矿石时把自己和自己配对；`j--` 和 `cars++` 每轮循环都执行（不管这轮是配对成功还是重的单独走），因为**每轮循环恰好对应发一辆车**。

## 四、易错点

1. 判断条件漏了 `i < j`——当 i、j 指向同一块矿石时会把它"和自己配对"，逻辑错误；
2. 以为要枚举所有配对方式——n=10⁵ 时不可能枚举，双指针 O(n log n)（排序为主）足够；
3. 题目保证"每块矿石单独一辆车能装下"（w[i] ≤ W），所以不用担心有块头矿石连自己都装不下的边界；
4. 循环里 `j--` 和 `cars++` 忘记在两个分支里都执行——这是本题最容易出错的地方，画图模拟几个例子最保险。

## 五、小结

双指针贪心是"排序 + 从两端向中间夹逼"的通用套路：一端代表"必须优先处理的极端值"，另一端代表"顺便搭车的候选"。以后见到"两两配对使总数最少/最多"，先想想这个模型。
