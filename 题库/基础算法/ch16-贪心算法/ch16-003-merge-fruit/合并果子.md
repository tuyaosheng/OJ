# 合并果子——讲解稿

## 一、题目解读

n 堆果子合并成 1 堆，每次合并耗费=两堆重量之和，求最小总耗费。这题和"排队接水""混合牛奶"同属贪心，但用到了不同的数据结构武器——**堆**。

## 二、思路分析

想象一下：如果先合并两个很大的堆，这两堆的重量会被这次合并"计一次费"；如果之后这个大堆又参与合并，它又要被计一次费——**越早参与合并的堆，越可能被反复计费**。所以我们希望**最小的堆尽早合并、尽早变成别的堆的一部分，从而少参与几次后续的计费**。

严格来说这是**哈夫曼编码**的思想：每次合并权值最小的两个节点，最终总代价最小（可以证明这样构造出的是"带权路径长度最小"的二叉树）。

## 三、代码讲解

"每次找最小的两堆"——用**小根堆（优先队列）**最高效：

```cpp
priority_queue<long long, vector<long long>, greater<long long>> pq;
while (pq.size() > 1) {
    long long x = pq.top(); pq.pop();
    long long y = pq.top(); pq.pop();
    total += x + y;
    pq.push(x + y);
}
```

每次 `top()` 拿最小值、`pop()` 弹出、算完耗费后把新堆 `push` 回去——堆会自动维护"当前最小值"，每次操作 O(log n)，总复杂度 O(n log n)。

对比第 8 章"C++ 实用技巧与模版库"里第一次用到 priority_queue 的那道同名练习题——这里我们把它当作**贪心算法的正式例题**再讲一遍：贪心的关键不是"用了堆"，而是"每次选代价最小的两个合并"这个策略本身。

## 四、易错点

1. 用普通数组每次扫一遍找最小的两个——O(n) 找一次，总共 O(n²)，n=10000 时会超时，必须用堆把找最小值降到 O(log n)；
2. 总耗费用 int 存：n=10000 时最坏情况总耗费可达 10⁹ 级，**必须 long long**；
3. `pq.size() > 1` 别写成 `!pq.empty()`——只剩一堆时不用再合并了。

## 五、小结

"贪心策略 + 合适的数据结构实现"是很多贪心题真正的难点：策略往往一句话（"每次选最小的两个"），但怎么快速找出最小的两个，需要用对数据结构。这里是堆，以后遇到"每次找区间最值""动态维护有序序列"，也要下意识想到堆、平衡树、单调队列这些工具。
