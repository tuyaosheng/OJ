# 烂橘子 讲解稿

## 考点
BFS 框架的第三次变化：从"单起点"变成"多起点"（多源 BFS）。

## 引入（1 分钟）
前三题的 BFS 都只有**一个**起点。这题很多同学第一反应是："那就对每个烂橘子分别跑一次 BFS，取最小值？"——这个思路是错的，或者说，是把问题搞复杂了。**所有烂橘子是同时开始腐烂扩散的**，正确的做法是把它们**一次性全部放进队列**，当成 BFS 的"第 0 层"一起出发。

## 核心推导（重点，讲透）
**为什么不能对每个烂橘子分别跑 BFS 再取最小值**：这样做，"某个新鲜橘子几分钟后变烂"确实能算对（取所有烂橘子源头的最短距离的最小值），但代价是要跑很多次 BFS，效率低；更麻烦的是，这题真正要求的是"全部橘子都烂掉需要多少分钟"，如果分开算，还得把每个格子的"最小距离"再求一次最大值，逻辑绕了一大圈。

**多源 BFS 的正确做法**：初始化时，把所有 `grid[i][j] == 2`（烂橘子）的格子**全部**设置 `dist = 0` 并入队，而不是只放一个。之后的 BFS 扩展逻辑和单源 BFS完全一样——因为所有源点都在"第 0 层"，它们各自向外扩散的"第 1 层"会自然地在 BFS 的同一轮被一起处理，等价于"所有烂橘子同时行动"。跑完 BFS，每个新鲜橘子格子的 `dist` 就是"它第几分钟变烂"，取所有新鲜橘子里 `dist` 的**最大值**，就是"全部变烂"需要的时间。

## 代码逐行讲解
```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        scanf("%d", &grid[i][j]);
        if (grid[i][j] == 1) freshCount++;
        if (grid[i][j] == 2) {
            dist[i][j] = 0;      // 所有初始烂橘子同时是第 0 分钟
            q.push({i, j});      // 多源 BFS：一次性把所有起点入队
        }
    }
}
```
- 这几行是本题和前面单源 BFS 唯一的结构性差别：初始化阶段循环整个网格，把所有源点一次性入队，而不是只入队一个起点。

```cpp
printf("%d\n", freshCount == 0 ? maxTime : -1);
```
- 用一个计数器 `freshCount` 记录"还剩多少个新鲜橘子没被感染"，BFS 扩展成功一个就减一；跑完 BFS 后如果还有没被感染的（`freshCount > 0`），说明存在永远烂不掉的橘子，输出 `-1`。

## 易错点
- **最容易犯的错**：只把"第一个找到的"烂橘子入队，或者写成"对每个烂橘子单独跑一次 BFS"——这两种写法要么算错，要么低效，务必强调"一次性全部入队"这个关键点。
- 特判"一开始就没有新鲜橘子"直接输出 `0`，不要走 BFS 流程（虽然不特判也不会出错，因为 BFS 跑完 `freshCount` 仍是 `0`，但特判能提前退出、逻辑更清楚）。
- `dist` 数组同时兼职"是否已经腐烂"的标记，判断条件是 `grid[nx][ny] != 1`（只有新鲜橘子才能被感染）和 `dist[nx][ny] != -1`（已经烂过的不用再烂一次）。

## 课堂串讲提示
练2"僵尸潮扩散距离"是这道题的直接变式，把"求全部感染时间"换成"求每个格子的感染时间"——多源 BFS 的框架完全不变，讲完这题后布置练2，可以直接让学生对照代码找不同。
