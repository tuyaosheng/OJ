# 抓住那头牛 讲解稿

## 考点
BFS 框架的第二次变化：从"网格"搬到"抽象状态空间"。

## 引入（1 分钟）
前两题的"格子"都是看得见摸得着的棋盘位置，这题要做一次抽象：**BFS 真正需要的只是"状态"和"状态之间怎么转移"，不需要状态长得像格子**。这里的"状态"就是数轴上的一个整数位置，"转移"就是 `x-1`、`x+1`、`x*2` 这三种移动方式——想清楚这个对应关系，这题的 BFS 代码和前两题几乎一样。

## 核心推导（重点，讲透）
把 `0` 到 `100000` 这 100001 个整数，当成 BFS 里的"格子"（一维数组代替二维网格），`dist` 数组记录"从农夫初始位置到这个数字最少需要几分钟"。起点是 `n`，扩展规则是 `x-1`、`x+1`、`x*2` 三条边，第一次到达 `k` 就是答案。

**为什么这题的"边界判断"和前两题不太一样**：网格类 BFS 判断的是"有没有出界、是不是墙"；这题判断的是"新位置有没有超出 `[0, 100000]` 这个范围"——超出这个范围的状态对抓到 `k` 没有意义（`k` 本身就在这个范围内，跑到范围外面只会离题目要求的目标更远），所以直接舍弃，不需要真的开一个更大的数组去存储。

## 代码逐行讲解
```cpp
int next[3] = {x - 1, x + 1, x * 2};
for (int i = 0; i < 3; i++) {
    int nx = next[i];
    if (nx < 0 || nx > 100000) continue;
    if (dist[nx] != -1) continue;
    dist[nx] = dist[x] + 1;
    q.push(nx);
}
```
- 三种转移方式直接列成一个长度为 3 的数组，循环处理——和前两题"方向数组"的写法是同一个思路，只是这次的"方向"不是几何方向，而是三种操作。

## 易错点
- 容易漏掉 `x * 2` 可能超过 `100000` 的情况，如果不判断直接往数组里写，会数组越界（这是本题最容易崩溃/运行错误的地方）。
- 不需要对 `n >= k` 的情况写特判——BFS 会自动只用 `-1` 这条边走出最短路径 `n - k`；手写特判反而容易和 BFS 的结果对不上（比如漏掉某些 `n < k` 但 `-1` 更优的边界情况）。
- 状态空间是"一维数组"，不是"二维网格"，很多同学会下意识地想套用网格 BFS 的写法，结果代码里出现不必要的 `x`、`y` 两个坐标——提醒自己"状态是什么"，才能少写冗余代码。

## 课堂串讲提示
这题讲完后，可以问学生一个开放问题："如果农夫还能 `x -> x/3`（如果能整除），BFS 的代码要怎么改？"——引导他们意识到**只要修改"转移规则"这一小段代码，BFS 框架完全不用动**，这正是抽象出"状态空间"这个概念的意义。
