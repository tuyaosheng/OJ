# 马的遍历 讲解稿

## 考点
BFS 框架的第一次变化：换移动规则；顺带体会"一次 BFS 求所有点最短距离"这个天然优势。

## 引入（1 分钟）
和例1对比：唯一的区别是"怎么从一个格子走到下一个格子"——例1是"上下左右挪一格"，这题是"走日字"。**BFS 的框架（队列 + dist 数组 + 一层层扩散）完全不用改，只需要把方向数组换成马的 8 种走法**。这提醒我们：学 BFS 不是在学某一道具体的题，而是在学一套能适配各种"移动规则"的通用框架。

## 核心推导（重点，讲透）
马的 8 种走法：横向挪 2、纵向挪 1，或者横向挪 1、纵向挪 2，四个象限各两种组合，一共 8 个 `(dx, dy)` 偏移量。除此之外，代码结构和例1一模一样。

**这题为什么不是"对每个格子跑一次 BFS"**：如果要分别求"起点到格子 A 的最短步数""起点到格子 B 的最短步数"……对每个格子都单独跑一次 BFS，复杂度会是 `O((nm)^2)`，对 `400×400` 的棋盘完全跑不动。但 BFS 的"一层层扩散"本身就会把从起点出发能到达的**所有**格子都访问一遍，并且访问到的那一刻 `dist` 值就是最短步数——所以**只需要跑一次 BFS，`dist` 数组填满的过程，就同时求出了到所有格子的最短步数**。这是 BFS 相比"单点最短路径搜索"的天然优势，也是这道题真正的考点。

## 代码逐行讲解
```cpp
int dx[8] = {-2, -2, -1, -1, 1, 1, 2, 2};
int dy[8] = {-1, 1, -2, 2, -2, 2, -1, 1};
```
- 把 8 种走法配对好、写成两个数组，扩展逻辑和例1完全复用（这也是为什么"方向数组"要单独抽出来，而不是写在循环体里手动列 8 个 if）。

## 易错点
- 8 种偏移量容易写漏或写重，建议画一个"日"字网格图对照着写，写完后数一遍确实是 8 个不重复的组合。
- 起点自己的 `dist` 是 `0`，不是 `-1`，不需要特殊处理——BFS 一开始就把 `dist[起点]=0` 设好了。
- 输出量很大（`400×400=16` 万个数），逐个用 `cout <<` 且没加速可能会偏慢，用 `printf` 更稳妥。

## 课堂串讲提示
可以顺便提一句：这题如果棋盘很小（比如 `n=1` 或 `m=1`），马根本没法移动，这时候大部分格子的 `dist` 都会保持 `-1`——`ch18-002` 的测试点里专门放了几个这样的"细长棋盘"，可以在讲解时演示一下这种边界情况。
