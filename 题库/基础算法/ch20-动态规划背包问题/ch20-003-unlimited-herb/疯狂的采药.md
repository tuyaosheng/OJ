# 疯狂的采药 讲解稿

## 考点
完全背包：物品能重复选取，一维数组的遍历方向和 01 背包相反。

## 引入（1 分钟）
还是采药的场景，只改了一条规则："每种草药能采无限次"。问学生："这一条规则的变化，会让代码的哪一部分需要修改？"——引导他们意识到：状态定义和"选或不选"的框架都不用变，唯一要变的是**一维数组的遍历方向**。

## 核心推导（重点，讲透）
01 背包一维优化时 `j` 要从大到小遍历，目的是保证 `dp[j-t[i]]` 还是"这件物品参与决策之前"的值，不会被自己重复计算。完全背包恰恰要反过来：**故意让 `dp[j-t[i]]` 可能已经被这种草药更新过**——这正是"允许重复选取"的实现方式：

```
for j = t[i] to T:      // 从小到大！
    dp[j] = max(dp[j], dp[j - t[i]] + v[i])
```

`j` 从小到大遍历时，算 `dp[j]` 的时候 `dp[j-t[i]]`（下标更小，已经被处理过）有可能已经包含了"采过这种草药一次或多次"的结果，这样 `dp[j] = dp[j-t[i]] + v[i]` 就相当于"在已经采过若干次的基础上，再采一次"——递推的过程本身就允许同一种草药被多次计入。

## 代码逐行讲解
```cpp
for (int j = t; j <= T; j++) {           // 完全背包：j 从小到大
    dp[j] = std::max(dp[j], dp[j - t] + v);
}
```
和【例1】的代码几乎一模一样，**唯一的区别就是这一行 `for` 循环的方向**——这行代码的对比，是本章最重要的一次"划重点"。

## 易错点
- 把这题的遍历方向也写成从大到小（照抄【例1】没改方向）：这是最常见、也最隐蔽的错误——因为代码能正常跑、大部分小数据也能算对（当每种草药只能采 0 或 1 次时两种写法结果一样），只有在"确实需要采同一种草药多次才能达到最优"的数据上才会算错，容易被忽略。
- `T` 的范围比【例1】大很多（最大 `10^5`），乘以草药种数（最大 `1000`），总时间复杂度 `O(nT)` 接近 `10^8`，一维数组是必须的，不能像二维数组那样浪费内存。

## 课堂串讲提示
建议把【例1】和这题的核心两行代码贴在一起对比讲：
```
01 背包（例1）：  for (j = T; j >= t; j--)
完全背包（本题）：for (j = t; j <= T; j++)
```
让学生一眼看出"只差一个遍历方向"，比反复口头强调更有效。
