# 采药 讲解稿

## 考点
01 背包入门：DP 三要素在"选或不选"类问题上的标准写法，以及一维滚动数组优化。

## 引入（1 分钟）
先回顾上一章"数字三角形"：状态是二维的，转移只依赖"上一层"，这一章的背包问题也有同样的性质。先按最直观的方式想：`dp[i][j]` = 只考虑前 `i` 株草药、时间不超过 `j` 分钟时的最大价值。

## 核心推导（重点，讲透）
第 `i` 株草药只有两种选择：
- **不采**：价值和"只考虑前 `i-1` 株草药、时间不超过 `j` 分钟"一样，`dp[i][j] = dp[i-1][j]`；
- **采**（前提是 `j >= t[i]`）：先花 `t[i]` 分钟采下它，得到 `v[i]` 价值，剩下 `j - t[i]` 分钟留给前 `i-1` 株草药，`dp[i][j] = dp[i-1][j-t[i]] + v[i]`。

两种选择取较大值，就是 `dp[i][j]`。

**滚动数组优化**：观察发现 `dp[i][...]` 只用到了 `dp[i-1][...]`，不需要保留 `i-2` 层及更早的数据。可以把二维数组压缩成一维 `dp[j]`，用"同一个数组"表示"上一层"和"这一层"——**压缩之后，`j` 必须从大到小遍历**。原因：如果从小到大遍历，算 `dp[j]` 时用到的 `dp[j-t[i]]` 可能已经被**这一株草药自己**更新过了（因为 `j-t[i] < j`，会被更早处理到），这就相当于允许"这株草药被采了两次"，破坏了"每株最多采一次"的限制。从大到小遍历，能保证更新 `dp[j]` 时，`dp[j-t[i]]` 还是"处理这株草药之前"的值，也就是"前 `i-1` 株"的状态，逻辑上完全对应二维版本的 `dp[i-1][j-t[i]]`。

## 代码逐行讲解
```cpp
for (int i = 1; i <= n; i++) {
    int t, v;
    scanf("%d %d", &t, &v);
    for (int j = T; j >= t; j--) {
        dp[j] = std::max(dp[j], dp[j - t] + v);
    }
}
```
- 草药信息可以边读边处理，不需要先存进数组再遍历——这是一维背包写法的一个额外好处：省去了存储所有物品信息的数组。
- 内层循环下界是 `t`（而不是 `0`）：`j < t` 时这株草药根本装不下，不需要考虑。

## 易错点
- **`j` 的遍历方向搞反是本题头号错误**：一定要从大到小，这是区分"01 背包"和"完全背包"最核心的一行代码，务必让学生手动模拟一个小例子（比如两个相同的物品）观察两种遍历方向算出的结果差异。
- 内层循环下界写成 `0` 而不是 `t`：不会算错（因为 `j < t` 时 `j - t` 会越界），但会导致数组越界访问，是一个隐蔽的 bug。
- 数组开够 `T+5` 左右的大小。

## 课堂串讲提示
这题建立的"二维→一维、遍历方向决定物品能否重复选"这套逻辑，会在接下来几道例题反复用到——例3（完全背包）会把这行代码的方向反过来，届时可以直接对比这两行代码，帮学生把两种模型的区别刻进记忆里。
