# 硬币凑数方案 讲解稿

## 考点
【例3】完全背包的直接变式：求最优值 → 求方案数，延续上一章"过河卒"讲过的转化规律，并揭示一个更隐蔽的坑——循环顺序决定"组合"还是"排列"。

## 引入（1 分钟）
先复习上一章的规律："只要转移能写成从几个更小子问题过来，把 `max` 换成'求和'，就能把'求最优值'的 DP 改成'求方案数'的 DP"。这题正是完全背包版本的这个转化。

## 核心推导（重点，讲透）
转移方程直接沿用完全背包的方向（`j` 从小到大，允许重复使用同一种硬币），把 `max` 换成"加起来"：
```
for i = 1 to n:
    for j = w[i] to S:
        dp[j] = (dp[j] + dp[j - w[i]]) % MOD
```

**这题真正的难点，是循环顺序会改变"统计的是什么"**：
- **外层枚举硬币种类，内层枚举金额**（上面的写法）：处理完第 `i` 种硬币，才会处理第 `i+1` 种，"哪种硬币先用、哪种后用"不会产生不同的方案——统计出的是**组合数**（不区分顺序），也就是题目要的答案。
- 如果把两层循环顺序交换，**外层枚举金额、内层枚举硬币种类**，会把"先用 1 元、后用 2 元"和"先用 2 元、后用 1 元"当成两种不同的方案分别计数——统计出的是**排列数**（区分顺序），不是题目要的答案。

这是完全背包计数问题里最容易被忽略、也最容易出错的细节，强烈建议现场带学生手动模拟一个"用 1 元和 2 元凑 3 元"的极小例子，对比两种循环顺序算出的结果（2 种组合 vs 3 种排列），把这个区别讲透。

## 代码逐行讲解
```cpp
dp[0] = 1;
for (int i = 1; i <= n; i++) {
    int w;
    scanf("%d", &w);
    for (int j = w; j <= S; j++) {
        dp[j] = (dp[j] + dp[j - w]) % MOD;
    }
}
```
- `dp[0] = 1` 是边界：凑出 0 元，只有"什么都不拿"这一种方案。
- 每一步加法都要取模，别忘了。

## 易错点
- 循环顺序写反（外层金额、内层硬币）——这是本题设计的核心陷阱，一定要让学生真正理解"为什么"，而不是死记"硬币在外层"这句话。
- `dp[0]` 忘记初始化成 `1`（而不是默认的 `0`），会导致整个数组全部算出 `0`。

## 课堂串讲提示
这题适合作为背包问题这一章的收尾：融合了完全背包的转移方向、"求最优值→求方案数"的转化规律，还引出了一个新的坑（循环顺序影响"组合"还是"排列"）——讲完这题，可以布置一道课后思考题："如果这题要求区分顺序（即求排列数），代码要怎么改？"留给学有余力的学生自己验证。
