# 分治法求最大子段和 讲解稿

## 考点
真分治的又一次练习：拆数据、递归、合并，只是这次"合"的内容不一样。

## 引入（1 分钟）
这题很多学生在第 10 章"常用基础算法概述"里已经用**前缀和/动态规划的思路**（Kadane 算法，一趟扫描）做过。今天要求换一种做法——**分治**，目的不是求更快的解法（分治是 `O(n log n)`，反而比 Kadane 的 `O(n)` 慢），而是**巩固"拆-治-合"这套框架**，并体会"同一个问题可以有多种解法"。

## 核心推导（重点，讲透）
把区间 `[l, r]` 从中点 `mid` 切开，最大子段和只有三种可能：
1. **完全落在左半** `[l, mid]`——这是规模减半的同类子问题，递归求；
2. **完全落在右半** `[mid+1, r]`——同上，递归求；
3. **横跨中点**，也就是子段一定包含 `a[mid]` 和 `a[mid+1]` 这两个位置——这种情况**不能再递归拆下去**，因为一旦再切一刀，横跨的这段就被破坏了，必须**直接算**。

第 3 种情况怎么 `O(n)` 直接算：从 `mid` 出发向左扫，边扫边累加，记录途中出现过的**最大前缀和**（这就是"以 `mid` 结尾、向左延伸能拿到的最大和"）；同理从 `mid+1` 出发向右扫，记录最大后缀和。两者相加，就是"横跨中点"能达到的最大子段和。

三种情况取最大值，就是 `[l, r]` 的答案。整体复杂度：切 `log n` 层，每层"合"的代价加起来是 `O(n)`，所以是 `O(n log n)`。

## 代码逐行讲解
```cpp
ll crossMax(int l, int mid, int r) {
    ll leftMax = -4e18, sum = 0;
    for (int i = mid; i >= l; i--) {
        sum += a[i];
        leftMax = std::max(leftMax, sum);
    }
    ...
}
```
- `leftMax` 初始值要设得足够小（不能是 0！因为 `a[i]` 可能全是负数，真正的最大前缀和也可能是负数）。
- `maxSubarray` 递归终止条件是 `l == r`（区间只剩 1 个数），直接返回这个数——哪怕它是负数，因为题目要求子段**非空**。

## 易错点
- 初始值陷阱：`leftMax`/`rightMax` 如果初始化成 0，遇到"全是负数"的数据会算出错误的偏大结果（相当于默许了"一个数都不选"），本题特意设计了 `tests/3.in`（全是 `-1`）来专门检验这一点。
- 求和要用 `long long`：`n=10^5` 个 `10^9` 级别的数累加，可达 `10^14`。
- 这题和 ch17-002（归并排序求逆序对）是本章"真分治"这条线上的两道题，可以对照读：两题的"分"和"治"几乎一样，区别全在"合"那一步在做什么——一个是双指针合并两个有序序列，一个是算横跨中点的最大和，体会"分治的骨架不变，合并的内容因题而异"。

## 课堂串讲提示
可以布置学生课后用 Kadane 算法（`O(n)`）重写一遍这题，然后对照分治版本的代码量和思路复杂度，讨论"分治不是任何时候都是最优解法，但训练价值不小"。
