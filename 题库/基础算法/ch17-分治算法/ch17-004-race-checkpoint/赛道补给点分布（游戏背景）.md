# 赛道补给点分布（游戏背景） 讲解稿

## 考点
二分答案的另一个方向：最大化最小值。是 ch17-003 的对照练习。

## 引入（1 分钟）
这题的场景是给竞速游戏设计赛道补给点，但撕开"游戏"这层外壳，数学模型和"教室里安排考生座位、让相邻考生间距尽量大"完全一样——练习的目的是让学生看穿包装，认出熟悉的模型。

## 核心推导（重点，讲透）
- 先把候选坐标从小到大排序，"相邻"才有意义。
- 单调性：设"最小间距"为 `x`，`x` 越大，能选出的点就越少（或不变）——这是单调不增的关系，方向和 ch17-003 相反：那题是"限制越松（`limit` 越大）越容易满足"，这题是"要求越高（`x` 越大）越难满足"。
- `check(mid)`：贪心地从第一个点开始选（第一个点一定选，能让后面选得更多），只要下一个候选点与"上一个选中的点"的距离 `>= mid`，就选它；扫完统计一共选出多少个点，`>= k` 就说明 `mid` 可行。
- 二分范围：下界 `0`（间距可以小到 0，比如强行选相邻很近的点），上界 `坐标最大值 - 坐标最小值`（只选首尾两个点时能达到的最大间距）。

## 代码逐行讲解
```cpp
ll L = 0, R = pos[n] - pos[1];
while (L < R) {
    ll mid = L + (R - L + 1) / 2;   // 向上取整
    if (check(mid)) {
        L = mid;        // mid 可行，答案可能更大，收缩到右半区间（含 mid）
    } else {
        R = mid - 1;    // mid 不可行，答案一定更小，收缩到左半区间
    }
}
```
- 这是"求最大可行值"的二分答案标准写法，和 ch17-003"求最小可行值"正好是镜像：这里 `check` 为真要把 `L` 收缩到 `mid`（`mid` 本身可能就是答案），所以 `mid` 必须**向上取整**（`(R - L + 1) / 2`），否则当 `L` 和 `R` 只差 1 时会死循环——这是本题最容易踩的坑，务必带学生手动模拟一遍 `L=1, R=2` 时如果用向下取整会发生什么。

## 易错点
- `mid` 向上取整 vs 向下取整，要跟"`check` 为真时把哪个边界收缩到 `mid`"配对着记，不要死背哪种题型用哪种取整——理解了"会不会死循环"就不会记混。
- 数组下标从 1 开始的话，`pos[n] - pos[1]` 才是排序后第一个和最后一个的差，不要写成 `pos[n-1]`（那是 0-indexed 的习惯，容易和这里的写法搞混）。
- 这题看似换了游戏皮肤，但判定函数的贪心逻辑和 ch17-003 的判定函数长得几乎一样（都是"从头贪心累加，超限就重新开始计数"），可以让学生对照两份 `check` 代码，体会"贪心判定 + 二分外壳"这套组合拳的通用性。

## 课堂串讲提示
本题作为练习题布置时，可以先不给出"这是二分答案"的提示，让学生自己识别出这是"教室座位分配"的变式——识别模型的能力比记代码模板更重要。
