# 讲解稿：错位排列（ch13-004）

## 一、题目解读

n 封信、n 个信封，每封信都有唯一正确的信封。现在要**全部装错**——**没有任何一封信**装进了正确的信封。问有多少种装法？

记作 **D(n)**。n = 3 时 D(3) = 2；n = 4 时 D(4) = 9（著名的"九种装错法"）。

**这题是本章的分水岭。**

前三题的递推式，你或许能靠"感觉"猜出来（都是斐波那契的变体）。但**错位排列的递推式，你猜不出来**——它必须靠**严格推导**。

如果你能独立推出它，说明你真正掌握了递推思维；如果推不出来，也别灰心，跟着走一遍，体会推导的"味道"。

## 二、思路分析

### 老规矩：盯住"最后一个"

考虑**第 n 封信**。它不能进 n 号信封（否则就装对了）。

那它进了几号呢？只能是 **1 ~ n−1** 中的某一个，设为 **k 号**。

**k 有 n−1 种选择。**

（先记住这个 `n−1`，它会出现在最终公式里。）

### 关键一问：那么"第 k 封信"去哪了？

第 n 封信占了 k 号信封。现在反过来看：**第 k 封信**（它本来该进 k 号，但 k 号被占了）会去哪？

**这里恰好分成两种情况**——而且这个分类是全题的**灵魂**：

---

### 情况一：第 k 封信 进了 **n 号**信封

也就是说，信 n 和信 k **互相交换了信封**（n 进了 k 的，k 进了 n 的）。

这两封信都已安置妥当，且都装错了 ✓

**剩下的问题**：还有 **n−2** 封信（除了 n 和 k）要放进 **n−2** 个信封（除了 k 号和 n 号），且要**全部装错**。

→ 这正是规模为 n−2 的**同类问题** → **D(n−2)** 种。

---

### 情况二：第 k 封信 **没有**进 n 号信封

这种情况更妙，请慢慢体会。

现在的局面是：

- 信 n 已放好（在 k 号信封里）。
- 剩下 **n−1** 封信：`1, 2, …, n−1`（除去信 n）。
- 剩下 **n−1** 个信封：`1, 2, …, n−1` 中除去 k 号，**再加上 n 号**。

每封信的"禁忌"是什么？

- 对信 i（i ≠ k）：不能进 **i 号**（自己的信封）。
- 对信 **k**：不能进 **n 号**（这是情况二的前提！）。

**看出来了吗？** 每封信都恰好有**一个**"禁止进入"的信封，而且这 n−1 个禁忌**两两不同**、正好覆盖了这 n−1 个信封。

> **这在结构上，和"n−1 封信全部装错"完全同构！**
>
> 只要我们把 **n 号信封**"重命名"为**第 k 封信自己的信封**，那么"信 k 不能进 n 号"就变成了"信 k 不能进自己的信封"——和其他信的限制一模一样。

→ 于是这就是规模为 n−1 的同类问题 → **D(n−1)** 种。

---

### 合并

对于**每一个** k（共 n−1 种选择），方案数是 `D(n−1) + D(n−2)`。所以：

### **D(n) = (n − 1) × [ D(n−1) + D(n−2) ]**

**边界**：
- `D(1) = 0`（唯一的信只能装进唯一的信封，必然装对，无法全错）
- `D(2) = 1`（两封信互换，唯一的一种）

**验算**：
- `D(3) = 2 × (D(2) + D(1)) = 2 × (1 + 0) = **2**` ✓ 与样例一致
- `D(4) = 3 × (D(3) + D(2)) = 3 × (2 + 1) = **9**` ✓ 正是"九种装错法"

## 三、代码讲解

```cpp
long long d1 = 0;   // D(1)
long long d2 = 1;   // D(2)
long long cur = 0;

for (int i = 3; i <= n; i++)
{
    cur = (long long)(i - 1) * ((d2 + d1) % MOD) % MOD;

    d1 = d2;        // 滚动
    d2 = cur;
}
```

### 溢出：本题最凶险的地方

看这一行的量级：

- `(i - 1)` 最大约 **10^6**
- `(d2 + d1)` 取模后最大约 **2 × 10^9**
- 两者**相乘** ≈ **2 × 10^15**

`int` 上限 2×10^9 —— **溢出到姥姥家去了**。必须 `long long`（上限 9.2×10^18，够用）。

**而且注意转换的位置**：

```cpp
cur = (long long)(i - 1) * (...) % MOD;    // ✓ 正确
cur = (i - 1) * (...) % MOD;               // ✗ 危险！
```

第二种写法里，`(i-1)` 是 int，如果 `(...)` 也是 int，那么**乘法在 int 里进行**，溢出后再赋给 long long —— **为时已晚**。

> **必须在乘法【之前】完成类型提升。** 这是 C++ 的经典陷阱，第 12 章的 A-B 数对里我们已经踩过一次，这里再次强调。

（本题的 `d1`、`d2` 本身就是 `long long`，所以乘法会自动提升。但显式写 `(long long)` 是个好习惯——**别依赖运气**。）

**复杂度**：O(n)，100 万次循环。

## 四、易错点

1. **想不出递推式，试图找通项公式** —— 错位排列确实有通项 `D(n) = n! × Σ(-1)^k/k!`，但它含**除法**，在取模意义下需要**逆元**（超纲）。**老实用递推。**
2. **溢出** —— `(i-1) × (D(n-1)+D(n-2))` 达 10^15，必须 long long，且转换要在乘法前。
3. **边界 `D(1) = 0` 写成 1** —— 一封信不可能装错。
4. **忘记取模** 或 **取模位置不对** —— 建议每步都取。
5. **推导时把情况一、二搞混或漏掉** —— 这是理解层面的错误，多画图。

## 五、小结

### 本题教会我们什么？

**递推的核心，是"分类讨论"的功夫。**

回顾整个推导，我们做的其实是一件事：**把"n 封信全错"这个大集合，不重不漏地劈成若干个小块，每块都能用更小规模的答案来表示。**

- 先按"信 n 进了哪个信封"分成 n−1 类；
- 每类再按"信 k 是否进了 n 号"分成 2 种；
- 每种都归约成 D(n−1) 或 D(n−2)。

**难点不在代码（就 3 行），而在这个分类是否"不重不漏"。**

### 情况二的"同构"技巧

情况二里那个"**把 n 号信封看作信 k 自己的信封**"的重命名技巧，是全题最精彩的一笔。

它体现了一种重要的数学思维：

> **不要盯着表面的标签，要看结构。** 两个问题只要**结构相同**，答案就相同——哪怕它们讲的是完全不同的故事。

这种"**同构**"的眼光，在组合数学和算法设计中价值连城。
