# 讲解稿：传球游戏（ch13-006）

## 一、题目解读

n 个同学站成**一个圆圈**（1 到 n 编号，1 号和 n 号相邻）。球从 **1 号**出发，每次只能传给**左右相邻**的人。传了恰好 **m** 次后，球**回到 1 号**手里。求传球方法数。

这是本章的**综合演练**，把前面所有的套路揉在一起，还加了两个新挑战：

1. **状态是二维的**：光记"传了几次"不够，还得记"球现在在谁手里"。
2. **结构是环形的**：下标要**绕圈**。

## 二、思路分析

### 第一步：为什么状态必须是二维的？

前面几题的状态都是一维的（`f[i]`）。这题行不行？

假设我们只记 `f[i]` = "传了 i 次的方案数"——**这没法转移！** 因为下一次能传给谁，**取决于球现在在谁手里**。信息不够，递推走不下去。

> **状态必须包含"决定未来走向的全部信息"。** 这是定义状态的黄金法则。

所以要加一维：

### **`f[i][j]` = 传了 i 次球后，球在 j 号同学手里的方案数。**

### 第二步：转移（还是"从哪儿来"）

要让"传了 **i** 次后，球在 **j** 手里"，那**第 i 次传球之前**（即传了 i−1 次时），球在谁手里？

球只能从**相邻的人**传过来，所以上一刻球只可能在：

- **j 的左邻居** 手里，或
- **j 的右邻居** 手里。

两种来源**互斥**（球不可能同时从两边来），**加法原理**：

### **f[i][j] = f[i−1][左邻居] + f[i−1][右邻居]**

**初始条件**：`f[0][1] = 1` —— 一次都没传时，球在 1 号手里，这是**唯一**的初始状态。其余 `f[0][j] = 0`。

**最终答案**：`f[m][1]` —— 传了 m 次后，球回到 1 号手里。

## 三、代码讲解

### 难点：环形下标

这是本题**最容易翻车**的地方。同学们站成**圆圈**，所以：

- j 号的**左**邻居是 `j-1`，但当 **j = 1** 时，左邻居应该是 **n**（绕回去！）
- j 号的**右**邻居是 `j+1`，但当 **j = n** 时，右邻居应该是 **1**（绕回去！）

如果你直接写 `f[i-1][j-1] + f[i-1][j+1]`，那么 j=1 时会访问 `f[i-1][0]`（不存在），j=n 时会访问 `f[i-1][n+1]`（越界）——**答案必错**。

**写法一：老实特判（推荐）**

```cpp
int leftNb  = (j == 1) ? n : j - 1;     // 1 号的左边是 n 号
int rightNb = (j == n) ? 1 : j + 1;     // n 号的右边是 1 号

f[i][j] = f[i - 1][leftNb] + f[i - 1][rightNb];
```

**清晰、直观、不易错。** 初学者请用这个。

**写法二：取模（优雅，但要小心）**

```cpp
int leftNb  = (j - 2 + n) % n + 1;      // j-1 号，绕圈
int rightNb = j % n + 1;                // j+1 号，绕圈
```

**推导思路**：编号是 1..n，但取模天然适合 0..n−1。所以——

1. **先减 1**，把 1..n 映射到 0..n−1；
2. **在 0-based 世界里绕圈**（`+n` 是为了防止出现负数，比如 j=1 时 `1-1-1 = -1`）；
3. **再加 1**，映射回 1..n。

以左邻居为例：`j → (j-1) - 1 = j-2` → 防负数 `(j-2+n) % n` → 转回 `+1`。

验证 j=1：`(1-2+n) % n + 1 = (n-1) % n + 1 = n-1+1 = n` ✓ 正确绕到 n 号。

> **建议**：写法二很漂亮，但容易在 `+n`、`-1`、`+1` 上出错。**竞赛中，写法一（特判）更稳。** 除非你对取模映射非常熟练。

### 完整代码

```cpp
f[0][1] = 1;                        // 初始：球在 1 号手里

for (int i = 1; i <= m; i++)        // 传了 i 次
    for (int j = 1; j <= n; j++)    // 球在 j 号手里
    {
        int leftNb  = (j == 1) ? n : j - 1;
        int rightNb = (j == n) ? 1 : j + 1;

        f[i][j] = f[i - 1][leftNb] + f[i - 1][rightNb];
    }

cout << f[m][1] << "\n";
```

**复杂度**：O(n × m) = 30 × 30 = **900** 次，瞬间完成。

### 数据范围与类型

n, m ≤ 30。方案数最大是多少？每次传球有 2 种选择，30 次最多 2^30 ≈ **10 亿** —— 接近 int 上限。

题目保证答案在 `long long` 范围内，所以**用 `long long` 最保险**（不用取模）。

## 四、易错点

1. **环形下标算错** —— **本题头号杀手**。j=1 和 j=n 这两个边界必须绕圈。
2. **忘记初始化 `f[0][1] = 1`** —— 整个数组全是 0，答案输出 0。
3. **状态定义成一维** —— 信息不足，无法转移。
4. **把答案写成 `f[m][n]` 或其他** —— 答案是 `f[m][1]`（回到 1 号）。
5. **误以为"传 1 次能回到自己"** —— 不可能！自己不是自己的邻居。（测试数据里有 m=1 的，答案应为 **0**。）

## 五、小结

### 本章完整回顾

我们从最简单的一维递推，一路走到了二维环形递推：

| 题 | 状态 | 递推式 | 新学到的 |
|---|------|--------|---------|
| 1 爬楼梯 | `f[i]` | `f[i-1]+f[i-2]+f[i-3]` | **盯住最后一步**；取模；滚动数组 |
| 2 骨牌铺方格 | `f[i]` | `f[i-1]+f[i-2]` | **建模**比公式重要；n 小≠答案小 |
| 3 数字三角形 | `f[i][j]` | `a+max(f[i+1][j], f[i+1][j+1])` | 二维状态；**最优子结构**；换方向推 |
| 4 错位排列 | `D[i]` | `(i-1)(D[i-1]+D[i-2])` | **严格推导**；分类讨论；同构 |
| 5 出栈序列 | `f[i]` | `Σ f[k]·f[i-1-k]` | **卡特兰数**；加法/乘法原理 |
| 6 传球游戏 | `f[i][j]` | `f[i-1][左]+f[i-1][右]` | 二维状态；**环形下标** |

### 递推方法论（本章最重要的收获）

无论题目外表如何千变万化，方法**始终如一**：

> 1. **定义状态**：`f[...]` 表示什么？（必须包含决定未来的全部信息）
> 2. **找关键决策点**：最后一步？某个特殊元素的位置？
> 3. **按决策点分类**：确保**不重不漏**（这四个字是生命线）
> 4. **每类归约成子问题**，写出**转移方程**
> 5. **确定边界**（起点），并**用小数据验算**
> 6. 注意**溢出**和**取模**

### 递推与动态规划

**恭喜你——学完本章，你其实已经会写简单的动态规划了。**

**递推**和 **DP** 的界限本就模糊：

- 它们都基于**状态**和**转移**；
- 递推常用于**计数**（转移用 `+`）；
- DP 常用于**最优化**（转移用 `max`/`min`）——就像本章的「数字三角形」。

**真正的区别在于思维的自觉性**：DP 会明确地问"最优子结构成立吗？""无后效性满足吗？"

**下一章「递归算法」**，我们会换一个视角看同样的问题：递推是"**从小到大，自底向上**"地推；而递归是"**从大到小，自顶向下**"地拆。两者互为镜像——理解了这一点，你会对"分解问题"这件事有全新的领悟。
