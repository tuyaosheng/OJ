**定义状态（二维！）**

设 **`f[i][j]`** = 传了 **i 次**球之后，球在 **j 号**同学手里的方案数。

**推导转移：还是"最后一步"**

要让"传了 i 次后球在 j 手里"，那么**第 i 次传球之前**（也就是传了 i−1 次时），球在谁手里？

只可能在 **j 的左邻居**或 **j 的右邻居**手里——因为球只能从相邻的人那里传过来。

所以：

### **f[i][j] = f[i−1][ j的左邻居 ] + f[i−1][ j的右邻居 ]**

**初始条件**：`f[0][1] = 1`（一次都没传时，球在 1 号手里，这是唯一的初始状态）。其余 `f[0][j] = 0`。

**最终答案**：`f[m][1]`（传了 m 次后，球回到 1 号手里）。

**难点：环形下标怎么算？**

这是本题最容易出错的地方。同学们站成一个**圆圈**：

- j 号的**左**邻居是 j−1，但如果 j = 1，左邻居应该是 **n**（绕回去）。
- j 号的**右**邻居是 j+1，但如果 j = n，右邻居应该是 **1**（绕回去）。

**两种写法**：

**写法一：老实特判**
```cpp
int left  = (j == 1) ? n : j - 1;
int right = (j == n) ? 1 : j + 1;
```

**写法二：取模（更优雅，但要小心）**

如果编号从 1 到 n，直接取模会有点别扭（因为 `n % n = 0`，但我们要的是 n）。一个常用技巧：

```cpp
int left  = (j - 2 + n) % n + 1;    // j-1 号，绕圈
int right = j % n + 1;              // j+1 号，绕圈
```

（推导：先把 1..n 转成 0..n−1，取模绕圈，再转回 1..n。加 `+ n` 是为了防止出现负数。）

**建议初学者用写法一**，清晰不易错。

**复杂度**：O(n × m)，30 × 30 = 900，瞬间完成。

**易错点**：
- `f[0][1] = 1` 别写成 `f[0][0] = 1` 或忘了初始化。
- 环形下标算错（尤其是 j=1 和 j=n 这两个边界）。
- **注意**：当 n = 3 时，一个人的左邻居和右邻居**是不同的两个人**（没问题）；但要留意 n 很小时的绕圈是否正确。
