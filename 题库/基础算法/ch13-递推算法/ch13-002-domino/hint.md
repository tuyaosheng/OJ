**建模：盯住"最右边"怎么铺**

设 `f[i]` = 铺满 2 × i 的棋盘的方案数。考虑**最右边的那一列（或两列）**是怎么被覆盖的：

**情况一：最右边竖着放 1 块骨牌**（占满第 i 列的上下两格）

那么剩下的就是一个 2 × (i−1) 的棋盘 → 有 `f[i-1]` 种铺法。

```
┌─┬─┬─╥─┐
│ 剩下  ║ │   ← 最后一列竖放一块
│ 2×(i-1)║ │
└─┴─┴─╨─┘
```

**情况二：最右边横着放 2 块骨牌**（上下各一块，各占第 i−1、i 两列）

注意：横着放**必须成对**！如果只在上面横放一块，下面那格就会空出来，而它只能由另一块横放的骨牌填充。所以这两块骨牌**捆绑出现**，一起占据了 2 × 2 的区域。

那么剩下的是 2 × (i−2) 的棋盘 → 有 `f[i-2]` 种铺法。

```
┌─┬─┬═══┐
│ 剩下 │═══│   ← 最后两列横放两块
│2×(i-2)═══│
└─┴─┴═══┘
```

这两种情况**不重不漏**，所以：

### **f[i] = f[i−1] + f[i−2]**

**又是斐波那契！** 一个铺骨牌的问题，和爬楼梯的递推式**一模一样**。数学之美就在于此。

**边界**：
- `f[1] = 1`（2 × 1 的棋盘，只能竖放一块）
- `f[2] = 2`（2 × 2 的棋盘：两块竖放，或两块横放）

验算 `f[3] = f[2] + f[1] = 2 + 1 = 3` ✓ 和题目给的样例一致。

**注意数据范围**：n = 50 时，`f[50]` 约为 **2 × 10^10**，**超过 int（21 亿）**！必须用 `long long`。

**复杂度**：O(n)，n ≤ 50，瞬间完成。
