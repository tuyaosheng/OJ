# 讲解稿：骨牌铺方格（ch13-002）

## 一、题目解读

用 **1 × 2** 的骨牌，把 **2 × n** 的棋盘**完全铺满**，骨牌可横放可竖放，问有多少种铺法？

n = 3 时答案是 3。

**这题和爬楼梯，看起来八竿子打不着。** 一个是走台阶，一个是铺砖头。但请拭目以待——它们的递推式**完全相同**。

## 二、思路分析

### 老规矩：盯住"最后一步"

爬楼梯里，"最后一步"是最后一次迈腿。这里的"最后一步"是什么？

> **最右边那一列（或两列），是怎么被盖住的？**

我们只需要盯住**最右边**，把所有可能的情况列全。

### 情况一：最右边竖放一块

一块 1×2 的骨牌**竖着**放，正好占满第 n 列的**上下两格**：

```
┌──────┬─╥─┐
│      │ ║ │
│ 2×(n-1)  ║ │    ← 最后一列，竖放一块
│      │ ║ │
└──────┴─╨─┘
```

剩下的部分是一个 **2 × (n−1)** 的棋盘 → 铺法有 **f[n−1]** 种。

### 情况二：最右边横放两块

一块骨牌**横着**放，它占据第 n−1 和第 n 列的**某一行**。

**关键推理**：假设我们在**上面一行**横放了一块骨牌（占据 (1, n−1) 和 (1, n)）。那么**下面一行**的 (2, n) 这一格怎么办？

- 它不能竖放（上面的格子 (1, n) 已经被占了）；
- 它只能**横放**，占据 (2, n−1) 和 (2, n)。

**所以横放的骨牌必须成对出现！** 它们捆绑在一起，占满了右边 **2 × 2** 的方块：

```
┌──────┬═════┐
│      │ ═══ │    ← 上面横放一块
│ 2×(n-2)  │     │
│      │ ═══ │    ← 下面必须也横放一块
└──────┴═════┘
```

剩下的是 **2 × (n−2)** 的棋盘 → 铺法有 **f[n−2]** 种。

### 不重不漏吗？

- **不漏**：最右边那一列的**右上角格子** (1, n)，要么被竖放的骨牌盖住（情况一），要么被横放的骨牌盖住（情况二）。**没有第三种可能。**
- **不重**：这两种情况下，(1, n) 被覆盖的方式**不同**，所以铺法必然不同，不会重复计数。

✓ 完美。于是：

### **f[n] = f[n−1] + f[n−2]**

**又是斐波那契！**

### 边界与验算

- `f[1] = 1`：2×1 的棋盘，只能竖放一块。
- `f[2] = 2`：2×2 的棋盘 —— 两块都竖放，或两块都横放。

验算：`f[3] = f[2] + f[1] = 2 + 1 = 3` ✓ 与题目样例一致。

`f[4] = f[3] + f[2] = 3 + 2 = 5`。（可以手动画一画验证。）

## 三、代码讲解

代码极其简单：

```cpp
long long f[55];        // 【必须 long long】

f[1] = 1;
f[2] = 2;

for (int i = 3; i <= n; i++)
    f[i] = f[i - 1] + f[i - 2];

cout << f[n] << "\n";
```

### 唯一的坑：数据范围

n ≤ 50，看起来小得可爱，但——

`f[50]` ≈ **2 × 10^10**

而 `int` 的上限是 **2.147 × 10^9**。**差了整整一个数量级！**

用 `int` 会溢出成一个奇怪的负数。**必须用 `long long`。**

> **这是本题唯一的、也是致命的陷阱。** 它给我们一个重要教训：
>
> **"n 很小"** ≠ **"答案很小"**。像斐波那契这种指数增长的数列，n 才 50，答案就已经上百亿了。
>
> **拿到题的第一件事，永远是估算答案的量级。**

（测试数据里专门放了 n = 50 这组，用 int 必挂。）

## 四、易错点

1. **用 `int` 存答案** —— f[50] ≈ 2×10^10，溢出。**头号杀手。**
2. **边界写错** —— `f[2] = 2` 别写成 1（2×2 的棋盘有横竖两种铺法）。
3. **以为横放可以只放一块** —— 那样会留下无法填充的空格。**横放必须成对。** 这是建模时最容易想漏的地方。
4. **忘记特判 n = 1** —— 循环从 3 开始，n=1 时 f[1] 已赋值，其实没问题；但若边界只赋了 f[2]，就会出错。

## 五、小结

### 本题的真正价值：**建模**

递推式 `f[n] = f[n-1] + f[n-2]` 和爬楼梯**一字不差**。但**你不可能靠"背下斐波那契"来做出这道题**——因为你得先想明白：

- 为什么盯住"最右边一列"？
- 为什么横放必须成对？
- 为什么剩下的正好是 2×(n−1) 和 2×(n−2)？

**这些都是建模，是递推真正困难的部分。** 一旦模型建对了，写代码只要 5 行。

> ### 递推的两个层次
> 1. **写代码**（简单）：把递推式翻译成循环。
> 2. **建模型**（困难）：从一个具体问题中，找出状态和转移关系。
>
> **90% 的功夫在第 2 层。**

### 斐波那契的"无数张面孔"

爬楼梯、铺骨牌、兔子繁殖、蜜蜂爬房、上台阶……它们外表迥异，骨子里都是斐波那契。

**为什么？** 因为它们都具有同一种结构：

> **最后一步有两种选择，一种让问题缩小 1，另一种让问题缩小 2。**

当你在新题里嗅出这个结构，就能立刻反应过来——"哦，这是斐波那契"。**这种模式识别能力，是靠一道道题喂出来的。**
