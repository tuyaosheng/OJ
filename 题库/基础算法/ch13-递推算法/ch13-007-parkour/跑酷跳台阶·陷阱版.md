# 跑酷跳台阶·陷阱版——讲解稿

## 一、题目解读

爬楼梯的"带障碍"变式：某些台阶不能落脚，问到顶方案数（取模）。跑酷游戏里的"毒刺平台"就是这个模型。它和例1 只差一件事：**部分状态被强制清零**。

## 二、思路分析

递推三要素重新过一遍：

1. **状态**：f[i] = 恰好落在第 i 级的方案数；
2. **转移**：最后一步要么从 i−1 跳上来、要么从 i−2 跳上来 → f[i] = f[i−1] + f[i−2]；
3. **边界**：f[0] = 1（站在地面，"空方案"算一种）。

陷阱怎么办？**落不了脚 = 这个状态不存在 = f[i] = 0**。注意"不能踩"不等于"不能跨过"：从 i−1 跳两级到 i+1 完全合法，这在递推里自动成立——陷阱只影响自己的 f 值，不影响转移公式本身。

## 三、代码讲解

```cpp
f[0] = 1;
for (int i = 1; i <= n; i++) {
    if (trap[i]) { f[i] = 0; continue; }
    f[i] = f[i-1];
    if (i >= 2) f[i] = (f[i] + f[i-2]) % MOD;
}
```

- trap 用 bool 数组标记（第 5 章"下标即信息"）；
- i=1 时没有 i−2，用 `if (i >= 2)` 挡住，比特判 f[-1] 干净；
- **每次加法后立刻取模**：两个 MOD−1 级别的数相加约 2×10^9，恰好爆 int——f 用 long long + 步步取模双保险。

## 四、易错点

1. 陷阱台阶忘了 `continue`，清零后又被覆盖；
2. 只在最后输出时取模 → 中途溢出，大数据错；
3. f[0] 设成 0 → 全盘皆 0；
4. 第 n 级是陷阱的用例（答案 0）没考虑——本题测试点专门有它；
5. k=0 时第二行为空，`cin` 循环读 0 次自然没问题，别画蛇添足去 getline。

## 五、小结

"递推 + 障碍清零"是路径计数题的常用组合，二维版就是"过河卒"（马拦路的网格计数）。取模递推的纪律——步步取模——从这题养成。
