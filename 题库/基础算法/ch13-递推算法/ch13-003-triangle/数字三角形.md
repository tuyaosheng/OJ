# 讲解稿：数字三角形（ch13-003）

## 一、题目解读

一个数字三角形，从顶走到底，每步只能走到**下一行相邻的两格**之一（正下方 or 右下方），求路径上数字之和的**最大值**。

```
    7
   3 8
  8 1 0
 2 7 4 4
4 5 2 6 5
```
最佳路径 `7→3→8→7→5`，和为 **30**。

**这道题地位特殊**：它是从**递推**通往**动态规划**的正式入口。几乎所有 DP 教材，都会用它当第一课。

## 二、思路分析

### 为什么不能暴力枚举？

从顶到底，每步 2 种选择，走 n−1 步 → **2^(n−1)** 条路径。

n = 1000 时是 **2^999** —— 这个数比宇宙中的原子总数还多得多。**枚举到宇宙末日也算不完。**

必须递推。

### 关键：定义状态

这是 DP 的第一步，也是最重要的一步。

> **`f[i][j]` = 从顶部走到格子 (i, j)，路径和的最大值。**

（注意"最大值"三个字。状态存的不是"某一条路径"，而是**所有到达这里的路径中，最好的那个结果**。）

### 转移：想想"我是从哪儿来的"

要站到格子 (i, j) 上，上一步只可能来自两个地方：

- **正上方** (i−1, j)
- **左上方** (i−1, j−1)

（题目说"走到下一行相邻的左边或右边"，反过来看，能走到 (i,j) 的就这两个格子。）

我们要的是**最大**和，所以从这两个来源里挑**更大**的那个，再加上当前格子的值：

### **f[i][j] = max( f[i−1][j], f[i−1][j−1] ) + a[i][j]**

### 为什么这样是对的？——最优子结构

这里藏着 DP 最核心的思想，值得讲透：

> **"到达 (i,j) 的最优路径"，其前半段（到达 (i-1,j) 或 (i-1,j-1) 的部分）也必定是到达那个格子的最优路径。**

为什么？**反证法**：假如到 (i−1, j) 还有一条更好的路，那我把它接上去，就得到一条到 (i, j) 的更好的路——矛盾。

所以我们**不需要记住路径本身**，只需要记住每个格子的**最优值**。这个性质叫**最优子结构**，是所有 DP 问题的基石。

## 三、代码讲解

### 换个方向：从下往上推（更简洁！）

上面的推导是"从上往下"，但它有个麻烦：**边界**。

- 每行最左边（j=1）：没有"左上方"；
- 每行最右边（j=i）：没有"正上方"。

要处理这些特判，代码会很啰嗦。而且如果数字有**负数**，把 `f` 初始化成 0 还会出错（0 会被误认为比负数更优）。

**换个方向就清爽了：从下往上推。**

> **`f[i][j]` = 从格子 (i,j) 出发，走到【底部】的最大路径和。**

站在 (i, j)，下一步只能走 (i+1, j) 或 (i+1, j+1)。这两个格子**必定存在**（因为下一行总是比这一行多一格）——**没有边界问题！**

### **f[i][j] = a[i][j] + max( f[i+1][j], f[i+1][j+1] )**

- **起点（边界）**：最后一行，哪儿也去不了 → `f[n][j] = a[n][j]`
- **答案**：`f[1][1]`（从顶点出发走到底的最大和）

```cpp
// 边界：最后一行
for (int j = 1; j <= n; j++)
    f[n][j] = a[n][j];

// 从倒数第二行往上推
for (int i = n - 1; i >= 1; i--)
    for (int j = 1; j <= i; j++)
        f[i][j] = a[i][j] + max(f[i + 1][j], f[i + 1][j + 1]);

cout << f[1][1] << "\n";
```

**干净利落，一个特判都不需要。** 而且负数也完全不影响——因为参与 `max` 的两个值都是**已经算好的真实值**，不存在"未初始化的 0"来捣乱。

> **这个"换个方向"的技巧非常值得学。** 很多 DP 题正着推很麻烦，倒着推却豁然开朗。**遇到边界处理很恶心的时候，先想想能不能反过来推。**

**复杂度**：O(n²)。n = 1000 时约 50 万个格子，二十几毫秒。

## 四、易错点

1. **想暴力枚举所有路径** —— 2^999，天方夜谭。
2. **把 f 初始化成 0（在从上往下的写法里）** —— 数字可能是**负数**，0 会被误认为更优。（测试数据里专门有**全负数**的一组。）
3. **边界没处理**（从上往下写法）—— 最左/最右列访问到了不存在的格子。
4. **数组开小** —— n=1000 要开 1005×1005。
5. **忘了答案不一定在最后一行的正中间** —— 从上往下推时，答案是 `f[n][1..n]` 的**最大值**，不是 `f[n][1]`。（从下往上推就没这个问题，答案固定是 `f[1][1]`。）

## 五、小结

### 从"递推"到"动态规划"

这道题里，我们第一次用上了完整的 DP 三要素：

| 要素 | 本题 |
|------|------|
| **状态定义** | `f[i][j]` = 从 (i,j) 走到底的最大和 |
| **转移方程** | `f[i][j] = a[i][j] + max(f[i+1][j], f[i+1][j+1])` |
| **边界条件** | `f[n][j] = a[n][j]` |

**递推和 DP 是什么关系？**

> **DP = 递推 + "最优化"的味道。**
>
> 前两题的递推在**数方案数**（`+` 号连接）；这题的递推在**求最优值**（`max` 连接）。
> 骨架完全一样，只是把 `+` 换成了 `max`。

**你已经在做动态规划了**，只是还没被正式介绍这个名词而已。

### 两个可以带走的技巧

1. **"从哪儿来"的思考方式**：站在一个状态上，反问"上一步可能是从哪些状态过来的"，把它们的最优值取 max/min/sum。
2. **"换个方向推"**：正着推边界恶心时，试试倒着推。

**下一题**「错位排列」会给你一个下马威——**那个递推式，你几乎不可能猜出来，只能老老实实推导。** 这正是检验你是否真正掌握了递推思维的试金石。
