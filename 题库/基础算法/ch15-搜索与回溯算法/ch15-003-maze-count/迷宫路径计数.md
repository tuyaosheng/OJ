# 讲解稿：迷宫路径计数（ch15-003）

## 一、题目解读

n×m 的迷宫，`0` 是空地、`1` 是障碍。从起点走到终点，每步只能上下左右移动一格，**同一个格子不能重复经过**。问共有多少条不同的路径？

**这是网格搜索的第一课**，也是理解**回溯**最重要的一道题。

**为什么"不能重复经过"？** 如果允许重复，你可以在两个格子之间无限来回横跳，路径就有**无穷多条**了，题目也就没意义了。

## 二、思路分析

### DFS 走迷宫：像人一样探路

想象你站在迷宫里，手里拿着粉笔：

1. 看看四周（上下左右），哪些方向能走？（不出界、不是墙、**没走过**）
2. 挑一个方向走过去，**在新格子上画个叉**（表示"这条路上我踩过这里"）。
3. 继续探索……
4. 如果走到**终点** → 路径数 +1，**返回**。
5. 如果**四个方向都走不通**（死胡同）→ **退回来**。
6. **退回来时，把刚才画的叉擦掉！**（关键！）
7. 换一个方向，重复。

**这就是 DFS + 回溯。**

### 方向数组：网格搜索的标准写法

不要写四个 `if`，用**方向数组**：

```cpp
int dx[4] = {-1, 1, 0, 0};      // 上、下、左、右
int dy[4] = { 0, 0,-1, 1};

for (int d = 0; d < 4; d++)
{
    int nx = x + dx[d];         // 新位置
    int ny = y + dy[d];
    ...
}
```

| d | dx | dy | 方向 |
|---|-----|-----|------|
| 0 | −1 | 0 | 上（行号减 1）|
| 1 | +1 | 0 | 下 |
| 2 | 0 | −1 | 左（列号减 1）|
| 3 | 0 | +1 | 右 |

**优雅、简洁、不易错。** 以后所有网格题都这么写。

### 三道"能不能走"的检查

```cpp
if (nx < 1 || nx > n || ny < 1 || ny > m) continue;  // ① 出界了
if (g[nx][ny] == 1) continue;                        // ② 是障碍
if (vis[nx][ny]) continue;                           // ③ 已在当前路径上
```

**顺序很重要**：**必须先检查出界，再访问 `g[nx][ny]`**！否则会**数组越界**（读到不该读的内存），可能出现诡异的错误。

## 三、代码讲解

### 全题的灵魂：撤销

```cpp
vis[nx][ny] = true;     // ① 做选择：踏上这个格子
dfs(nx, ny);            // ② 递归：继续探索
vis[nx][ny] = false;    // ③ ★撤销★ 退回来，擦掉标记
```

**第 ③ 行如果漏掉，答案会严重偏小**（往往只能找到 1 条路径）。

### 为什么？——想清楚 `vis` 到底在标记什么

**`vis[i][j]` 的语义是**：

> **"格子 (i,j) 是否在【我当前正在走的这条路径】上？"**

请注意，**不是**"这个格子曾经被走过"，而是"**它现在是否在我脚下这条路上**"。

**推演一遍**（2×2 空迷宫，从 (1,1) 走到 (2,2)）：

```
起点(1,1) ─→ (1,2) ─→ (2,2)  ✓ 第 1 条路径
```

走完这条路，我们要**退回起点**，尝试另一条路：

```
起点(1,1) ─→ (2,1) ─→ (2,2)  ✓ 第 2 条路径
```

**关键时刻**：从第一条路退回来时，`vis[1][2]` 和 `vis[2][2]` 还是 `true` 吗？

- **如果撤销了** → 它们变回 `false` → 第二条路可以正常走到 (2,2) ✓ **答案 = 2** ✓
- **如果没撤销** → `vis[2][2]` 仍是 `true` → 第二条路走到 (2,1) 后，发现 (2,2) "已被占用"，**走不过去** ✗ **答案 = 1** ✗

**看到了吗？没撤销就会丢失路径。**

> ### 粉笔的比喻（请记住它）
>
> 你在迷宫里探路，手拿粉笔：
>
> - **往前走**：在脚下画个叉——"这条路上，我已经踩过这里了，不能再踩（否则会绕圈）"。
> - **往回退**：**必须把叉擦掉**——因为你**已经离开**这个格子了，它**不再属于**你当前的路径。
>
> **如果不擦**：等你去走另一条岔路时，会看到满地的旧粉笔印，误以为"这些地方都走过了"，于是无路可走，**大量路径被错失**。
>
> ### **"进来画叉，出去擦掉。"**

### 其他细节

**别忘了标记起点**：

```cpp
vis[sx][sy] = true;     // 否则路径可能会绕回起点
dfs(sx, sy);
```

**起点 == 终点的情况**：答案是 **1**（原地不动算一条路径）。上面的代码天然处理了——一进 `dfs` 就发现 `x==tx && y==ty`，`ans++` 后返回。

**复杂度**：最坏是**指数级**的（6×6 的空迷宫，自避路径有 **1262816** 条！）。但 n,m ≤ 6，实测 143ms，能过。

> **这也说明了搜索的本质**：它是"暴力枚举"，复杂度往往是指数级的。**所以搜索题的数据范围通常很小**（本题 n,m ≤ 6）。看到很小的数据范围，就该想到"**可能要爆搜**"。

## 四、易错点

1. **漏掉 `vis[nx][ny] = false`（撤销）** —— **头号杀手**。答案严重偏小。
2. **撤销位置放错** —— 必须在 `dfs()` **之后**（回来时撤销），不能在之前。
3. **先访问 `g[nx][ny]` 再判断出界** —— 数组越界！**必须先判边界。**
4. **忘记标记起点** —— 路径可能绕回起点，产生错误的"路径"。
5. **到达终点后没有 `return`** —— 会继续从终点往外走，逻辑错误（虽然本题因为 vis 的存在不至于死循环，但会数出错误的路径）。

## 五、小结

### 回溯的核心

```
① 做选择（打标记）
② 递归（深入探索）
③ 撤销选择（擦标记）   ← 生命线！
```

**这个三步曲，你在第 14 章的全排列里已经见过。本题只是把它搬到了网格上。**

**框架是一样的**，变的只是：
- 全排列的"选择"是"在这个位置填哪个数字"；
- 迷宫的"选择"是"往哪个方向走"。

### 什么时候需要撤销？（重要预告）

`vis` 的语义决定了一切：

> **`vis` = "在【当前路径】上"** → 离开就不在了 → **必须撤销**

**本题、全排列、八皇后，都属于这一类。**

**但是**——**下一题「细胞个数」会给你一个完全相反的例子**：那里的 `vis` 语义是"**曾经被访问过**"，是一个**永久的结论**，**绝对不能撤销**！

**不要死记"回溯就要撤销"。要理解：你的标记，到底在标记什么？**
