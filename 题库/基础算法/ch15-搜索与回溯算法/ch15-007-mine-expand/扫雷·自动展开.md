# 扫雷·自动展开——讲解稿

## 一、题目解读

扫雷"点一下翻一片"的实现原理。它是**洪水填充**（例3 细胞个数）的变式：普通洪水填充淹到障碍就停；这里多了一层规则——**数字格会被翻开、但不再向外传播**，就像洪水漫到堤坝：堤坝会被打湿，但水不会越过去。

## 二、思路分析

把格子分三类：

- 雷：永不翻开；
- 数字格（周围雷数 > 0）：可被翻开，是扩展的**终点**；
- 0 格：翻开后继续向 8 个方向扩展，是扩展的**通道**。

从点击格出发 DFS：翻开自己 → 若是 0 格就向 8 方向递归。第 5 章的"数雷"函数在这里复用（也可以先预处理整张数字表）。

**灵魂问题再问一遍：vis 撤销吗？** vis = "已被翻开"，是永久事实——**绝不撤销**。如果撤销，同一格会被反复翻开、反复计数，甚至死循环。这和例2（迷宫计数，vis="在当前路径上"，必须撤销）正好是一对反例——判断标准永远是**你给 vis 赋的语义**。

## 三、代码讲解

- 方向数组 8 向版（第 5 章埋的种子在这里发芽）；
- dfs 开头三连判：越界、雷、已翻开——顺序注意先判越界再访问数组；
- `if (mines(x,y) > 0) return;` 就是"数字格封边"，放在计数**之后**、扩展**之前**——数字格要算进答案；
- 点击格本身是数字格 → 第一层递归翻开它就 return，答案 1，特判自动被覆盖；
- 最坏情况全图都是 0 格：100×100 = 10^4 次递归，安全。

## 四、易错点

1. 数字格的 return 放在 `cnt++` 之前 → 数字格没被计入，答案偏小；
2. vis 手贱撤销 → 死循环/重复计数（本章的灵魂考点，错这个要面壁）；
3. 输入坐标是 1 下标，程序内 0 下标，转换漏了差一格；
4. 4 方向和 8 方向搞混——扫雷是 8 方向；
5. 忘判越界或判在数组访问之后。

## 五、小结

洪水填充 + "边界格计入但不扩展"，这个模式在"填涂颜色""岛屿边界"等题里反复出现。至此扫雷三部曲集齐：数雷（第 5 章）→ 自动展开（本题）→ 你可以试着写一个完整的扫雷小游戏了。
