# 讲解稿：选数（ch15-002）

## 一、题目解读

从 n 个整数中**任选 k 个**相加，统计有多少种选法使得**和为素数**。

例：n=4, k=3，数字是 `3 7 12 19`。四种选法的和分别是 22、29、38、34，其中只有 **29 是素数** → 答案 **1**。

**这题 = 上一题的组合枚举 + 素数判定。** 是搜索算法最典型的应用形态：

> ### **搜索 = 枚举所有可能 + 对每一种可能做判断**

## 二、思路分析

### 第一部分：枚举组合

和上一题**完全一样**——用 `start` 参数强制**下标递增**，保证每个数只选一次、不重不漏。

**但有个小改进**：本题只要**统计个数**，不需要输出组合本身。所以我们可以**在递归时顺便把和累加起来**：

```cpp
// pos   = 已经选了几个数
// start = 这一层最小从哪个【下标】开始选
// sum   = 当前已选数字之和   ← ★ 用参数携带！
void dfs(int pos, int start, int sum)
{
    if (pos == k)                   // 选够 k 个了
    {
        if (isPrime(sum)) ans++;    // 直接判断，无需回头累加
        return;
    }

    for (int i = start; i < n; i++)
        dfs(pos + 1, i + 1, sum + x[i]);    // 把 sum + x[i] 传下去
}
```

**注意 `sum` 是作为【参数】传递的**，不是全局变量。好处：

- **不需要撤销**（每层有自己的 `sum` 副本，递归返回时自动恢复）；
- 走到底时 `sum` 已经是完整的和，**直接判断即可**，不用回头再遍历一遍 `path[]` 累加。

**代码更短，也更不容易出错。** 这是"用参数携带状态"的又一次胜利。

### 第二部分：判断素数

**素数**（质数）的定义：**大于 1** 的自然数中，除了 1 和它本身外**没有其他因子**的数。

```cpp
bool isPrime(int v)
{
    if (v < 2) return false;                    // ★ 0 和 1 都不是素数！

    for (int i = 2; (long long)i * i <= v; i++)  // 只需试除到 √v
        if (v % i == 0) return false;           // 找到因子，不是素数

    return true;
}
```

### 关键：为什么只需试除到 √v？

这是本题最值得学的一个数学优化。

**结论**：如果 v 在 `2 ~ √v` 的范围内**没有因子**，那它在 `√v ~ v` 的范围内也**不可能有因子**。

**证明（很简单）**：假设 v 有一个因子 `a > √v`。因子是成对出现的——既然 `a` 能整除 v，那么 `b = v / a` 也是 v 的因子。

而：

`a > √v`  ⟹  `b = v / a < v / √v = √v`

**所以 b 一定小于 √v！** 也就是说，**只要有一个大因子，就必然对应一个小因子。**

**逆否命题**：如果小范围（≤ √v）里一个因子都没有，那大范围里也一定没有。**试到 √v 就够了。** ∎

**效果**：复杂度从 **O(v)** 降到 **O(√v)**。

本题的和最大约 20 × 5×10^6 = **10^8**，`√(10^8) = 10^4` —— 从 1 亿次降到 1 万次，**快了一万倍**。

> **写法细节**：`(long long)i * i <= v` —— 转成 long long 防止 `i * i` 溢出。
> （也可以写成 `i <= v / i`，避免乘法。）

## 三、代码讲解

### 复杂度分析

- 组合数最多 C(20,10) = **184756**
- 每个组合做一次素数判定 O(√10^8) = **10^4**

粗看是 184756 × 10^4 ≈ 18 亿？**吓人吗？**

**别慌，实际远没这么多**：

1. 素数判定通常**很早就返回**了——大部分合数被 2、3、5 这些小因子一除就出局，根本跑不到 √v。
2. 只有真正的素数才会跑满 √v 次循环。

实测最慢 **93ms**，轻松通过。

> **教训**：复杂度的**上界估算**是必要的，但也别被"最坏情况"吓住——**很多算法的平均表现远好于最坏情况**。当然，如果上界估算显示必然超时（比如 10^12），那就得换算法了。

## 四、易错点

1. **`v < 2` 时没返回 false** —— **头号错误**。0 和 1 **都不是素数**！很多人只判了 `v == 1`，漏掉了 0（当所有数都很小时，和可能是 0 吗？本题 xi ≥ 1 所以不会，但养成好习惯）。
2. **试除写成 `i <= v`** —— 复杂度 O(v)，10^8 次，超时。**必须用 √v。**
3. **`i * i` 溢出** —— v 接近 10^8 时，i 到 10^4，`i*i = 10^8` 其实不溢出。但如果 v 更大（比如 10^18），`i*i` 就会爆 int。**养成转 long long 的习惯。**
4. **组合枚举写成排列** —— 忘了 `start` 参数，会把 `{3,7,19}` 和 `{19,7,3}` 数成两次。
5. **和用 int 会溢出吗？** 20 × 5×10^6 = 10^8 < 2.1×10^9 —— **int 够用** ✓（但用 long long 更保险）。

## 五、小结

### 搜索题的标准结构

> **搜索 = 枚举所有可能（DFS）+ 对每种可能做判断（check）**

本题完美体现了这个结构：

| 部分 | 本题 |
|------|------|
| **枚举** | DFS 枚举所有 C(n,k) 个组合 |
| **判断** | `isPrime(sum)` 判断和是否为素数 |

**很多搜索题都是这个套路**：把"所有可能"穷举出来，逐一检验。难点通常在于：

1. **怎么不重不漏地枚举**（本题：`start` 参数）；
2. **怎么快速判断**（本题：√v 优化的素数判定）；
3. **怎么剪枝**（下一题开始，这会成为重点）。

### 试除到 √n：一个必须掌握的经典优化

**因子成对出现**（`a × b = v`，一大一小，以 √v 为界）——这个观察，把素数判定从 O(v) 降到了 O(√v)。

**同样的思想还能用来**：
- **求一个数的所有因子**（只需枚举到 √v，另一半用 `v/i` 得到）
- **分解质因数**

**记住这个 √n，它在数论题里无处不在。**
