## 上课怎么开场

上一章全排列已经带过一次"选择→递归→撤销"，先别急着往下讲新东西，让学生把那三行骨架在黑板上默写一遍——写不出来就先停下来补，这一章接下来全部建立在这个骨架之上。

写完之后告诉学生："今天要做的事，就是把这三行骨架，从'排排队'这一件事，**推广成一门通用武功**。" 黑板上写一句话当作本章的总纲：

> 把"所有可能"组织成一棵树，沿着一条路走到黑（**深度优先**），走不通就退回上一个路口（**回溯**），换条路继续，直到整棵树都被走遍。

这门武功能打的题分三类，随口报一下，后面例题会一一对应：枚举方案（组合、选数、N 皇后）、在网格上走路径（迷宫）、数一块一块的区域（细胞个数，也叫"洪水填充"）。

## 组合的输出：从"排列"退化成"组合"，多一个 start 参数

先复习一下上一章的全排列：n=3 的话，`1 2 3` 和 `3 2 1` 是两种不同的排列，都要输出。今天这道题变了个说法——从 1~n 里选 r 个数，**不讲顺序**，`1 2` 和 `2 1` 只算一种。

如果学生偷懒直接照抄全排列的写法（用 `used[]` 标记，每层都从 1 扫到 n），会出什么问题？让学生自己想一下：n=3,r=2 会把 `1 2` 和 `2 1` 都输出出来，多了一倍。**组合天然要求"不重不漏"，用排列的写法做不到。**

解决办法是给递归多带一个参数 `start`，**规定这一层只能从 start 开始往后选**，选过的数不可能再被更早的位置选一遍：

```cpp
void dfs(int step, int start) {
    if (step == r + 1) { 输出当前组合; return; }
    for (int i = start; i <= n; i++) {
        a[step] = i;
        dfs(step + 1, i + 1);     // 下一层只能选比 i 更大的数
    }
}
```

拿 n=3, r=2 手动展开这棵树，跟着代码一步步走：

```
dfs(1,1)：i 从 1 到 3
├─ 选 1 → dfs(2,2)：i 从 2 到 3
│         ├─ 选 2 → dfs(3,3)：step==3==r+1，输出 "1 2"，回溯
│         └─ 选 3 → dfs(3,4)：step==3==r+1，输出 "1 3"，回溯
│         （回到上一层，把选的 1 放回去）
├─ 选 2 → dfs(2,3)：i 从 3 到 3
│         └─ 选 3 → dfs(3,4)：输出 "2 3"，回溯
│         （回到上一层，把选的 2 放回去）
└─ 选 3 → dfs(2,4)：i 从 4 到 3，循环一次都不执行，直接返回（这条路选不出第二个数了）
          （回到上一层，把选的 3 放回去）
```

三个组合 `1 2`、`1 3`、`2 3`，一个不多一个不少，跟 C(3,2)=3 对上。**排列问题用 `used[]` 判重，组合问题用 `start` 定序**——这一句话把两个模板的分野钉死。顺手带一句剪枝：如果剩下能选的数已经不够凑满 r 个（`n - i + 1 < r - step + 1`），提前 `return` 掉，没必要再往下试。

到这里切到 `回溯搜索演示.html` 第一个页签，n、r 就用默认的 3 和 2，点"下一步"一步步走，注意看每次"选择"节点变蓝、凑够 r 个时节点变绿并弹出组合、退回上一层时节点变暗——这跟黑板上刚画的树完全对应，只是换成了动画。想看更接近课本例题的规模，把 n 改成 5、r 改成 3，重新生成，能凑出 10 个组合。

## 网格 DFS 的公共基本功：方向数组

【例2】迷宫、【例3】细胞、【练2】单词方阵都要在格子图上走，统一用**方向数组**处理"上下左右"，不用写四个 if：

```cpp
int dx[] = {-1, 1, 0, 0};   // 上、下、左、右
int dy[] = {0, 0, -1, 1};
for (int d = 0; d < 4; d++) {
    int nx = x + dx[d], ny = y + dy[d];
    if (nx < 1 || nx > n || ny < 1 || ny > m) continue;   // 越界
    if (障碍 || vis[nx][ny]) continue;                     // 不可走
    ...
}
```

三道关卡——越界判断、障碍判断、访问标记——一个都不能省，八方向就把两个数组扩到 8 个（【练2】单词方阵要用）。这段代码本身没什么难的，真正决定生死的是下一段。

## 全章最重要的一课：vis 到底要不要撤销

**这是本章的灵魂问题，请务必花时间讲透，两道题连着讲、对着讲。**

先看【例2】迷宫路径计数：统计从起点到终点一共有多少条不同的路径。拿一个 2×2 的小地图举例，起点 (1,1)，终点 (2,2)，四个格子全是空地：

```
起 .
.  终
```

手动画出这棵搜索树（方向顺序按代码里的"上下左右"）：从 (1,1) 出发，往上越界跳过，往下走到 (2,1)；从 (2,1) 出发，往上是 (1,1)——**已经在当前路径上了，不能再走回去**，往下越界，往左越界，往右走到 (2,2)，到达终点，**第 1 条路径**：(1,1)→(2,1)→(2,2)。这条路走完之后要**退回** (2,1)，再退回 (1,1)，回到最初的十字路口，接着试"往右"这个方向：从 (1,1) 走到 (1,2)，再往下走到 (2,2)，到达终点，**第 2 条路径**：(1,1)→(1,2)→(2,2)。一共 2 条，跟 ch15-003 的样例答案对得上。

关键问题来了：为什么第一条路径走完之后，(2,1) 和 (1,1) 要"退回"（也就是把 `vis` 改回 `false`）？想一下如果不撤销会发生什么——试第二条路径时，程序想经过 (1,1) 去 (1,2)，可 (1,1) 从第一条路径开始就一直标记着"已访问"，程序会把它当成"走不通"直接跳过，**根本发现不了第二条路径，答案少算成 1**。这里 `vis` 标记的真实含义是：**"这个格子在我当前正在尝试的这条路径上"**。既然一条路走完就退回来了，这个格子当然就不在路径上了，**必须撤销**：

```cpp
vis[nx][ny] = true;     // 踏进去，标记为在路径上
dfs(nx, ny);
vis[nx][ny] = false;    // 撤销：退回来之后，这里已经不在路径上了
```

现在切到【例3】细胞个数，看一个截然不同的语义。规则：矩阵里 0 表示空白，非 0 表示细胞组织，上下左右相邻的非 0 格子算同一个细胞，问一共有多少个细胞。拿一个 2 行 3 列的小矩阵举例：

```
1 1 0
0 1 1
```

从 (1,1) 出发向外扩散：(1,1) 和 (1,2) 相邻，都标记成"属于当前这个细胞"；(1,2) 和 (2,2) 相邻，也标记进来；(2,2) 和 (2,3) 相邻，标记进来。四个格子——(1,1)(1,2)(2,2)(2,3)——全部连成一片，是**同一个细胞**，答案是 1。

这次问题反过来问：这四个格子的标记，**要不要在"探索完退出来"之后撤销掉？** 想一下如果撤销会发生什么——(1,1) 往 (1,2) 探索完、退回来之后如果把 (1,2) 的标记撤销了，那 (1,2) 会被当成"还没访问过"，等外层扫描再次扫到它的时候，会把它当成一个**全新的细胞**重新数一遍，同一个细胞被数成好几个，答案严重偏大；更严重的是，(1,2) 撤销后可能又被 (2,2) 反过来重新探索一遍，(1,1)↔(1,2)↔(2,2) 之间来回震荡，**递归根本停不下来，直接栈溢出**。这里 `vis` 标记的真实含义是：**"这个格子已经属于某个细胞了，这是一个永久事实"**。一个格子属于哪个细胞，退不退出探索都不会改变，所以**绝不能撤销**：

```cpp
vis[x][y] = true;     // 标记为已访问
for (四个方向)
    if (合法 && 非0 && !vis[nx][ny])
        dfs(nx, ny);
// 注意：这里没有 vis[x][y] = false，故意的——一旦标记就不再改变
```

到这里切到 `回溯搜索演示.html` 第二个页签，两个模式用的是同一套控件：先点"迷宫路径计数"演示一遍，盯着格子看——每退回一步，刚才走过的格子会**熄灭**，变回普通颜色；再点"细胞个数"演示一遍，同样是逐格点亮，但这次点亮的格子**再也不会熄灭**，直到动画结束还是绿的。两个动画放在一起对照着看，比听多少遍讲解都直观。

把这一课的结论钉成一句话，写在黑板最显眼的地方：

> **撤销与否，不取决于"模板"，取决于你给 `vis` 赋予的语义。**
> "在当前路径上" → 回溯时必须撤销；"曾经访问过 / 已经归类" → 永远不要撤销。
> 判断方法只有一句自问：**"退回上一层之后，这个标记还成立吗？"** 成立就别动它，不成立就撤销它。

## 洪水填充的标准姿势

【例3】细胞个数的完整做法是"扫描 + 引爆"两段式：外层双重循环按顺序扫过整张图，一旦碰到一个"非 0 且还没被标记过"的格子，说明发现了一个全新的细胞，计数器 `+1`，然后从这个格子出发做 DFS，把**整个连通块一次性标记完**，这样外层循环扫到这个连通块里的其他格子时，会因为已经被标记而直接跳过，不会被重复计数。这个套路叫**洪水填充（Flood Fill）**，以后遇到"数连通块"类型的题，基本都是这个固定写法，第 18 章讲 BFS 的时候还会再见到它的另一个版本。

## 剪枝：把"检查"变成"查表"（N 皇后）

【例4】N 皇后骨架跟全排列一模一样——逐行放皇后，每行选一列，唯一多出来的事是**冲突判定**：同一列不能有两个皇后，同一条对角线也不能有两个皇后。列冲突好办，开个 `col[]` 数组；对角线稍微绕一点，但有个漂亮的性质：**主对角线上"行 − 列"是常数**（要整体加 n 防止出现负下标），**副对角线上"行 + 列"是常数**。把这两条也各开一个布尔数组，放置前查一下三个数组，O(1) 就知道能不能放——**这就是剪枝的典型手法：把"现场检查"变成"提前查表"，越早发现这条路走不通，就越早回头，省下大量不会有结果的搜索**。

用数字说话：n=12 时暴力枚举全排列有 12! ≈ 4.8×10⁸ 种，直接超时；加上这三个数组剪枝之后，实际方案数只有 14200 个，轻松跑完。**剪枝不改变答案，只砍掉那些注定失败的分支**，这句话比任何公式都更能说明剪枝的价值。

## 学生最容易栽的坑

1. **撤销与否想反了**：数路径不撤销 → 答案偏小；数连通块乱撤销 → 死循环/重复计数。先在草稿纸上写下 `vis` 的中文含义，再动手写代码；
2. 方向数组 `dx`/`dy` 配对写错（一个是行偏移一个是列偏移，写反了整个方向体系就乱了）；
3. 越界判断没放在递归调用**之前**（或函数开头统一判），漏判就是数组越界；
4. 起点忘记标记，或者终点特判的顺序放错了位置；
5. 组合枚举忘传 `i + 1`，写成 `start + 1`——这是经典手误，会导致同一个数被重复选中；
6. N 皇后对角线下标出现负数：记得用 `x - y + n` 整体平移；
7. 全局计数器（比如细胞个数的 `ans`）多组数据之间忘记清零。
