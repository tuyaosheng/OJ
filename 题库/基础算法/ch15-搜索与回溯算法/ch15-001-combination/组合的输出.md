# 讲解稿：组合的输出（ch15-001）

## 一、题目解读

从 1~n 中任取 r 个数，输出所有**组合**。

**组合 vs 排列**——这是本题的全部关键：

| | 讲究顺序吗 | `1 2 3` 和 `3 2 1` |
|---|-----------|-------------------|
| **排列**（第 14 章） | **讲究** | 是**两个**不同的排列 |
| **组合**（本题） | **不讲究** | 是**同一个**组合，只输出一次 |

n=5, r=3 时有 C(5,3) = **10** 个组合。

## 二、思路分析

### 回顾：全排列是怎么做的？

第 14 章的全排列，用 `used[]` 数组标记哪些数被用过，每层从 1 到 n **全部尝试一遍**：

```cpp
for (int v = 1; v <= n; v++) {
    if (used[v]) continue;
    ...
}
```

于是 `1 2 3` 和 `3 2 1` **都会**被生成——因为排列讲顺序，它们本来就是两个答案。

### 但组合不讲顺序，怎么去重？

如果直接套用全排列的框架，`1 2 3`、`1 3 2`、`2 1 3`、`3 2 1`…… 这 6 个排列都会被输出，但它们其实是**同一个组合** `{1,2,3}`。**重复了 6 次！**

**解决办法**（和第 14 章「自然数拆分」完全相同的招数）：

> ### **强制递增：后选的数，必须【大于】先选的数。**

这样：
- `1 2 3` ✓ 合法（递增），会被生成；
- `3 2 1` ✗ 非法（2 < 3），**根本不会被生成**；
- `2 1 3` ✗ 非法，也不会被生成。

**每个组合，有且仅有一个合法的表示形式**（就是从小到大排的那个）→ **天然不重不漏！**

而且，它还**顺便满足了**"每个组合内从小到大排列"的输出要求。**一石二鸟。**

### 实现：一个 `start` 参数搞定

```cpp
// pos   = 当前要选第几个数（1 ~ r）
// start = 这一层最小能选的数
void dfs(int pos, int start)
{
    if (pos > r)                        // 选够 r 个了，输出
    {
        for (int i = 1; i <= r; i++)
            cout << path[i] << (i == r ? "\n" : " ");
        return;
    }

    for (int v = start; v <= n; v++)    // ★ 从 start 开始，保证比上一个大
    {
        path[pos] = v;
        dfs(pos + 1, v + 1);            // ★ 传 v+1：下一个必须【严格大于】v
    }
}
```

调用 `dfs(1, 1)`。

**注意**：整个代码里**没有 `used[]` 数组，也没有"撤销"**！`start` 参数一个顶俩。

## 三、代码讲解

### 关键：传 `v + 1` 还是 `v`？

这是一个字符之差、却决定问题性质的地方：

| 传递的值 | 含义 | 例子 |
|---------|------|------|
| **`v + 1`**（本题）| 下一个必须**严格大于** v → **每个数只能选一次** | `1 2 3` ✓，`1 1 2` ✗ |
| **`v`**（自然数拆分）| 下一个可以**等于** v → **允许重复选** | `1 1 3` ✓ |

**做题时务必想清楚：你的问题允许重复吗？**

### 为什么不需要撤销？

回顾第 14 章的经验法则：

> **状态用【参数】传递 → 不用撤销**（每层独立，返回时自动恢复）
> **状态用【全局变量】记录 → 必须撤销**（全局共享，会被污染）

本题的状态（`pos`、`start`）**全靠参数传递**，所以**不需要撤销**。

而 `path[]` 虽然是全局数组，但我们只使用它的**前 r 个元素**，且每次都会被新值覆盖——**无害**。

（对比全排列：那里用了全局的 `used[]`，就**必须**写 `used[v] = false`。）

### 为什么天然是字典序？

因为每层都 `for (v = start; v <= n; v++)` **从小到大**枚举。先走到的分支，字典序一定更小。

### 剪枝（进阶）

上面的代码有个小浪费：如果剩下的数**不够选了**，还在傻傻地往下递归。

比如 n=5, r=3，已经选了 `4`（还要再选 1 个），那么 v 只能是 5——但如果已经选了 `5`（还要再选 1 个），就**无解**了，白跑一趟。

**剪枝**：限制 v 的上界，保证"从 v 到 n 的数够填满剩余位置"：

```cpp
// 还需要选 (r - pos + 1) 个数，所以 v 最大只能到 n - (r - pos)
for (int v = start; v <= n - (r - pos); v++)
```

本题 n ≤ 20，不剪枝也能过。但**剪枝的思想**很重要——**下一题开始，它会成为生死攸关的东西。**

**复杂度**：O(C(n,r) × r)。n=20, r=10 时 C(20,10) = **184756** 个组合。

## 四、易错点

1. **套用全排列的 `used[]` 框架** —— 会输出大量重复组合（每个组合重复 r! 次）。
2. **传 `v` 而不是 `v + 1`** —— 会生成 `1 1 2` 这种重复选数的非法组合。
3. **忘记 `start` 参数** —— 同上，无法去重。
4. **边界写成 `pos == r`** —— 应该是 `pos > r`（选完第 r 个后 pos 变成 r+1）。
5. **画蛇添足地写撤销** —— 不算错，但说明没理解参数与全局变量的区别。

## 五、小结

### 排列 vs 组合：框架对比

| | 全排列（第 14 章） | 组合（本题）|
|---|-------------------|------------|
| **去重手段** | 不去重（顺序有意义）| **`start` 参数强制递增** |
| **状态载体** | 全局 `used[]` 数组 | **函数参数** |
| **需要撤销吗** | **必须** | **不需要** |
| **枚举范围** | 每层 1 ~ n 全试 | 每层 start ~ n |

**同一个 DFS 框架，改一个参数，就从"排列"变成了"组合"。** 体会这种"骨架不变、细节微调"的感觉——**这就是掌握框架的力量。**

### 「不重不漏」的万能套路

> **当问题"顺序无关"时（`{1,2,3}` 和 `{3,2,1}` 视为相同），就人为规定一个标准顺序（如递增），只生成"标准形式"的那一个。**

这个套路在**组合枚举、子集枚举、集合划分**中会反复出现。你已经在「自然数拆分」和本题里用了两次，请把它变成本能。
