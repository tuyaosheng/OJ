# 讲解稿：N 皇后（ch15-005）

## 一、题目解读

在 n×n 棋盘上放 n 个皇后，**任意两个皇后不能互相攻击**——即不能同**行**、同**列**、同**对角线**。求方案数。

n=4 → **2** 种；n=8 → **92** 种（经典的"八皇后问题"）；n=12 → **14200** 种。

**这是回溯算法最著名的问题**，没有之一。高斯当年也研究过它。

它完美展示了搜索的**两大支柱**：

1. **回溯**：试 → 递归 → 撤销
2. **剪枝**：发现此路不通，**立刻掉头**

## 二、思路分析

### 优化一：逐行摆放（把搜索空间砍到极小）

**最朴素的想法**：在 n² 个格子里选 n 个放皇后。方案数是 C(64, 8) ≈ **44 亿**（n=8 时）——**根本跑不完**。

**但注意**：题目要求 n 个皇后**不能同行**。而棋盘正好有 **n 行**，要放 **n 个**皇后……

> ### **每一行必然恰好有一个皇后！**（抽屉原理）

既然如此，我们干脆**规定**：

> **第 1 个皇后放第 1 行，第 2 个放第 2 行，…… 第 i 个放第 i 行。**

这样，"**不同行**"这个约束就被**自动满足**了。我们只需要为每一行**决定放在哪一列**。

**搜索空间**：从 C(n², n) 骤降为 **n^n**（每行 n 种选择）—— n=8 时是 8^8 ≈ 1600 万，**已经可以接受**。再加上剪枝，实际搜索量还会小得多。

> **这一步"建模优化"极其重要。** 它不是靠代码技巧，而是靠**观察题目性质**。**很多搜索题的关键，就在于找到这样一个"天然的顺序"。**

### 优化二：O(1) 判断冲突（对角线的数学性质）

现在的问题是：在第 `row` 行第 `col` 列放皇后，怎么快速判断它和前面的皇后冲不冲突？

**同列**：好办，用 `colUsed[col]` 标记。

**同对角线**？这里有个**漂亮的数学观察**：

> ### **主对角线（↘ 方向）上，`row − col` 是常数！**
> ### **副对角线（↙ 方向）上，`row + col` 是常数！**

**验证一下**：

主对角线上的格子 (1,1)、(2,2)、(3,3)：`row − col` 都是 **0** ✓
另一条主对角线 (2,1)、(3,2)、(4,3)：`row − col` 都是 **1** ✓

副对角线上的格子 (1,3)、(2,2)、(3,1)：`row + col` 都是 **4** ✓

**太妙了！** 于是我们只需两个标记数组：

```cpp
bool colUsed[15];       // 第 col 列是否被占
bool diag1[30];         // 主对角线，下标 = row - col + n   ★ 加 n 防止负数！
bool diag2[30];         // 副对角线，下标 = row + col
```

**判断冲突：O(1)！** 比逐个检查前面所有皇后（O(n)）快得多。

> **为什么 `diag1` 的下标要 `+ n`？**
>
> 因为 `row - col` 可能是**负数**（如 row=1, col=5 时是 −4），而**数组下标不能为负**。
> 加上 n 后，范围变成 `[1, 2n-1]`，全是正数 ✓

## 三、代码讲解

```cpp
void dfs(int row)
{
    if (row > n)            // n 行都放好了 → 找到一个解
    {
        ans++;
        return;
    }

    for (int col = 1; col <= n; col++)      // 在这一行，尝试每一列
    {
        // ★ 剪枝：这个位置会被攻击，直接跳过
        if (colUsed[col] || diag1[row - col + n] || diag2[row + col])
            continue;

        colUsed[col] = true;                // ① 做选择：放下皇后
        diag1[row - col + n] = true;
        diag2[row + col] = true;

        dfs(row + 1);                       // ② 递归：去放下一行

        colUsed[col] = false;               // ③ ★撤销★ 拿走皇后
        diag1[row - col + n] = false;
        diag2[row + col] = false;
    }
}
```

### 为什么必须撤销？

`colUsed` / `diag1` / `diag2` 的语义是：

> **"在【我当前正在摆的这个方案】里，这一列/对角线是否已被占用？"**

当我探索完"第 row 行放 col 列"的所有后续可能，要**退回来**尝试"第 row 行改放 col+1 列"时——

**刚才那个皇后已经被拿走了**，它占的列和对角线自然要**释放**，否则会误以为还被占着。

**这和迷宫路径计数是同一类**（`vis` = "在当前方案上"）→ **必须撤销** ✓

（对比细胞个数：那里 `vis` = "曾访问过" → **绝不撤销**。**再次强调：看语义，不要背模板。**）

### 剪枝：搜索的生命线

```cpp
if (colUsed[col] || diag1[...] || diag2[...])
    continue;               // ← 这就是剪枝
```

**这一行的意义**：一旦发现"这个位置会被攻击"，就**立刻放弃**，**绝不往下递归**。

**如果不剪枝**会怎样？那就是"先把 n 个皇后全摆完，最后再检查合不合法"——

- 不剪枝：要搜完整棵 n^n 的树（n=8 时 1600 万个叶子）
- **剪枝后**：大量分支在**很浅的层次**就被砍断了

**举例**：如果第 1 行放在第 1 列，那么第 2 行的第 1 列（同列）和第 2 列（同对角线）**立刻就被排除**了——这两棵**巨大的子树**根本不会被展开。

**效果**：n=12 时，剪枝后只需 **36ms**。

> ### **剪枝是搜索算法的生命线。**
>
> **搜索的本质是暴力枚举，复杂度往往是指数级的。而剪枝，就是在"暴力"里注入"智慧"——通过提前判断"此路不通"，砍掉大片无效的搜索空间。**
>
> **一个好的剪枝，能让原本不可能的搜索变得可行。**

## 四、易错点

1. **`diag1` 下标忘记 `+ n`** —— `row - col` 是负数，**数组越界**（往往是 RE 或诡异的错误答案）。**头号坑。**
2. **漏掉撤销** —— 只能找到很少的解。
3. **撤销时漏掉某一个数组** —— 三个数组（`colUsed`、`diag1`、`diag2`）**都要撤销**，漏一个就错。
4. **对角线公式搞反** —— 主对角线是 `row - col`，副对角线是 `row + col`。记混了答案就错。
5. **数组开小** —— `diag1`/`diag2` 的下标范围是 `[0, 2n]`，要开 `2n+1` 以上。

## 五、小结

### N 皇后的三大优化

| 优化 | 做法 | 效果 |
|------|------|------|
| **① 逐行摆放** | 规定第 i 个皇后放第 i 行 | "不同行"自动满足，搜索空间从 C(n²,n) 降到 n^n |
| **② 对角线的数学性质** | `row−col` / `row+col` 为常数 | 冲突判断从 O(n) 降到 **O(1)** |
| **③ 剪枝** | 发现冲突立刻 `continue` | 砍掉大片无效子树 |

**三管齐下，n=12（14200 个解）只需 36ms。**

### 搜索算法的两大支柱

到这里，我们可以总结出搜索的完整方法论：

> ### **搜索 = 回溯 + 剪枝**
>
> - **回溯**（试 → 递归 → **撤销**）：保证**不重不漏**地枚举所有可能。
> - **剪枝**（提前判断，砍掉无效分支）：保证**效率**能接受。
>
> **没有回溯，答案不对；没有剪枝，时间不够。**

### 关于"撤销"的最终总结（本章核心）

| `vis` 的语义 | 例子 | 撤销？|
|-------------|------|-------|
| **"在当前路径/方案上"** | 迷宫、全排列、**N 皇后** | **必须撤销** |
| **"曾经被访问过"** | **细胞个数**、连通块、图遍历 | **绝不撤销** |
