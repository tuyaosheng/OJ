**为什么不能用"开个桶数组计数"？**

你可能想：开个数组 `cnt[x]++` 不就行了？问题在于——**数值范围是 ±10^9**，你没法开一个 20 亿大小的数组（内存爆炸）。

（如果数值范围很小，比如都在 1~1000 之间，那么**桶计数**确实是最优解，O(n) 就搞定。这也是"桶排序"的思想。但本题范围太大，行不通。）

**排序 + 扫描的做法**

```cpp
sort(a, a + n);      // 排序后，相同的数一定挨在一起

int bestVal = a[0], bestCnt = 1;    // 记录答案
int curVal = a[0], curCnt = 1;      // 记录当前这一"块"

for (int i = 1; i < n; i++)
{
    if (a[i] == curVal)
        curCnt++;                   // 还在同一块里，计数 +1
    else
    {
        curVal = a[i];              // 换新数了，开启新的一块
        curCnt = 1;
    }

    if (curCnt > bestCnt)           // 注意是严格大于！
    {
        bestCnt = curCnt;
        bestVal = curVal;
    }
}
```

**为什么"严格大于"就能自动保证输出最小的数？**

这是本题最妙的一点。因为排序后是**从小到大**扫描的，较小的数一定**先**被处理。当后面遇到一个出现次数**相同**的数时，`curCnt > bestCnt` 不成立（相等不算大于），于是**不会更新答案**——答案就保留着那个先出现的、也就是**更小**的数。

**一行 `>` 而不是 `>=`，就自动满足了"取最小"的要求。** 如果写成 `>=`，就会被后面更大的数覆盖，答案错误。

**复杂度**：排序 O(n log n) + 扫描 O(n)，总体 O(n log n)。
