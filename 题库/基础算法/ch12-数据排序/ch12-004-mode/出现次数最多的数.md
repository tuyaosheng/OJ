# 讲解稿：出现次数最多的数（ch12-004）

## 一、题目解读

给 n 个整数（n ≤ 10 万，数值范围 ±10^9），找出**出现次数最多**的那个数（**众数**）。若有并列，输出**最小**的那个。

## 二、思路分析

### 第一反应：开个桶数一数？

学过数组的同学，第一反应大概是**桶计数**：

```cpp
cnt[a[i]]++;      // 用值当下标，直接计数
```

思路完全正确，而且是 **O(n)** 的，比排序还快！**但这题用不了。**

为什么？看数据范围：**数值的绝对值可达 10^9**。要用值当下标，你得开一个大小 **20 亿**的数组。按 int 计算就是 **8 GB 内存** —— 直接爆炸。

> **重要经验**：桶计数的适用条件是**数值范围小**（比如 1~1000）。范围一大，就必须换思路。
> （这也是"桶排序"的局限。它是 O(n) 的，但**只在值域小的时候可用**。）

### 换个思路：排序 + 扫描

这里就要请出排序最重要的性质之一：

> ### **排序会把相同的数聚到一起。**

原本 `3 1 4 1 5 1 4` 里的三个 1 散落各处，排序后变成 `1 1 1 3 4 4 5` —— 相同的数连成了一段一段的"**块**"：

```
1 1 1 | 3 | 4 4 | 5
└─3个─┘ └1┘ └2个┘ └1┘
```

**问题瞬间简化了**：只需从头扫一遍，数一数**每块有多长**，最长的那块对应的数就是答案。一个"计数"问题，被排序变成了简单的"**扫描**"。

## 三、代码讲解

```cpp
sort(a, a + n);      // 关键：相同的数聚到一起

int bestVal = a[0], bestCnt = 1;    // 目前最优答案
int curVal = a[0], curCnt = 1;      // 当前这一块

for (int i = 1; i < n; i++)
{
    if (a[i] == curVal)
        curCnt++;                   // 还在同一块里，块长 +1
    else
    {
        curVal = a[i];              // 遇到新数，开启新块
        curCnt = 1;
    }

    if (curCnt > bestCnt)           // 注意：严格大于！
    {
        bestCnt = curCnt;
        bestVal = curVal;
    }
}
```

用**两组变量**：`cur*` 追踪"当前这一块"，`best*` 保存"迄今最优"。扫描时不断比较、更新。

### 全题的精华：为什么 `>` 能自动保证"取最小"？

题目要求：**并列时输出最小的那个数**。你可能以为要写额外的判断逻辑。**其实不用——一个 `>` 就够了。**

这里的推理非常漂亮，请细品：

1. 排序后，数组是**从小到大**的，所以我们扫描时，**小的数一定先被处理**。
2. 假设数 A（较小）和数 B（较大）出现次数**相同**，都是最多的。
3. 扫描时**先**遇到 A，此时 `curCnt > bestCnt` 成立，`bestVal` 被设为 **A**。
4. **后**遇到 B 时，B 的次数和 A **相等**，于是 `curCnt > bestCnt` **不成立**（相等不算大于）！
5. 于是**答案不被更新**，`bestVal` 保持是 **A** —— 正是那个**更小**的数。✓

**如果把 `>` 写成 `>=` 呢？** 第 4 步就会成立，`bestVal` 被 B 覆盖，输出较大的数 —— **WA**。

> **一个符号之差，决定成败。** 这提醒我们：写比较条件时，一定要想清楚"相等"的情况该怎么办。
> （本题测试数据里专门放了 `2 2 3 3` 这组——`>=` 会输出 3，正确答案是 2。）

### 复杂度

排序 O(n log n) + 扫描 O(n) = **O(n log n)**。10 万数据，十几毫秒。

## 四、易错点

1. **想开桶数组** —— 值域 ±10^9，内存爆炸。**先看数据范围再选算法！**
2. **`>=` 写成 `>`（或反之）** —— 并列时输出了较大的数。**本题头号陷阱。**
3. **忘记初始化** —— `bestVal`/`curVal` 应初始化为 `a[0]`，`bestCnt`/`curCnt` 初始化为 `1`（第一个数本身就算一次）。若初始化成 0，n=1 时会出错。
4. **循环从 `i = 0` 开始** —— 会把 `a[0]` 重复计数一次。应从 **`i = 1`** 开始。
5. **忘记排序** —— 相同的数没聚到一起，块的逻辑完全失效。

## 五、小结

本题的核心是排序的第二大红利：

> **排序 → 相同元素相邻 → "统计"变成"扫描"。**

这个套路极其常用，比如：

- 统计每个数出现了几次（本题）
- **数组去重**（排序后，相邻元素相同就是重复的——配合 `unique` 函数）
- 判断是否有重复元素（排序后扫一遍看有没有相邻相等）

**和"桶计数"的对比，请记牢这张表**：

| 方法 | 复杂度 | 适用条件 |
|------|--------|---------|
| 桶计数 | **O(n)** | 值域**小**（能开下数组） |
| 排序+扫描 | O(n log n) | **任意值域** |

**桶计数更快，但排序更通用。** 拿到题先看数据范围，再决定用哪个——**这是算法竞赛的基本功。**
