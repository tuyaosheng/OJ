# 讲解稿：选择排序（ch12-001）

## 一、题目解读

给 n 个整数（n ≤ 2000），从小到大排好序输出。

题目明确要求：**先别用 `sort`，自己写一个排序**。

有同学会嘀咕："`sort` 一行就搞定，为什么要自找麻烦？"

因为**排序是算法的启蒙课**。亲手写一遍，你才能真正体会到：

- 一个"排好序"的过程，到底是怎么一步步发生的；
- 为什么朴素排序是 O(n²)，它慢在哪里；
- 有了这份切身体会，下一题看到快排的 O(n log n) 时，你才会由衷地感到"**这真快**"。

## 二、思路分析

### 选择排序的思想

它的名字已经把思路说尽了——**每一轮，从剩下的数里"选择"一个最小的**。

想象你手里有一把打乱的扑克牌，要把它们从小到大排好。最自然的做法是：

> 1. 扫一遍所有牌，找出**最小**的那张，放到第 1 个位置；
> 2. 再扫一遍**剩下的**牌，找出最小的，放到第 2 个位置；
> 3. 再扫剩下的……如此重复。

每做完一轮，就有**一个位置被永久确定下来**。做 n−1 轮，整个数组就排好了。

### 手动模拟一遍

以 `[3, 1, 4, 1, 5]` 为例：

| 轮次 i | 在 `[i, n)` 中找最小 | 交换 | 结果 |
|--------|---------------------|------|------|
| i=0 | 最小是 1（下标 1） | a[0] ↔ a[1] | `[1, 3, 4, 1, 5]` |
| i=1 | 剩下 `3 4 1 5`，最小是 1（下标 3） | a[1] ↔ a[3] | `[1, 1, 4, 3, 5]` |
| i=2 | 剩下 `4 3 5`，最小是 3（下标 3） | a[2] ↔ a[3] | `[1, 1, 3, 4, 5]` |
| i=3 | 剩下 `4 5`，最小是 4（下标 3） | 自己和自己换 | `[1, 1, 3, 4, 5]` |

排好了。注意加粗的规律：**每轮结束后，前 i+1 个位置就再也不会变了**。

## 三、代码讲解

```cpp
for (int i = 0; i < n - 1; i++)      // 依次确定第 i 个位置该放谁
{
    int minIdx = i;                  // 先假设 i 位置上的就是最小的

    for (int j = i + 1; j < n; j++)  // 到"还没排好的部分"找找有没有更小的
        if (a[j] < a[minIdx])
            minIdx = j;              // 记住更小者的【下标】

    swap(a[i], a[minIdx]);           // 把最小的换到 i 位置
}
```

三个细节值得琢磨：

**细节一：为什么记录的是下标 `minIdx`，而不是最小值本身？**

因为最后要**交换**。如果只记住"最小值是 1"，你并不知道这个 1 在数组的哪个位置，没法把它换过来。**记下标才能定位。** 这是初学者常犯的错。

**细节二：外层为什么只到 `n - 1`，而不是 `n`？**

因为当前 n−1 个位置都确定后，最后那个位置上**只剩一个数**了——它自然就是最大的，无需再排。多跑一轮不会出错，但是浪费。

**细节三：内层从 `i + 1` 开始**

因为 `[0, i)` 已经排好、锁定了，我们只需要在**还没排好的部分** `[i, n)` 里找最小值。内层从 `i+1` 起，就是把 `a[i]` 当作"擂主"，让后面的数来挑战它。

### 复杂度分析

外层跑 n−1 轮，第 i 轮内层要比较 n−1−i 次。总比较次数：

`(n-1) + (n-2) + … + 1 = n(n-1)/2 ≈ n²/2`

所以是 **O(n²)**。

- n = 2000（本题）：约 200 万次 —— **很快，几毫秒**。
- n = 100000（下一题）：约 **50 亿次** —— **必然超时！**

这就是朴素排序的天花板。**n 一旦上万，O(n²) 就走不通了。**

### 输出格式的小陷阱

题目要求"相邻两数用一个空格隔开"，行末**不要多余空格**。一个优雅的写法：

```cpp
for (int i = 0; i < n; i++)
    cout << a[i] << (i == n - 1 ? "\n" : " ");
```

最后一个数后面跟换行，其余跟空格。（其实大多数 OJ 会忽略行末空格，但养成规范的习惯总是好的。）

## 四、易错点

1. **内层循环记录了值而不是下标** —— 没法交换。
2. **内层从 `i` 开始而不是 `i+1`** —— 不算错（`a[i] < a[i]` 恒假），但多比一次，纯属浪费。
3. **忘记 `#include <algorithm>`** —— `swap` 用不了。
4. **每轮都从 0 开始找最小值** —— 那会把已经排好的部分又搅乱，逻辑错误。**必须从 `i` 开始。**
5. **输出多了行末空格** —— 有些严格的 OJ 会判 PE（格式错误）。

## 五、小结

选择排序的精髓，一句话：**每一轮选出剩余部分的最小值，放到当前位置。**

| | |
|---|---|
| **优点** | 思路直白、代码短、容易写对 |
| **缺点** | O(n²)，数据一大就废 |
| **适用** | n ≤ 几千的小规模数据 |

**它的价值在于教学**——让你亲眼看到"排序"这件事是怎么一步步完成的。

**顺带一提**，另外两个经典的 O(n²) 排序也值得你自己写一遍：

- **冒泡排序**：相邻两数比较，大的往后"冒泡"，每轮把最大的推到末尾。
- **插入排序**：像整理扑克牌，把每张新牌**插入**到前面已排好的部分中的正确位置。

三者复杂度相同，但思路各异。写完它们，你对"有序"这件事的理解会深刻很多。

**下一题**，我们把 n 提到 10 万。O(n²) 彻底失效，是时候请出真正的主角了——**快速排序**与 `sort`。你会看到 O(n log n) 是如何把 50 亿次操作压缩到 170 万次的。
