## 上课怎么开场

黑板上写 5 个数：`3 1 4 1 5`。问一句："谁最小？"——一眼就能看出来是 1。"那你是怎么看出来的？"多半答不上来，因为这是人脑并行扫描出来的，但计算机不会"一眼看出"，它只会**一个一个比**。

再问："如果我要你把这 5 个数从小到大排好，你脑子里的过程是什么？"多数人会说："先挑个最小的放前面，再从剩下的里挑最小的……" ——恭喜，这就是**选择排序**，你脑子里天生就有这个算法，只是没意识到。

排序这一章，为什么要单独用一整章来讲？因为**"先排序"是无数题目解题的第一步**：找众数要排序、二分查找要求数据有序、后面学的贪心几乎总是先排序再下手。排序把杂乱变成有序，有序带来一个关键性质——**单调性**，这正是二分、双指针这些高效技巧成立的前提。本章走两条线：先**亲手写**一个 O(n²) 的排序，搞懂原理；再见识 O(n log n) 的快排和 `sort`，应对大数据；最后看排序完之后能干什么——二分查找、统计、配对。

## 选择排序（例1）：手把手排 `3 1 4 1 5`

黑板上写数组，下标从 0 开始：`a = [3, 1, 4, 1, 5]`。选择排序的规则："第 1 轮从**全部**数里挑最小的，换到第 1 个位置；第 2 轮从**剩下**的数里挑最小的，换到第 2 个位置……"重复到最后。带着学生一轮一轮走：

**第 1 轮**（未排序区是整个数组，从下标 0 找起）：假设最小值下标是 `minIdx=0`（值 3）。拿 `a[1]=1` 比，`1<3`，`minIdx` 更新成 1；拿 `a[2]=4` 比，`4<1` 不成立，不变；拿 `a[3]=1` 比，`1<1` 不成立（相等不算更小），不变；拿 `a[4]=5` 比，不成立。这轮扫完 `minIdx=1`，把 `a[0]` 和 `a[1]` 交换：`[1, 3, 4, 1, 5]`。前 1 个数归位。

**第 2 轮**（未排序区从下标 1 开始）：`minIdx=1`（值 3）。`a[2]=4` 不小于 3；`a[3]=1` 小于 3，`minIdx=3`；`a[4]=5` 不小于 1。交换 `a[1]` 和 `a[3]`：`[1, 1, 4, 3, 5]`。前 2 个数归位。

**第 3 轮**：`minIdx=2`（值 4）。`a[3]=3` 小于 4，`minIdx=3`；`a[4]=5` 不小于 3。交换 `a[2]`、`a[3]`：`[1, 1, 3, 4, 5]`。前 3 个数归位。

**第 4 轮**：`minIdx=3`（值 4）。`a[4]=5` 不小于 4，`minIdx` 不变，等于自己，**不用交换**。前 4 个数归位，最后一个自然也对了。结果 `[1, 1, 3, 4, 5]`——排好了。

问学生一句容易忽略的："第 4 轮明明没发生交换，为什么代码里通常不写'如果没变就跳过'的特判？"——因为"自己和自己交换"什么都不会改变，写不写这个特判，结果都一样，只是省一次无意义的赋值，不是正确性问题。翻译成代码：

```cpp
for (int i = 0; i < n - 1; i++) {
    int minIdx = i;
    for (int j = i + 1; j < n; j++)
        if (a[j] < a[minIdx]) minIdx = j;   // 打擂台找最小值下标
    swap(a[i], a[minIdx]);                   // 一轮只交换一次
}
```

外层循环是"第几轮"，内层循环是"在未排序区里打擂台"——这是本章要建立的第一个心智模型：**一轮结束，前面就多一个数归位，未排序区缩小一格**。

选择排序是 O(n²)：n=1000 完全没问题，但 **n=10⁵ 就是 10¹⁰，必然超时**。这是本章第一道复杂度分水岭，也是下一题要解决的问题。

切到 `排序过程演示.html` 的"选择排序"页签，把数组换成 `3 1 4 1 5`，点"下一步"看每一轮的"打擂台"过程——当前比较的两个数会高亮，找到新的最小值下标会变色提示，一轮结束时看交换的两个格子怎么互换位置、前面的格子怎么变绿"归位"。

## 快速排序与 `sort`（例2）：分治初体验 + 实战铁律

数据规模一旦提到 `n≤10⁵`，O(n²) 就彻底失效了（`10⁵ × 10⁵` = 100 亿）。快速排序用**分治**的思想把复杂度降到平均 O(n log n)：选一个基准数 `pivot`，一趟扫描把数组分成"≤ pivot"和"> pivot"两半，再对两半分别递归排序——**每一层只需要扫一遍，层数是 log n，总量是 n log n**。

手写快排是为了理解分治长什么样；但**考场上 99% 的情况，直接用标准库的 `sort`**：

```cpp
#include <algorithm>
sort(a, a + n);                     // 默认从小到大
sort(a, a + n, greater<int>());     // 从大到小
sort(stu, stu + n, cmp);            // 自定义比较规则（结构体多关键字）
```

这里要立一条"实战铁律"：**手写快排是为了懂原理，考场上写代码是为了不出错——两件事都要会，但用在不同场合**。`sort` 底层正是快排的工程优化版本（加了三数取中、小区间转插入排序等防止最坏情况的手段），直接用它比自己手写更快也更不容易出 bug。

问一句容易被问倒的："快排最坏情况是什么，会退化成多差？"——如果每次选的 pivot 都恰好是当前区间的最大或最小值（比如数组本身已经有序，又固定取第一个数当 pivot），每次只能切掉 1 个数，退化成 O(n²)。标准库的 `sort` 用了多种手段规避这个最坏情况，这也是为什么"手写快排"和"用 sort"在工程上不是一回事。

## 二分查找（例3）：有序带来的加速

前提只有一个：**数组必须有序**。还是拿刚才排好的 `[1, 1, 3, 4, 5]` 举例，现在要回答三个问题：`1` 在不在里面、第一次出现在哪；`4` 呢；`2` 呢。

暴力做法是从头扫到尾，单次 O(n)。如果这样的问题问 `q` 次，`n、q` 都是 10 万，总量 100 亿，必然超时。**排序之后**，可以用二分：每次看区间正中间的数，跟目标比一比，**能直接排除掉一半**。10 万个数最多找 17 次（`2¹⁷≈13万`）就能锁定，这就是"有序"换来的加速。

黑板上手推 `x=1`，数组下标 0~4 存 `[1, 1, 3, 4, 5]`，`l=0, r=4`：

- `mid=(0+4)/2=2`，`a[2]=3`，比 1 大，往左缩，`r=mid-1=1`；
- `mid=(0+1)/2=0`，`a[0]=1`，等于目标！但**先别急着退出**——数组里有重复的 1，题目要的是**第一次出现的位置**，所以记下 `ans=0`，继续往左找有没有更靠前的 1：`r=mid-1=-1`；
- 这时候 `l=0 > r=-1`，循环结束，`ans=0`，转成"从 1 开始编号"就是位置 **1**。

再推 `x=4`：`l=0,r=4`，`mid=2`，`a[2]=3<4`，往右，`l=3`；`mid=(3+4)/2=3`，`a[3]=4`，等于目标，记 `ans=3`，继续往左找更靠前的 4：`r=2`；`l=3>r=2`，结束，`ans=3`，位置是 **4**。

再推 `x=2`（数组里根本没有 2）：`l=0,r=4`，`mid=2`，`a[2]=3>2`，往左，`r=1`；`mid=0`，`a[0]=1<2`，往右，`l=1`；`mid=1`，`a[1]=1<2`，往右，`l=2`；这时候 `l=2>r=1`，循环结束，`ans` 从没被赋值过，还是 **-1**——没找到。三次手推的结果 `1、4、-1`，和真实测试点的答案一字不差。

模板代码（注意这版为了找"第一次出现的位置"，找到相等后不立刻退出，而是继续往左收缩）：

```cpp
int l = 0, r = n - 1, ans = -1;
while (l <= r) {
    int mid = (l + r) / 2;
    if (a[mid] == x) { ans = mid; r = mid - 1; }   // 记录答案，继续往左找更靠前的
    else if (a[mid] < x) l = mid + 1;
    else r = mid - 1;
}
```

**边界是二分的命门**：`l <= r` 还是 `l < r`、`l=mid+1` 还是 `r=mid-1`，想不清楚就像刚才这样，拿 3~5 个数手推一遍，比死记模板靠谱得多。延伸一句：标准库的 `lower_bound(a, a+n, x)` 就是在做"找第一个 ≥ x 的位置"这件事，【练2】A-B 数对统计"等于某个值的个数"就要靠它（或者手写两次二分，找下界和上界）。

切到 `排序过程演示.html` 的"二分查找"页签，输入数组和目标值，点"下一步"看 `[l, r]` 这个区间怎么被一步步砍掉一半，`mid` 命中之后又是怎么继续往左收缩去找第一个出现位置的。

## 逆序对与归并排序（例4）：排序的时候顺便数一数

**逆序对**：一对下标 `i<j`，但 `a[i]>a[j]`——排在前面的数反而比后面的大。数列 `3 1 2` 里，`(3,1)` 和 `(3,2)` 都是逆序对，一共 **2** 对（这是真实测试样例，答案也确实是 2）。逆序对个数能衡量一个数列"乱"到什么程度：完全升序是 0 对，完全降序是 `n(n-1)/2` 对，也就是最多能有约 `5×10⁹` 对（n=10⁵ 时）——**这个数字已经超过 int 上限，必须开 long long**。

暴力两层循环 O(n²) 会超时，正确做法是**归并排序**，排序的同时"顺便"把逆序对数出来。归并的规则：把数组从中间劈成两半，各自排好序，再用两个指针把两个有序序列合并成一个。

关键的那一步在"合并"时发生。举一个比 `3 1 2` 稍微丰富一点的过程感受一下：假设合并阶段左边有序段是 `[1, 3]`，右边有序段是 `[2]`，两个指针 `i` 指左边、`j` 指右边：比较 `L[i]=1` 和 `R[j]=2`，`1≤2`，把 1 先取出来，`i` 往后走，没有产生逆序对；再比较 `L[i]=3` 和 `R[j]=2`，`3>2`，这时候要**先取右边的 2**——问学生一句："这一步能顺手数出几个逆序对？"——左边从 `i` 到末尾**剩下的所有数**（这里就是 `3`）都比这个刚取出的 `2` 靠前、又都比它大，全部构成逆序对，一次性加上 `剩余个数`（这里是 1 个）。这就是"归并顺便计数"的核心机关：**每次从右边取数时，左边还剩多少个没取，就产生多少个逆序对**，不需要额外再扫一遍。

```cpp
// 合并两个有序段 [l, mid] 和 [mid+1, r]，顺便统计逆序对
int i = l, j = mid + 1, k = l;
while (i <= mid && j <= r) {
    if (a[i] <= a[j]) tmp[k++] = a[i++];
    else { tmp[k++] = a[j++]; ans += mid - i + 1; }  // 左边剩下 mid-i+1 个数，全都跟 a[j] 构成逆序对
}
```

这是"**在分治过程中顺便统计答案**"这个思想第一次登场，后面学到树状数组求逆序对，本质上是它的加速版。逆序对也解释了为什么冒泡排序的交换次数恰好等于逆序对个数——冒泡每次交换正好消掉一对逆序，这与第 10 章车厢重组、本章选择排序讲过的内容遥相呼应。

## 值域小的时候：桶思想（练1 的另一条路）

如果数的取值范围不大（比如都在 `10⁵` 以内），可以直接开一个计数数组 `cnt[x]++`，这一步天然完成了"排序 + 统计"——扫一遍统计数组就知道谁出现得最多、谁出现了几次。**排序 vs 桶**：值域小，桶比排序还快（O(值域) 而不是 O(n log n)）；值域大（比如到 `10⁹`），数组开不下，只能老老实实排序。

## 记住这一条就够

排序的 O(n²) 和 O(n log n) 之间隔着一道"n=10⁵"的坎；排序带来的有序性，是二分查找、桶统计、归并计数这些技巧全部成立的地基。这一章讲完，以后看到"是否有序""能不能预处理排序"，应该成为拿到题目的第一反应。

## 学生最容易栽的坑

1. n=10⁵ 时 O(n²) 必超时——看到范围先定复杂度，别等 TLE 了才反应过来；
2. 二分前**必须先排序**；`lower_bound` 用在无序数组上是没有意义的；
3. 二分边界：`l <= r` 配 `mid±1`；死循环基本都是"区间没有真正缩小"，出问题就手推一个小例子；
4. 逆序对计数**开 long long**（最大约 5×10⁹，早算过范围就不会漏）；
5. 自定义 `cmp` 必须满足严格弱序：`return a < b;`，不要写成 `<=`（可能导致运行时错误）；
6. 快排最坏 O(n²)（数组已有序 + 固定取端点当 pivot），标准库 `sort` 已经规避了这个问题，但手写快排时要留心。
