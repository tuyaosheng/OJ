# 匹配对手——讲解稿

## 一、题目解读

匹配系统找"分差最小的对手"，10^5 名玩家 × 10^5 候选。朴素两重循环 10^10 次运算直接判死刑——数据范围替你选好了算法：排序 + 二分。

## 二、思路分析

关键洞察：**把对手池排好序后，离 x 最近的候选一定紧挨着"x 应该插入的位置"**——只可能是右边第一个（第一个 ≥ x 的）或左边第一个（最后一个 < x 的），其余候选都被这两个"隔开"，不可能更近。

于是每次查询：

1. `lower_bound` 二分出第一个 ≥ x 的下标 p；
2. 候选只有 b[p]（若存在）和 b[p-1]（若存在），两个差取 min。

## 三、代码讲解

- `lower_bound(b, b+n, x) - b`：返回指针减首地址得下标——STL 二分的标准用法（第 12 章例3 手写二分的库函数版）；
- 两个 if 处理边界：p==n（x 比所有人大，只有左侧）、p==0（x 比所有人小，只有右侧）；
- 差值用 long long：分值 ≤ 10^9，差本身 int 也装得下（< 10^9），但初始的"无穷大"取 4×10^9 超了 int——干脆全程 ll，省得纠结；
- 读入 2×10^5 个数，开 `sync_with_stdio(false)` 加速。

## 四、易错点

1. **忘了先排序**——lower_bound 在无序数组上结果毫无意义（不会报错，纯错答案，最坑）；
2. 只看 b[p] 不看 b[p-1] → "最近的在左边"的一半用例全错；
3. p==0 时访问 b[p-1] → 越界；
4. 初始最小值取 10^9 不够大（最大差可达 10^9 − 1，凑巧能对，但边界思维要严谨——取 4e18 类的安全值）。

## 五、小结

"找最接近的数" = 排序 + lower_bound + 看左右两个邻居。这个三步套路在"A-B 数对"（本章练2）基础上更进一步，也是所有"匹配/推荐"类问题的最简原型。
