# 讲解稿：快速排序（ch12-002）

## 一、题目解读

还是排序，但 **n 从 2000 涨到了 100000**。

就这一个数字的变化，让上一题的选择排序**彻底失效**。我们算笔账：

| 算法 | 复杂度 | n = 2000 | n = 100000 |
|------|--------|----------|-----------|
| 选择排序 | O(n²) | 200 万次 ✓ | **50 亿次** ✗ 超时 |
| 快速排序 | O(n log n) | 2 万次 ✓ | **170 万次** ✓ |

50 亿 vs 170 万，**差了近 3000 倍**。这就是算法复杂度的威力——**换个算法，比换台电脑管用得多。**

## 二、思路分析

### 先说结论：竞赛里直接用 `sort`

```cpp
#include <algorithm>
sort(a, a + n);      // 完事
```

C++ 标准库的 `sort` 是 O(n log n) 的，而且经过极致优化，通常**比你手写的快排还快**。竞赛中 99% 的场合，你就该这么写。

但今天我们要打开这个"黑盒"，看看 O(n log n) 到底是**怎么做到的**。

### 快排的核心：分治

分治（Divide and Conquer）的三部曲：**分解 → 解决 → 合并**。

快排是这么分的：

> 1. **选基准**：从数组里挑一个数当"基准"（pivot）。
> 2. **分区**：把**比基准小**的都甩到左边，**比基准大**的都甩到右边。
>    这一步之后，基准就**站到了它最终该在的位置**——左边全比它小，右边全比它大。
> 3. **递归**：对左半边、右半边**分别重复**这个过程。

注意第 2 步的妙处：**一次分区，就永久确定了一个数的位置**，并且把问题规模**砍成了两半**。

### 为什么是 O(n log n)？

每一层递归，所有的分区加起来要扫描 n 个元素——这是 **O(n)**。

而问题规模每次**减半**：n → n/2 → n/4 → … → 1。要减多少次才到 1？答案是 **log₂n** 次。

（n = 100000 时，log₂(100000) ≈ 17。所以只有 17 层！）

**总复杂度 = 层数 × 每层工作量 = O(log n) × O(n) = O(n log n)。**

对比选择排序：它每一轮只能确定**一个**位置，要 n 轮；快排每一层能把问题**砍半**，只要 log n 层。**这就是分治的力量。**

## 三、代码讲解

```cpp
void quickSort(int l, int r)
{
    if (l >= r) return;              // 区间里只剩 0 或 1 个数，本来就有序

    int pivot = a[(l + r) / 2];      // 取【中间】的数作基准
    int i = l, j = r;

    while (i <= j)
    {
        while (a[i] < pivot) i++;    // 从左往右，找一个"站错队"的（>= pivot）
        while (a[j] > pivot) j--;    // 从右往左，找一个"站错队"的（<= pivot）

        if (i <= j)
        {
            swap(a[i], a[j]);        // 让它俩换个位置，各归其位
            i++;
            j--;
        }
    }

    quickSort(l, j);                 // 递归排左半边
    quickSort(i, r);                 // 递归排右半边
}
```

### 分区是怎么工作的？

想象两个人从数组两头**相向而行**：

- **左边的人** `i` 一路向右走，直到发现一个 **≥ pivot** 的数——"这家伙不该待在左边！"于是停下。
- **右边的人** `j` 一路向左走，直到发现一个 **≤ pivot** 的数——"这家伙不该待在右边！"于是停下。
- 两人**交换**手里的数，然后继续走。
- 直到两人**相遇**（`i > j`），此时左边全是小的、右边全是大的，分区完成。

### 关键：为什么基准要取【中间】的数？

这是本题**最重要的细节**，也是新手最容易踩的坑。

假如你图省事，取**第一个元素** `a[l]` 当基准。那么当输入是**已经有序**的数组时，会发生什么？

- 基准是最小的数，分区后左边**空**，右边有 n−1 个数；
- 下一层，基准还是最小的，左边又空，右边 n−2 个……

**问题规模每次只减少 1，而不是减半！** 递归深度变成 n，复杂度退化成 **O(n²)**——比选择排序还慢（还多了递归开销），而且递归 10 万层会直接**爆栈**。

取**中间**的元素作基准，就能避开"有序数据"这个陷阱。（更稳妥的做法是**随机**取基准，那样任何输入都难以卡死它。）

> 本题的测试数据里，**专门放了"完全有序"和"完全逆序"两组 n = 10 万的数据**，就是为了考验你的基准选择。取首元素的写法会在这里 TLE 或 RE。

### 别忘了关同步

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

n = 10 万时，光是读入输出就有 20 万次操作。`cin`/`cout` 默认和 C 的 `stdio` 保持同步，很慢。加上这两行能**提速好几倍**，是大数据题的标配。

## 四、易错点

1. **基准取首元素** —— 遇到有序数据退化成 O(n²)，超时或爆栈。**本题头号杀手。**
2. **`while (a[i] < pivot)` 写成 `<=`** —— 当所有元素相等时，`i` 会一路冲到数组末尾，越界或死循环。（本题测试数据里有"**全部相同**"的一组，专治这个 bug。）
3. **递归边界写错** —— `if (l >= r) return;` 少了，无限递归爆栈。
4. **递归区间写错** —— 必须是 `quickSort(l, j)` 和 `quickSort(i, r)`，不是 `(l, i-1)` 和 `(j+1, r)`。这套 Hoare 分区的边界很微妙，建议**照着背下来**。
5. **忘了关同步** —— 10 万级读写，可能因为 I/O 慢而超时。

## 五、小结

| | 选择排序 | 快速排序 |
|---|---------|---------|
| **思想** | 每轮选出最小值 | 分治：分区 + 递归 |
| **复杂度** | O(n²) | 平均 O(n log n) |
| **n=10万** | 50 亿次，超时 | 170 万次，飞快 |

**分治**是算法世界最重要的思想之一：**把大问题劈成两个小问题，分别解决，再合起来。** 后面的归并排序、二分查找、乃至整个"分治算法"章节，都建立在这个思想上。

**实战建议**：竞赛中**直接用 `sort`**，别手写。手写快排的意义在于**理解**，不在于使用——就像你学会了汽车原理，但上路还是开成品车。

**下一题**，我们来看排序的一个直接红利：数据一旦有序，**查找**就能从 O(n) 降到 O(log n)。这就是**二分查找**。
