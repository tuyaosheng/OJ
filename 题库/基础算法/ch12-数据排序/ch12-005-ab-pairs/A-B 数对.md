# 讲解稿：A-B 数对（ch12-005）

## 一、题目解读

给一个长度 n 的数列和一个正整数 C，统计有多少个**下标对** (i, j) 满足：

**a[i] − a[j] = C**

n ≤ 10 万。

**暴力做法**是两重循环枚举所有 (i, j)：

```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        if (a[i] - a[j] == C) ans++;
```

O(n²) = **100 亿次** —— 必然超时。这题的任务，就是把它优化掉。

## 二、思路分析

### 第一步：移项！

这是全题的**转折点**。把式子变个形：

**a[i] − a[j] = C  ⟺  a[i] = a[j] + C**

看出区别了吗？

- **原式**：要同时盯住 **i 和 j 两个**变量，只能双重循环。
- **变形后**：只要**固定 j**，那么 a[i] 的值就**唯一确定**了——它必须等于 `a[j] + C`。

于是问题从"枚举两个下标"变成了：

> **枚举 j（O(n)），然后数一数：数组里有多少个数等于 `a[j] + C`？**

只要"数一数"这一步足够快，总复杂度就能降下来。

> **一个小小的移项，把二维问题降成了一维。** 这种代数变形的能力，在算法题里价值千金。遇到多变量的条件，先试试能不能移项、分离变量。

### 第二步：怎么快速"数一数"？

问题变成：**在数组里，值等于 x 的元素有多少个？**

排序之后，相同的数会连成一段（还记得上一题吗？）。于是：

- `lower_bound(a, a+n, x)` → 第一个 **≥ x** 的位置（这段的**开头**）
- `upper_bound(a, a+n, x)` → 第一个 **> x** 的位置（这段的**末尾之后**）
- **两者相减 = 等于 x 的元素个数！**

举例：排序后是 `1 3 3 3 7`，求等于 3 的个数：
- `lower_bound(3)` → 下标 1
- `upper_bound(3)` → 下标 4
- 4 − 1 = **3 个** ✓

每次查询 O(log n)，n 次查询就是 **O(n log n)**。搞定！

## 三、代码讲解

```cpp
sort(a, a + n);      // 二分的前提

long long ans = 0;   // 【必须 long long】

for (int j = 0; j < n; j++)
{
    long long target = (long long)a[j] + C;    // 【防溢出】

    int cnt = upper_bound(a, a + n, target) - lower_bound(a, a + n, target);

    ans += cnt;
}
```

核心就这几行。但里面藏着**两个致命的溢出陷阱**，必须讲透。

### 陷阱一：`ans` 必须是 `long long`

答案最大能到多少？

设想：数组一半是 100，另一半是 107，C = 7。那么每个 100 都能和每个 107 配对：

`(n/2) × (n/2) = 50000 × 50000 = 25 亿`

而 `int` 的上限是约 **21.47 亿** —— **溢出！** 结果会变成负数，答案全错。

> 本题的测试数据里，**专门构造了这样一组**（答案 = 2,500,000,000），用 int 必挂。

**经验法则**：**只要答案是"计数"且规模可能达到 n²，就用 `long long`。** 这是竞赛中最常见的溢出场景之一。

### 陷阱二：`a[j] + C` 也可能溢出！

这个更隐蔽。a[j] 最大 10^9，C 最大 10^9，相加是 **2 × 10^9** —— 而 int 上限是 2.147 × 10^9。

看起来"刚好没超"？但如果 a[j] = 10^9 且 C = 10^9，和是 2×10^9 < 2.147×10^9，**确实没溢出**。可这已经**极其接近上限**了，稍有不慎（比如题目范围再放宽一点）就会翻车。

**稳妥的做法是先转成 `long long` 再相加**：

```cpp
long long target = (long long)a[j] + C;
```

**注意 `(long long)` 必须加在 `a[j]` 前面**！如果写成 `long long target = a[j] + C;`，那么 `a[j] + C` 这个加法**仍然是在 int 里做的**（先算完再转换），溢出照样发生。**必须让加法本身在 long long 里进行。**

> 这是 C++ 类型转换的经典陷阱，**很多人栽在这里**。记住：**在运算之前转换，而不是运算之后。**

### 一个小疑问：i 和 j 会是同一个下标吗？

题目要求的是**不同下标**的配对。会不会出现 i = j 的情况？

不会。因为 **C ≥ 1**（题目保证是正整数），所以 `a[i] = a[j] + C` 意味着 `a[i] ≠ a[j]`，两者数值都不同，自然不可能是同一个元素。**无需额外排除。**

（但如果题目允许 C = 0，就必须小心了——那时每个数都会和自己配对，得减掉 n。**边界条件永远值得多想一秒。**）

## 四、易错点

1. **`ans` 用 `int`** —— 答案可达 25 亿，溢出成负数。**头号杀手。**
2. **`a[j] + C` 在 int 里做加法** —— 必须写 `(long long)a[j] + C`，转换要在**加法之前**。
3. **忘记排序** —— `lower_bound` / `upper_bound` 的结果毫无意义。
4. **用了两重循环** —— O(n²)，超时。
5. **搞混 `lower_bound` 和 `upper_bound`** —— 记住：**lower 是"第一个 ≥"，upper 是"第一个 >"**，相减得到"等于"的个数。

## 五、小结

这道题浓缩了三个重要技能：

1. **代数变形**：`a[i] - a[j] = C` → `a[i] = a[j] + C`。**分离变量，把二维枚举降成一维。** 这一步是解题的钥匙。
2. **排序 + 二分**：用 `upper_bound - lower_bound` 快速统计"等于某值的元素个数"，O(log n)。
3. **溢出意识**：答案用 `long long`；中间运算也要防溢出，**转换要在运算之前**。

优化路径：**O(n²) 暴力 → 移项 → O(n log n)**。这是算法优化最典型的一条路。

> **拓展思考**：如果数值范围很小（比如都在 1~1000 之间），你还可以用**桶计数** —— `cnt[v]` 存值为 v 的个数，然后 `ans += cnt[v] * cnt[v + C]`，复杂度 **O(n + 值域)**，比排序还快！
>
> 又见"值域小用桶、值域大用排序"这条法则。**拿到题先看数据范围**，这句话怎么强调都不过分。

**最后一题**是本章的压轴：**逆序对**。我们将见识到——排序的过程本身，也可以"顺便"计算出有价值的信息。
