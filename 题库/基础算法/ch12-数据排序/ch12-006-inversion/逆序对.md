# 讲解稿：逆序对（ch12-006）

## 一、题目解读

**逆序对**：一对下标 (i, j)，满足 **i < j** 且 **a[i] > a[j]**。

人话：**排在前面的数，反而比后面的大**——这一对就"逆序"了。

例：`3 1 2` 中，(3,1) 和 (3,2) 都是逆序对，共 **2** 对。

逆序对的个数，衡量了数列的"**混乱程度**"：

- 完全升序 `1 2 3 4 5` → **0** 个逆序对（最有序）
- 完全降序 `5 4 3 2 1` → **10** 个（= n(n−1)/2，最混乱）

暴力做法两重循环 O(n²)，n = 10 万时 100 亿次，超时。

**本题的精妙**：逆序对能在**归并排序的过程中"顺便"数出来**——排序和计数一箭双雕。这是本章的压轴题，也是**分治思想**的绝佳范例。

## 二、思路分析

### 先回顾归并排序

归并排序也是分治，但和快排的路子相反：

- **快排**：先分区（做事），再递归（左右两半自然就有序了）。**先做事，后递归。**
- **归并**：先递归排好左右两半，再把两个**有序**的半边**合并**起来。**先递归，后做事。**

合并两个有序数组很简单：两个指针分别指向左右两半的开头，每次挑较小的那个放进结果里。

```
左半: 1 3 5      右半: 2 4 6
     ↑                ↑
比较 1 和 2 → 取 1；比较 3 和 2 → 取 2；比较 3 和 4 → 取 3……
结果: 1 2 3 4 5 6
```

### 核心洞察：在"合并"时数逆序对

现在是本题最关键的一步，请集中注意力。

假设正在合并：左半边 `L`（**已有序**），右半边 `R`（**已有序**）。指针 i 指着 L 中某个元素，j 指着 R 中某个元素。

**情况一：`L[i] <= R[j]`** —— 取 L[i]。
不产生逆序对（L[i] 不比 R[j] 大，也不比 R 里后面的数大，因为 R 有序）。

**情况二：`L[i] > R[j]`** —— 取 R[j]。**注意了！**

L[i] 比 R[j] 大，它们构成一个逆序对（L 在左边，下标更小）。但**不止这一对**——

> **因为 L 是有序的**，`L[i] > R[j]` 意味着 L[i] 后面的元素 `L[i+1], L[i+2], …, L[mid]` **全都 ≥ L[i] > R[j]`**！
>
> 而它们的下标**全都小于** R[j] 的下标（左半边整个都在右半边前面）。
>
> **所以它们每一个都和 R[j] 构成逆序对！**

一口气产生了多少对？从 i 到 mid，共 **`mid - i + 1`** 对！

```cpp
if (a[i] <= a[j])
    tmp[k++] = a[i++];
else
{
    tmp[k++] = a[j++];
    ans += mid - i + 1;      // ★ 精髓：左边剩下的全都和 a[j] 逆序
}
```

**这就是全题的灵魂。** 我们不是一对一对地数，而是**一批一批**地数——这正是它能做到 O(n log n) 的原因。

### 手动模拟一遍

数列 `3 1 2`，逆序对应该是 2 个。

1. 分成 `[3]` 和 `[1, 2]`。
2. 右半 `[1, 2]` 递归排序 → 内部无逆序对，仍是 `[1, 2]`。
3. **合并 `[3]` 和 `[1, 2]`**（mid 指向 3 的位置，i 指向 3）：
   - 比较 `3` vs `1`：3 > 1 → 取 1，`ans += mid - i + 1 = 1`。（3 和 1 逆序）✓
   - 比较 `3` vs `2`：3 > 2 → 取 2，`ans += 1`。（3 和 2 逆序）✓
   - 左边 `3` 剩下，直接搬过来。
4. 总计 **ans = 2** ✓ 完全正确！

### 为什么不重不漏？

任意一对 (i, j)，在归并的递归树里，**恰好**会在**唯一一次**合并中被"跨越"：

- 如果 i、j 落在**同一半边**里 → 由那一边的**递归**去处理；
- 如果 i、j **分属左右两半** → 就在**这次合并**中被统计。

每对元素**有且仅有一次**分属左右两半的时刻。所以**不重不漏**。这是分治结构给出的严格保证。

## 三、代码讲解

```cpp
void mergeSort(int l, int r)
{
    if (l >= r) return;

    int mid = l + (r - l) / 2;

    mergeSort(l, mid);              // 先排好左半
    mergeSort(mid + 1, r);          // 再排好右半

    int i = l, j = mid + 1, k = l;

    while (i <= mid && j <= r)
    {
        if (a[i] <= a[j])
            tmp[k++] = a[i++];      // 取左边，不产生逆序对
        else
        {
            tmp[k++] = a[j++];
            ans += mid - i + 1;     // ★ 关键
        }
    }

    while (i <= mid) tmp[k++] = a[i++];   // 搬走剩余
    while (j <= r)   tmp[k++] = a[j++];

    for (int p = l; p <= r; p++)    // 写回原数组
        a[p] = tmp[p];
}
```

### 细节一：为什么是 `a[i] <= a[j]` 而不是 `a[i] < a[j]`？

逆序对的定义是 **严格大于**（`a[i] > a[j]`），**相等不算**。

- 写 `<=`：相等时走 **if 分支**（取左边），**不计数** ✓ 正确
- 写 `<`：相等时走 **else 分支**（取右边），**会 `ans += ...`** ✗ 把相等的也算成逆序对了，答案偏大！

> **又是一个符号之差定成败。** 本题测试数据里有"**全部相同**"（答案应为 0）和"**大量重复**"两组，专治这个 bug。写 `<` 会得到一个巨大的错误答案。

### 细节二：`ans` 必须是 `long long`

最坏情况（完全逆序），逆序对个数是：

`n(n-1)/2 = 100000 × 99999 / 2 ≈ 50 亿`

int 上限 21 亿 —— **溢出**。（测试数据里有一组完全逆序的，答案正是 **4,999,950,000**。）

### 细节三：需要临时数组 `tmp`

合并时不能在原数组上直接改（会覆盖还没读的数据），必须先写进 `tmp`，合并完再**写回**原数组。

## 四、易错点

1. **`ans` 用 int** —— 50 亿溢出。
2. **`a[i] <= a[j]` 写成 `<`** —— 把相等的也算成逆序对。**本题最隐蔽的坑。**
3. **`ans += mid - i + 1` 写错** —— 常见错写：`ans += 1`（只数了一对，漏掉了 L 中后面的）、`ans += mid - i`（少算一个，差一错误）。**牢记：从 i 到 mid，共 `mid - i + 1` 个。**
4. **忘记把 tmp 写回原数组** —— 上层递归拿到的不是有序数组，全盘皆错。
5. **在错误的时机计数**（比如在取左边时计数）—— 逻辑颠倒。

## 五、小结

**逆序对 = 归并排序 + 一行计数。**

核心公式：**合并时若 `L[i] > R[j]`，则 `ans += mid - i + 1`。**

| 做法 | 复杂度 | n = 10 万 |
|------|--------|----------|
| 暴力两重循环 | O(n²) | 100 亿次 ✗ |
| 归并排序统计 | **O(n log n)** | 170 万次 ✓ |

### 本章总回顾

我们从最朴素的排序，一路走到了分治的殿堂：

| 题 | 内容 | 核心收获 |
|---|------|---------|
| 1 | 选择排序 | 亲手实现排序，理解 O(n²) 的局限 |
| 2 | 快速排序 | **分治**：分区 + 递归，O(n log n) |
| 3 | 二分查找 | **有序 → 查找变快**（预处理换查询速度）|
| 4 | 众数 | **有序 → 相同元素相邻**（计数变扫描）|
| 5 | A-B 数对 | **排序 + 二分**，移项降维；溢出防范 |
| 6 | 逆序对 | **归并排序**，排序时顺便计算信息 |

**整章的主线是一句话**：

> **排序远不只是"把数排整齐"。它是一种强大的预处理手段——数据一旦有序，查找、去重、统计、配对……无数问题都会豁然开朗。**

而最后这道逆序对更进一步告诉我们：**排序的"过程"本身，也蕴含着可以利用的信息。** 归并的每一次合并，都在无声地丈量着数据的混乱程度。
