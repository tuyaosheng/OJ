# 讲解稿：二分查找（ch12-003）

## 一、题目解读

给 n 个数（无序、可能重复），再给 q 次询问。每次问一个数 x：它在不在数组里？如果在，**排序后第一次出现在第几位**？

n、q 都是 10 万。

**先算暴力的账**：每次询问都从头扫到尾，单次 O(n)，q 次就是 **O(nq) = 100 亿** —— 稳稳超时。

这一题要传达的核心观念是：

> **排序不只是"把数排整齐"，它是一种强大的"预处理"——排完之后，很多操作会突然变快。**

## 二、思路分析

### 二分查找的思想：猜数字游戏

你一定玩过猜数字：我心里想一个 1~100 的数，你来猜，我只告诉你"大了"还是"小了"。

聪明的玩法是**每次猜中间**：

- 猜 50 → "小了" → 答案在 51~100，**一半的可能被排除了**
- 猜 75 → "大了" → 答案在 51~74
- 猜 62 → …… 

100 个数，最多猜 **7 次**（因为 2⁷ = 128 > 100）就能锁定。

**二分查找就是这个道理**：每次比较中间元素，就能**砍掉一半**的搜索范围。

- 10 万个数，砍多少次剩 1 个？**log₂(100000) ≈ 17 次**。
- 对比暴力的 10 万次 —— **快了近 6000 倍**。

### 二分的铁律前提：必须有序！

为什么必须有序？因为二分依赖一个判断：

> "中间的数比 x 小 → 那 x 只可能在**右半边**"

这个推理，**只有在数组有序时才成立**。乱序数组里，左边照样可能藏着比 x 大的数——一刀砍掉半边，可能就把答案砍没了。

**所以第一步永远是 `sort(a, a + n)`。** 忘了排序，二分不会报错，但会静静地给你错误答案——**这种 bug 最难查**。

### 这题的特殊之处：要找"第一次出现"

数组里可能有重复。比如排序后是 `1 1 3 4 5`，问 x = 1，答案应该是位置 **1**（第一个 1），不是位置 2。

普通的二分找到任意一个 1 就停了，**未必是最左边那个**。所以我们要的是**二分下界**（lower_bound）——找**第一个 ≥ x 的位置**。

## 三、代码讲解

### 方法一：手写二分

```cpp
int l = 0, r = n - 1;
int pos = -1;                       // 记录答案，初始"没找到"

while (l <= r)
{
    int mid = l + (r - l) / 2;

    if (a[mid] >= x)
    {
        if (a[mid] == x)
            pos = mid;              // 找到一个！但左边可能还有更早的
        r = mid - 1;                // 【关键】不停下，继续往左找
    }
    else
    {
        l = mid + 1;                // a[mid] < x，答案在右边
    }
}
```

**精髓在于：找到 x 之后不立即返回，而是记下位置、继续往左找。** 这样最终 `pos` 停在的，一定是**最左边的那个 x**。

**`mid = l + (r - l) / 2` 是什么写法？**

它等价于 `(l + r) / 2`，但**能防止溢出**。当 l 和 r 都很大时（比如接近 21 亿），`l + r` 会超出 int 范围变成负数，而 `l + (r - l) / 2` 永远不会溢出。**这是竞赛里的标准写法，请养成习惯。**

### 方法二：用 STL（推荐）

C++ 已经把二分写好了：

```cpp
int pos = lower_bound(a, a + n, x) - a;   // 第一个 >= x 的下标

if (pos < n && a[pos] == x)
    cout << pos + 1 << "\n";      // 找到了，0-based 转 1-based
else
    cout << -1 << "\n";
```

- `lower_bound(起点, 终点, x)` 返回**第一个 ≥ x 的元素的指针**，减去数组首地址 `a` 就得到下标。
- **注意那两个检查缺一不可**：
  - `pos < n`：如果 x 比数组里所有数都大，`lower_bound` 会返回**末尾**（下标 n），此时 `a[pos]` 已经越界！
  - `a[pos] == x`：`lower_bound` 只保证"≥ x"，返回的可能是个**比 x 大**的数。必须再确认它**真的等于** x。

（相应地，`upper_bound` 返回第一个 **> x** 的位置。下一题会用到。）

## 四、易错点

1. **忘记先排序** —— **头号杀手**。二分会给出看似合理的错误答案，极难调试。
2. **忘记 `pos < n` 的越界检查** —— x 比所有数都大时，访问 `a[n]` 越界。（测试数据里专门有一组"**询问全部越界**"的数据。）
3. **忘记检查 `a[pos] == x`** —— 把"第一个比 x 大的数"的位置当成了 x 的位置。
4. **找到就返回，没继续往左找** —— 重复元素时返回的不是**第一次**出现的位置。（测试数据里有"**全部相同**"和"**大量重复**"两组，专治此病。）
5. **忘记 0-based 转 1-based** —— 下标从 0 开始，题目要的位置从 1 开始，**输出时要 +1**。
6. **忘了关同步** —— 10 万次询问，I/O 量大。

## 五、小结

**二分查找**：在**有序**数据中，每次比较中间元素、砍掉一半范围，O(log n) 完成查找。

| 数据规模 | 暴力扫描 | 二分查找 |
|---------|---------|---------|
| n = 10 万 | 10 万次 | **17 次** |

**三个必须记住的点**：

1. **前提是有序** —— 二分之前必须先排序，这是铁律。
2. **`lower_bound` / `upper_bound`** —— STL 已经写好了，直接用，但**别忘了越界和相等的双重检查**。
3. **`mid = l + (r - l) / 2`** —— 防溢出的标准写法。

**更重要的领悟**：这一题真正想告诉你的是——

> **"排序"是一种投资。** 花 O(n log n) 排一次序，之后每次查询只要 O(log n)。查询次数越多，这笔投资越划算。

这种"**预处理换查询速度**"的思路，和第 10 章的**前缀和**如出一辙（花 O(n) 预处理，换来 O(1) 查询区间和）。**它是算法优化最常见的套路之一。**

**下一题**，我们看排序的另一个红利：**排完序，相同的数会聚在一起**——于是"统计出现次数"这件事，变得异常简单。
