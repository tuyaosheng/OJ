# 过河卒 讲解稿

## 考点
DP 从"求最优值"扩展到"求方案数"——转移方式从"取最大/最小"变成"相加"。

## 引入（1 分钟）
和例1对比：状态设计的思路完全一样（`dp[i][j]` 描述"走到 `(i,j)` 这个子问题的答案"），但这题问的不是"最优是多少"，而是"**一共有多少种走法**"。这个变化直接影响转移公式怎么写。

## 核心推导（重点，讲透）
DP 三要素：
1. **状态**：`dp[i][j]` = 从 `(0,0)` 走到 `(i,j)` 的不同走法数。
2. **边界**：`dp[0][0] = 1`（前提是 `(0,0)` 本身不是马控制的格子——如果是，那就一种走法都没有，`dp[0][0]=0`）。
3. **转移**：`dp[i][j] = dp[i-1][j] + dp[i][j-1]`。

**"取最优"和"求方案数"的对应关系**：例1的转移是 `a[i][j] + max(...)`——"从多个来源里挑最好的一个"；这题的转移是 `dp[i-1][j] + dp[i][j-1]`——"从多个来源里，把方案数加起来"。这不是巧合：**只要一个问题能写成"从几个更小的子问题转移过来"，把 `max` 换成"求和"，往往就能把"求最优值"的 DP 改造成"求方案数"的 DP**（反过来也一样）。这是动态规划里非常通用的一个转换技巧，后面章节会反复见到。

**障碍怎么处理**：马自己所在的格子，加上马能一步跳到的最多 8 个格子（日字形，注意越界的要排除），一共最多 9 个格子是卒不能经过的。这些格子的 `dp` 值保持默认的 `0`，既不会被赋予别的值，也不会作为来源传给别的格子（因为它们自己是 `0`，加进别的格子的转移里相当于没贡献）。

## 代码逐行讲解
```cpp
for (int k = 0; k < 9; k++) {
    int x = bx + hx[k], y = by + hy[k];
    if (x >= 0 && x <= n && y >= 0 && y <= m) blocked[x][y] = true;
}
```
- `hx[0], hy[0]` 是 `(0, 0)`，代表马自己所在的格子；剩下 8 组是马能跳到的日字位置——用同一个循环处理"马自己"和"马能跳到的地方"，代码更整齐。

```cpp
ll fromUp = (i > 0) ? dp[i - 1][j] : 0;
ll fromLeft = (j > 0) ? dp[i][j - 1] : 0;
dp[i][j] = fromUp + fromLeft;
```
- 处理第一行（`i=0`）和第一列（`j=0`）的边界：这些格子只有一个来源方向，另一个方向"不存在"，直接按 `0` 处理（因为它代表"没有这个来源"，不是"这个来源的方案数是 0"，两者在加法里效果一样，可以统一处理）。

## 易错点
- 方案数可能很大（最多约 `1.4×10^11`），必须用 `long long`，不能用 `int`。
- 判断马控制点时，容易忘记检查坐标越界（马跳到棋盘外面的位置不需要标记）。
- 起点 `(0,0)` 如果恰好是马控制点，答案直接是 `0`，代码里的 `if (!blocked[0][0]) dp[0][0] = 1;` 已经自然处理了这种情况，不需要额外特判。

## 课堂串讲提示
练2"网格最小路径和"是这道题的直接变式：把"障碍点+求方案数"换成"障碍点+求最优值"，转移公式从 `+` 换回 `min`——讲完这题后对比着讲练2，能帮学生看清楚"DP 转移结构相同、只是运算符不同"这个规律。
