# 摆花 讲解稿

## 考点
"用前几种东西凑出某个数量"的计数 DP——为下一章的背包问题打前站。

## 引入（1 分钟）
这题的状态不再是"走到哪"或"以谁结尾"，而是"**考虑了前几种东西，凑出了多少数量**"——这是一类新的状态设计模式，几乎所有"从若干类物品里选、凑出一个目标数量"的问题，都可以往这个方向想。

## 核心推导（重点，讲透）
- **状态**：`dp[i][j]` = 只考虑前 `i` 种花，摆放恰好 `j` 株的方案数。
- **边界**：`dp[0][0] = 1`（前 0 种花摆 0 株，只有"什么都不摆"这一种方案，是合法的）；`dp[0][j]`（`j>0`）保持默认值 `0`（没有花可摆，不可能摆出正数株）。
- **转移**：第 `i` 种花摆几株是一个独立的选择——摆 `0` 株、`1` 株……一直到 `a[i]` 株，把每种选择对应的方案数加起来：
  ```
  dp[i][j] = dp[i-1][j-0] + dp[i-1][j-1] + ... + dp[i-1][j-a[i]]
  ```
  含义是："第 `i` 种花摆 `k` 株，剩下的 `j-k` 株交给前 `i-1` 种花去摆，把所有可能的 `k` 对应的方案数加起来"。

**这题和"过河卒"的相似之处**：过河卒的转移也是"把几个来源的方案数加起来"，只是过河卒的来源固定是"上边"和"左边"两个，这题的来源是"这一种花摆 0 到 `a[i]` 株"这么多个——**来源的个数可以不止两个，只要想清楚"这一步有哪些选择、每种选择对应哪个更小的子问题"，转移公式就能写出来**。

## 代码逐行讲解
```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 0; j <= m; j++) {
        for (int k = 0; k <= std::min(a[i], j); k++) {
            dp[i][j] = (dp[i][j] + dp[i - 1][j - k]) % MOD;
        }
    }
}
```
- 三重循环：第一层枚举"考虑到第几种花"，第二层枚举"目标摆放数量"，第三层枚举"这种花具体摆几株"——`k` 最多枚举到 `min(a[i], j)`（不能摆得比 `a[i]` 多，也不能摆得比 `j` 多，否则剩下的株数是负数，没有意义）。
- 复杂度 `O(n × m × max(a[i]))`，本题数据范围下最坏约 `100×100×100=10^6`，很快。

## 易错点
- **每一步加法都要取模**：`dp[i][j] = (dp[i][j] + dp[i-1][j-k]) % MOD`，不能攒到最后才取模一次——虽然本题数据范围下用 `long long` 存中间结果也不会溢出，但"每步取模"是处理"方案数对某个数取模"这类题的标准写法，务必养成习惯，数据范围一旦变大就会真的溢出。
- `k` 的枚举上界写错：应该是 `min(a[i], j)`，只写 `a[i]` 会在 `j < a[i]` 时导致数组下标 `j - k` 变成负数，越界访问。

## 课堂串讲提示
这题是承上启下的一课：状态"考虑前几种物品、凑出多少数量"，加上转移里"枚举这一种物品选几个"的三重循环写法，正是下一章"背包问题"的雏形——讲完这题，可以提前预告"下一章会看到一种更快的写法，能把这道题的三重循环优化成两重"，为学习完全背包/多重背包的优化技巧埋下伏笔。
