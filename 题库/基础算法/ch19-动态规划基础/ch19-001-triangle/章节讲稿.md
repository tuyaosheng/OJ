## 上课怎么开场

先问学生一个问题："斐波那契数列 `f(n) = f(n-1) + f(n-2)`，如果直接写递归，`n=40` 会不会超时？"——现场跑一下（或者手动画递归树），会发现 `f(38)` 被计算了两次，`f(37)` 被计算了三次……越往下重复的次数越多，整个递归树的节点数是指数级的，`n=40` 左右就会明显卡顿。

问题出在哪：**同一个子问题被反复计算**。而斐波那契数列本身只有 `n+1` 个不同的子问题（`f(0)` 到 `f(n)`），如果把每个子问题的答案存下来，第二次要用的时候直接查，就能把复杂度从指数级降到 `O(n)`。**这就是动态规划的核心思想：拆解出子问题，把子问题的答案存下来复用，不重复计算**。

和第 17 章"分治"的区别要讲清楚：分治处理的子问题**互不重叠**（比如归并排序的左右两半完全独立），所以分治不需要"存答案"这一步；动态规划处理的子问题**会重叠**（不同的大问题会用到同一个子问题），所以才需要"存下来复用"。这是分治和动态规划最本质的区别，也是很多学生容易混淆的地方。

## DP 三要素

动态规划的解题步骤，本章反复强调三件事：
1. **状态**：用什么变量描述一个子问题；
2. **转移**：状态之间怎么推导——当前状态能不能用更小规模的状态答案算出来；
3. **边界**：最小的、不能再往下拆的子问题，答案是多少。

**状态是最关键的一步**：状态想对了，转移和边界基本水到渠成；状态想不清楚，会卡在"转移方程写不出来"这一步（例3会专门演示这种"卡住"的场景）。

## 例1：数字三角形——建立 DP 三要素的基本框架

从最经典的入门模型开始：数字三角形，从顶点走到最后一行，每步只能走到下一行相邻的两个数字之一，求路径和最大值。

`dp[i][j]` = 从 `(i,j)` 出发走到最后一行能拿到的最大和；边界是最后一行（`dp[n][j] = a[n][j]`）；转移是 `dp[i][j] = a[i][j] + max(dp[i+1][j], dp[i+1][j+1])`。这题采用"从下往上"推的方向，是为了让转移不用处理越界（下一行永远比当前行多一个数字）——**同一个状态可以选不同方向递推，选一个让转移最简单的方向**。

## 例2：过河卒——从"求最优值"到"求方案数"

状态设计的思路不变，但转移方式变了：过河卒问的是"有多少种走法"，转移从"取最大值"变成"把方案数加起来"：`dp[i][j] = dp[i-1][j] + dp[i][j-1]`。

**这是本章最重要的一个类比**：只要一个问题能写成"从几个更小的子问题转移过来"，把 `max`/`min` 换成"求和"，往往就能把"求最优值"的 DP 改造成"求方案数"的 DP，反过来也一样。练1和练2分别是例1、例2的直接变式，讲完例2后可以先卖个关子："等下练习题会让你们亲手验证这个规律"。

## 例3：最长上升子序列——状态卡住了怎么办

这题故意设计成"先卡住，再引导"：让学生先尝试 `dp[i]` = "前 `i` 个数里的最长上升子序列长度"，会发现转移方程写不出来（不知道第 `i` 个数在不在这个子序列里）。这时候引导学生换一种状态定义：`dp[i]` = "**以第 `i` 个数结尾**的最长上升子序列长度"——多了"结尾是谁"这个限定，转移立刻清晰：枚举前面每个 `a[j] < a[i]` 的位置，`dp[i] = max(dp[i], dp[j]+1)`。

**这道题真正的考点，是让学生体会"状态设计卡住时，试着让状态更具体"这个通用套路**，而不是记住"LIS 的状态是以谁结尾"这一个知识点。

## 例4：摆花——从"走格子"到"凑数量"

状态换了一种全新的类型：`dp[i][j]` = "考虑前 `i` 种花，摆放 `j` 株的方案数"。转移不再是固定的两个来源（上边/左边），而是"这一种花摆 `0` 到 `a[i]` 株"这么多种选择，把它们的方案数加起来。**来源的个数不固定，关键是想清楚"这一步有哪些选择、每种选择对应哪个更小的子问题"**。这个状态设计模式，是下一章"背包问题"的雏形——讲完这题可以预告"背包问题会用到几乎一样的状态设计，但转移方式能优化得更快"。

## 学生最容易栽的坑

1. **分不清动态规划和分治**：分治的子问题互不重叠，不需要存答案；动态规划的子问题会重叠，必须存答案复用——这是本章开场就要讲清楚的核心区别；
2. **状态设计得不够具体**：像最长上升子序列，"前 i 个数里最优"这种笼统的状态经常推不出转移，遇到卡住时，试着让状态描述得更具体（比如加上"以谁结尾"）；
3. **递推顺序搞反**：写"从下往上"的转移公式，却按"从上往下"的顺序扫描数组，会用到还没算出来的值——写代码前先想清楚"算 `dp[x]` 之前，它依赖的状态是不是已经算好了"；
4. **求方案数忘记取模、求最优值数组越界初始化不当**：方案数类 DP 要每一步取模；求最优值类 DP（尤其带负数或障碍）要用"很大/很小的哨兵值"正确初始化，不能用 `0`；
5. **答案不是 `dp[n]`**：像最长上升子序列，答案要在所有 `dp[i]` 里取最大值，不是想当然地取最后一个状态。
