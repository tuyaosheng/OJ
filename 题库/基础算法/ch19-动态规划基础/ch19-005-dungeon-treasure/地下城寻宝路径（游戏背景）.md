# 地下城寻宝路径（游戏背景） 讲解稿

## 考点
例1数字三角形的直接变式：三角形换成矩形网格，DP 三要素的思路完全不变。

## 引入（1 分钟）
换了游戏皮肤，也换了图形（三角形→矩形网格），但解题的三个问题还是一样的：状态是什么？怎么转移？边界是什么？——讲这题不需要重新推导思路，重点是让学生自己完成"从三角形迁移到网格"这一步。

## 核心推导（简要，重点在对照）
- **状态**：`dp[i][j]` = 从起点 `(1,1)` 走到 `(i,j)`，沿途能拿到的最大金币和——和例1的状态设计思路完全一致，只是"位置"从"第几行第几个数字"变成了"第几行第几列"。
- **边界**：`dp[1][1] = a[1][1]`。
- **转移**：`dp[i][j] = a[i][j] + max(dp[i-1][j], dp[i][j-1])`。

**和例1的对照**：例1是"从下往上"推（因为终点是最后一行任意位置，起点固定在顶点，从"确定的边界"往"要求的答案"推更顺手）；这题是"从上往下"推（起点固定在 `(1,1)`，边界天然就在这里，正着推更自然）。两题选择的推导方向不同，但**本质上都是"从已知的边界出发，一步步把未知的状态用更小的子问题填满"**。

## 代码逐行讲解
```cpp
for (int i = 0; i <= n; i++)
    for (int j = 0; j <= m; j++)
        dp[i][j] = NEG_INF;   // 先全部标记成"走不到"

dp[1][1] = a[1][1];
```
- 把第 `0` 行和第 `0` 列（不存在的"虚拟边界"）都初始化成一个很小的负数，代表"走不到"。这样在转移时，第一行（`i=1`）取 `dp[0][j]` 会自动是"走不到"（因为不存在从上面来的路），`max` 会自然选中另一个方向，不需要对第一行/第一列单独写特殊判断——这是处理"网格 DP 边界"的一个常用技巧，比逐个判断 `i==1`、`j==1` 更简洁。

## 易错点
- 金币可能是负数，`dp` 数组的初始值不能用 `0` 表示"走不到"（`0` 可能是一个合法的路径和），必须用足够小的负数。
- 数组开够 `1000×1000`，别忘了循环边界。

## 课堂串讲提示
讲完这题可以顺势问学生："如果这题的起点和终点换成任意两个格子，DP 还能不能直接套用？"——引导他们意识到 DP 依赖"从固定起点/边界出发"这个前提，如果起点不固定，思路就要重新设计（比如变成多次 DP，或者换成图论最短路算法）。
