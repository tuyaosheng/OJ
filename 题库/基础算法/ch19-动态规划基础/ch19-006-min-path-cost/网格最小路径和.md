# 网格最小路径和 讲解稿

## 考点
例2过河卒的直接变式：把"求方案数"换回"求最优值"，同时保留"障碍"这个设定。

## 引入（1 分钟）
和练1呼应：练1是例1（求最优值）的变式，这题是例2（求方案数）的变式——但两题变式之后的最终形态非常接近（都是"网格路径 + 求最优值"）。这恰好印证了例1和例2讲过的道理：**"求最优值"和"求方案数"的 DP，转移结构是相通的，运算符从 `max`/`min` 换成 `+`，就能互相转化**。

## 核心推导（简要，重点在对照）
- **状态**：`dp[i][j]` = 从起点走到 `(i,j)` 的最小代价。
- **边界**：`dp[1][1] = a[1][1]`（题目保证起点不是障碍物）。
- **转移**：`dp[i][j] = a[i][j] + min(dp[i-1][j], dp[i][j-1])`；障碍格子不设置 `dp` 值，直接跳过。
- **和过河卒的对照**：过河卒的"马控制点"变成了这题的"障碍物"，处理方式一样——不参与转移；过河卒转移是把两个方向的方案数**相加**，这题转移是取两个方向里**更小**的代价——就是"运算符从 `+` 换成 `min`"这句话的具体体现。

## 代码逐行讲解
```cpp
if (a[i][j] == -1) continue;   // 障碍物，不设置 dp 值
ll best = std::min(dp[i - 1][j], dp[i][j - 1]);
if (best < INF) dp[i][j] = a[i][j] + best;
```
- `dp` 数组先全部初始化成一个很大的数（`INF`），代表"不可达"；只有当至少一个方向"可达"（`best < INF`）时，才更新 `dp[i][j]`——这样处理"障碍物导致部分格子完全走不到"的情况，不需要额外的标记数组。

## 易错点
- 判断"最终能不能到达终点"：如果 `dp[n][m]` 仍然是初始的 `INF`，说明所有路径都被障碍物挡住了，要输出 `-1`，而不是直接输出 `INF` 这个哨兵值。
- 障碍物格子本身也可能出现在 `min` 比较里（作为"来源方向"），但因为障碍物的 `dp` 值从未被设置，会一直保持 `INF`，自然不会被 `min` 选中——理解这一点，就不需要在转移时额外判断"来源格子是不是障碍物"。

## 课堂串讲提示
可以在黑板上把例2和这题的核心两行代码并排写出来对比：
```
过河卒：dp[i][j] = fromUp + fromLeft;
本题：  dp[i][j] = a[i][j] + min(dp[i-1][j], dp[i][j-1]);
```
让学生直观感受"DP 转移结构相同、具体运算不同"这句话的分量——这是本章例2到练2这条线索最重要的收获。
