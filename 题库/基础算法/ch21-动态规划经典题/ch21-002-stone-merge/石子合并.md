# 石子合并 讲解稿

## 考点
区间 DP 入门 + "断环成链"处理圆形结构的通用技巧。

## 引入（1 分钟）
这题的状态和前面所有题都不一样——不是"一个位置"或"两个位置"，而是"**一个区间**"：`dp[i][j]` 描述"把第 `i` 堆到第 `j` 堆合并成一堆"这件事。这是**区间 DP**：状态由区间的左右端点决定，转移是"在区间内挑一个分割点，拆成两个更小的区间分别解决，再合并"。

## 核心推导（重点，讲透）
**先不考虑圆圈，想直线上的情况**：`n` 堆石子排成一排，要把 `[i,j]` 这一段合并成一堆，一定存在"最后一次合并"——把这段石子分成左右两部分，各自先合并好，最后再合成一堆。枚举这个分割点 `k`：
```
dp[i][j] = min( dp[i][k] + dp[k+1][j] + sum(i,j) )，i <= k < j
```
`sum(i,j)` 是这一段的重量总和，也就是"最后一次合并"的代价——不管中间怎么分割，最后这一下的代价都是固定的（把 `[i,j]` 这一整段的石子并成一堆），所以要提前用前缀和算好，不要放进 `min` 里重复计算。

边界 `dp[i][i] = 0`（单独一堆，不需要合并）。

**处理圆圈——断环成链**：把 `n` 堆石子的数组复制一份接在后面，变成长度 `2n` 的数组。这样，圆圈上"从任意一堆开始、连续 `n` 堆"的选法，都对应长度 `2n` 数组里的一个长度为 `n` 的区间。对这个 `2n` 长度的数组正常做区间 DP，最后枚举"从哪一堆开始展开成链"（`i` 从 `1` 到 `n`），取 `dp[i][i+n-1]` 里最小的一个。

**为什么这样能保证枚举到所有圆圈上的合并方式**：圆圈展开成链后，任何"不跨越展开点"的连续 `n` 堆，都能在链上找到；而"断环成链"枚举了所有 `n` 个可能的展开点，等价于圆圈上所有可能的位置都被当过一次"链的起点"，所以不会漏掉任何一种圆圈上的选法。

## 代码逐行讲解
```cpp
for (int len = 2; len <= n; len++) {
    for (int i = 1; i + len - 1 <= m; i++) {
        int j = i + len - 1;
        ...
        for (int k = i; k < j; k++) {
            dp[i][j] = std::min(dp[i][j], dp[i][k] + dp[k + 1][j] + segSum);
        }
    }
}
```
- **区间 DP 的循环顺序很关键**：必须**按区间长度从小到大**遍历（外层 `len`），保证算 `dp[i][j]` 时，所有比它短的区间（`dp[i][k]`、`dp[k+1][j]`）都已经算好了。这和前面"网格 DP 按行/列顺序推"、"背包 DP 按物品顺序推"是同一个道理，只是这次"规模从小到大"体现在区间长度上。

## 易错点
- **循环顺序写错**：如果按 `i` 从小到大、`j` 从小到大遍历（而不是按 `len`），可能在 `dp[i][j]` 还没算出来的情况下就去用它，得到错误结果——区间 DP 必须按"区间长度"这个真正的"规模"来排循环顺序。
- **忘记断环成链**：直接对原始 `n` 堆做区间 DP，只能算出"直线排列"下的最优解，会漏掉"跨越首尾"的合并方式。
- 数据类型：代价累加可能超过 `int` 范围（本题上限约 `100 × 100 × 100`，属于中等规模但仍建议用 `long long` 保持稳妥）。
