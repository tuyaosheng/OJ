# 合唱队形 讲解稿

## 考点
把第 19 章学过的 LIS 模型用两次，正向反向各跑一遍再合并——练习"组合已有模型解决新问题"的能力。

## 引入（1 分钟）
先问学生："先增后减"的山峰形状，能不能拆成两个更简单的部分？——引导他们想到：拆成"上升的前半段"和"下降的后半段"，而这两段分别就是标准的最长上升子序列问题（下降段倒过来看也是上升）。

## 核心推导（重点，讲透）
**转化问题**：与其直接想"怎么让出列的人最少"，不如反过来想"**剩下的人组成的队形最多能有多少人**"，答案就是 `n` 减去这个最大值——这个"正难则反"的转化技巧，在很多最优化问题里都很好用。

**拆成两次 LIS**：
- 正向跑一遍 LIS：`L[i]` = 以第 `i` 位同学**结尾**的最长上升子序列长度（第 19 章的原版模板，直接复用）；
- 反向跑一遍 LIS：`R[i]` = 以第 `i` 位同学**开头**、往右看的最长下降子序列长度（等价于把数组倒过来，求"以 `i` 结尾的最长上升子序列"）。

对每一位同学 `i`，如果让他当"峰顶"，能组成的队形长度是 `L[i] + R[i] - 1`——`i` 自己在 `L[i]` 和 `R[i]` 里各被算了一次，要减掉重复的那一次。枚举所有 `i`，取 `L[i]+R[i]-1` 的最大值，就是"剩下的人最多能组成的队形长度"。

## 代码逐行讲解
```cpp
for (int i = 1; i <= n; i++) {           // 正向 LIS
    L[i] = 1;
    for (int j = 1; j < i; j++)
        if (h[j] < h[i]) L[i] = std::max(L[i], L[j] + 1);
}
for (int i = n; i >= 1; i--) {           // 反向 LIS
    R[i] = 1;
    for (int j = n; j > i; j--)
        if (h[j] < h[i]) R[i] = std::max(R[i], R[j] + 1);
}
```
- 两段代码结构几乎一样，只是遍历方向相反——正向从左往右求"以 i 结尾"，反向从右往左求"以 i 开头（往右看）"。

## 易错点
- **忘记减 1**：`L[i] + R[i]` 会把第 `i` 位同学自己重复计算两次，一定要减掉多算的那一次。
- **峰顶不一定在中间**：`L[i]+R[i]-1` 要对**每一位**同学都算一遍并取最大值，不能想当然地只看中间位置——峰顶可以在队伍的任何一个位置，甚至是最左端或最右端（此时队形退化成纯上升或纯下降）。
- 别忘了最后要用 `n` 减去最大队形长度，直接输出最大队形长度不是题目要的答案。

## 课堂串讲提示
这题很适合作为本章（乃至第 19～21 章整个动态规划板块）的收尾：它不引入任何新算法，纯粹考察"能不能把学过的模型灵活组合起来解决新问题"——这正是动态规划学习到一定阶段后，比"记住更多模板"更重要的能力。
