# 矿区资源统计——讲解稿

## 一、题目解读

矩形区域求和、查询多达 5 万次——一维前缀和（本章例1）的二维升级版。矿区只是皮，考点是**二维前缀和**的两个容斥公式。

## 二、思路分析

先算复杂度账：朴素做法每次查询最坏累加 500×500 = 25 万格，5 万次查询就是 1.25×10^10 次运算，必超时。所以要"预处理一次，查询 O(1)"。

**建表**：s[i][j] = 从 (1,1) 到 (i,j) 的矩形总和。递推时用"上面的大块 + 左边的大块"，两块的公共部分（左上角矩形）被算了两次，减掉一次，再加上自己：

s[i][j] = s[i-1][j] + s[i][j-1] - s[i-1][j-1] + a[i][j]

**查询**：目标矩形 = 大矩形 s[x2][y2] 挖掉上边条和左边条；两条的公共部分（左上角）被减了两次，补回一次：

ans = s[x2][y2] - s[x1-1][y2] - s[x2][y1-1] + s[x1-1][y1-1]

两个公式是同一种思想：**容斥——重叠的部分加减找平**。一定对着图各推一遍，别背。

## 三、代码讲解

- 下标从 1 开始，s 的第 0 行/列天然是 0，公式对边界（x1=1 或 y1=1）自动成立——这就是"多开一行一列"的价值；
- `ios::sync_with_stdio(false); cin.tie(0);`：25 万个数的读入，不加速可能就在 IO 上超时；
- 前缀和数组用 long long（本题峰值 2.5×10^7 虽然 int 够，但"区间和用 ll"值得养成肌肉记忆）。

## 四、易错点

1. 建表漏减 s[i-1][j-1] → 重叠区重复计算，样例都过不了；
2. 查询公式最后一项忘了**加回** → 差一块左上角；
3. x1-1、y1-1 在下标从 0 存时会变 -1 越界——从 1 存就没这事；
4. 忘了读入加速，大测试点超时。

## 五、小结

一维前缀和管"线段"，二维前缀和管"矩形"，都是"预处理换查询"。想继续升级？"二维差分"（矩形区域整体加值）就是它的逆运算，欢迎自己推推看。
