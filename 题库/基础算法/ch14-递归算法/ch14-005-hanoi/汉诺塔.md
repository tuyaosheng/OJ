# 讲解稿：汉诺塔（ch14-005）

## 一、题目解读

三根柱子 A、B、C。A 上有 n 个盘子（大的在下、小的在上）。要把它们**全部移到 C**，规则：

1. **每次只能移动一个**盘子（且只能移最顶上的）；
2. **任何时候，大盘不能压在小盘上**。

输出总步数和每一步怎么移。

**汉诺塔是递归的"镇山之宝"。** 它完美诠释了递归最迷人的那一面——

> **你根本不需要想清楚每一步，问题就解决了。**

## 二、思路分析

### 先破除一个误区

初学者拿到这题，往往会试图**在脑子里推演每一步**：

"第一步把最小的移到 C，第二步把第二小的移到 B，第三步……"

**打住。** n = 5 时有 31 步，n = 15 时有 32767 步。**你的大脑不可能推演清楚。**

**这正是递归存在的意义**：把"想清楚所有步骤"这个不可能的任务，换成"**只想清楚一层**"这个简单的任务。

### 核心：递归信仰

请接受一个"信念"：

> **假设我已经有了一个函数 `hanoi(k, ...)`，它能正确地移动 k 个盘子。**
> **（哪怕我还不知道它内部怎么工作——先信它！）**
>
> **那么，我该怎么用它来移动 n 个盘子？**

这个思维跳跃，叫做**递归信仰（Recursive Faith）**。它是掌握递归的**关键心法**。

### 三步瓦解汉诺塔

要把 **n 个盘子**从 **A** 移到 **C**（B 当中转站）：

```
      A              B              C
   ┌──┴──┐
   │ 上面 │
   │n-1个 │
   ├─────┤
   │ 第n号 │  ← 最大的
   └─────┘
```

**第 ① 步**：把上面的 **n−1 个**盘子，从 **A** 挪到 **B**（借助 C 当中转）。

> **怎么挪？我不管！** 这是一个规模为 **n−1** 的**同类问题** —— 直接调用 `hanoi(n-1, A, C, B)`，**信任它能搞定**。

**第 ② 步**：现在 A 上只剩**最大的第 n 号**盘子，而 **C 是空的**。

> 直接把它从 **A 移到 C**。**一步到位！**
> （不用担心违规——它是最大的，而 C 是空的，怎么放都合法。）

**第 ③ 步**：把 B 上那 **n−1 个**盘子，从 **B** 挪到 **C**（借助 A 当中转）。

> 又是一个规模 n−1 的同类问题 —— 调用 `hanoi(n-1, B, A, C)`。

**完事了。** 就这么简单。

### 为什么这样是对的？

- **第 ② 步合法吗？** 合法。移动最大盘时，C 是**空的**（n−1 个盘子都在 B 上）。
- **第 ①③ 步合法吗？** 它们移动的是 n−1 个较小的盘子。这些盘子**都比第 n 号小**，所以就算把它们放在第 n 号上面（第 ③ 步），也不违规。而第 n 号盘子在 ①③ 步中**根本不动**，可以完全忽略它的存在。

**递归的正确性，只需要验证"一层"就够了。** 剩下的由数学归纳法保证。

## 三、代码讲解

**核心就三行**：

```cpp
// 把 n 个盘子，从 from 柱，借助 via 柱，移到 to 柱
void hanoi(int n, char from, char via, char to)
{
    if (n == 0) return;                     // 边界：没盘子可移

    hanoi(n - 1, from, to, via);            // ① n-1 个：from → via（借助 to）

    step++;                                 // ② 第 n 号：from → to
    cout << "第" << step << "步：将第" << n
         << "号盘子从" << from << "柱移动到" << to << "柱\n";

    hanoi(n - 1, via, from, to);            // ③ n-1 个：via → to（借助 from）
}
```

调用：`hanoi(n, 'A', 'B', 'C')`

### 唯一的难点：三个柱子参数的顺序

这是本题**最容易搞混**的地方。请紧盯函数签名的含义：

```
hanoi(要移几个, 从哪来, 借助谁, 到哪去)
```

| 步骤 | 目标 | 起点(from) | 中转(via) | 终点(to) |
|------|------|-----------|----------|---------|
| ① | n−1 个：A → B | **A** | **C** ← 变了！ | **B** |
| ③ | n−1 个：B → C | **B** | **A** ← 变了！ | **C** |

**规律**：**谁是终点，谁就不能当中转**。

- 第 ① 步终点是 B（原来的中转），所以中转换成了 **C**（原来的终点）。
- 第 ③ 步起点是 B，终点是 C，所以中转只能是 **A**。

**建议**：写代码时，把 `hanoi(n-1, ?, ?, ?)` 的三个问号，对着上表**一个一个填**，别凭感觉。

### 总步数：2^n − 1

设 T(n) 是移动 n 个盘子的步数。由三步曲直接得出：

**T(n) = T(n−1) + 1 + T(n−1) = 2·T(n−1) + 1**

配合 T(0) = 0，可以解出：

### **T(n) = 2^n − 1**

代码里用位运算 `(1 << n) - 1` 计算即可。

> **著名的传说**：印度神庙里有 **64 个**金盘。僧侣们日夜不停地移动，当全部移完时，世界就会毁灭。
>
> 需要多少步？**2^64 − 1 ≈ 1.8 × 10^19 步**。
> 就算每秒移一个盘子，也需要约 **5800 亿年** —— 而宇宙至今才 138 亿岁。
>
> **世界暂时是安全的。** 😄

## 四、易错点

1. **三个柱子参数写错顺序** —— **头号杀手**。移动序列全错。请对着表格逐一核对。
2. **试图用循环模拟** —— 逻辑复杂到爆炸。**这题就该用递归。**
3. **边界写错** —— `if (n == 0) return;`（或 `n == 1` 时直接输出一步）。
4. **输出格式不符** —— 本题要求严格的中文格式，注意是中文冒号"：",以及"第X步：将第Y号盘子从A柱移动到C柱"。
5. **步数用 int 且 n 很大** —— 本题 n ≤ 15，`(1<<15)-1 = 32767`，int 够用。但若 n 到 40，就得用 long long 了。

## 五、小结

### 递归信仰：本题最宝贵的收获

> **写递归时，不要试图在脑子里展开所有层次。**
>
> **你只需要做两件事**：
> 1. **假设** `f(n-1)` 已经能正确工作（**信任它！**）；
> 2. **想清楚**：如何用 `f(n-1)` 来构造 `f(n)`。
>
> 再加上一个**正确的边界**，递归就一定正确。（这背后是**数学归纳法**在为你撑腰。）

**很多人学不会递归，就是因为总想"跟踪"每一层调用**——那是在用大脑模拟计算机，注定失败。**要学会"信任"和"抽象"。**

### 汉诺塔的三步曲，是分治的完美范例

| 分治三部曲 | 汉诺塔 |
|-----------|--------|
| **分解** | 把 n 个盘子的问题，分成两个 n−1 的子问题 |
| **解决** | 递归解决子问题；中间那一步（移最大盘）直接做 |
| **合并** | 不需要额外合并——三步按顺序执行即可 |

### 本章递归题型总览

| 题 | 递归的用途 |
|---|-----------|
| 1 斐波那契 | **计算值**（+ 记忆化避免重复） |
| 2 进制转换 | **利用"返回途中"的顺序**（倒序输出） |
| 3 快速幂 | **分治**：每层砍半，O(log n) |
| 4 全排列 | **搜索**：穷举所有可能（回溯） |
| **5 汉诺塔** | **分治 + 递归信仰**：不想细节，只想一层 |
