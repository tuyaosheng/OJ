# 讲解稿：全排列问题（ch14-004）

## 一、题目解读

按字典序输出 1~n 的**所有全排列**。n = 3 时输出 6 行。

**这道题是本章、乃至整个算法学习的一个重要里程碑。** 你将第一次写出**回溯（Backtracking）**框架——它是下一章「搜索与回溯」的全部基础。

**请务必亲手写一遍**（虽然 C++ 有 `next_permutation` 可以偷懒）。这个框架的价值，怎么强调都不为过。

## 二、思路分析

### 思考方式：一个位置一个位置地填

不要试图"一次性生成所有排列"，而要想成**逐步做决策**：

> **第 1 个位置放谁？** —— n 种选择
> **第 2 个位置放谁？** —— 从**还没用过**的数里选，n−1 种
> **第 3 个位置放谁？** —— n−2 种
> **……**
> **全部填满后**，就得到了一个完整的排列，**输出它**。

这个"逐步做决策，走到底就得到一个答案"的过程，画出来就是一棵**决策树**：

```
                    (空)
          /          |          \
        [1]         [2]         [3]        ← 第1位填谁
       /   \       /   \       /   \
    [12]  [13]  [21]  [23]  [31]  [32]     ← 第2位填谁
      |     |     |     |     |     |
   [123] [132] [213] [231] [312] [321]     ← 第3位填谁（填满，输出！）
```

**每一条从根到叶的路径，就是一个排列。** 我们要做的，就是**把这棵树完整地走一遍**——这就是**深度优先搜索（DFS）**。

## 三、代码讲解：回溯三步曲

```cpp
int path[10];       // path[i] = 第 i 个位置填的数
bool used[10];      // used[v] = 数字 v 是否已被使用
int n;

void dfs(int pos)
{
    if (pos > n)                    // 【边界】填满了！
    {
        for (int i = 1; i <= n; i++)
            cout << path[i] << (i == n ? "\n" : " ");
        return;
    }

    for (int v = 1; v <= n; v++)    // 在第 pos 位，尝试每个数字
    {
        if (used[v]) continue;      // v 已被用过，跳过

        path[pos] = v;              // ① 做选择
        used[v] = true;             //    打标记

        dfs(pos + 1);               // ② 递归：去填下一位

        used[v] = false;            // ③ ★撤销★ 擦掉标记
    }
}
```

从 `dfs(1)` 开始。

### 灵魂所在：第 ③ 步「撤销」

```cpp
used[v] = false;        // 这一行，是回溯的心脏
```

**这是初学者最容易漏掉的一行，也是最重要的一行。**

**为什么必须撤销？** 我们来看具体场景（n=3）：

1. 第 1 位填 **1**（`used[1] = true`）
2. 深入下去，探索出 `1 2 3` 和 `1 3 2` 两个排列 ✓
3. 现在要**回来**，尝试第 1 位填 **2**

此时，如果我们**没有撤销**——`used[2]` 和 `used[3]` 还停留在上一个分支留下的 `true` 状态。

于是程序会认为"2 和 3 都已经被用过了"，**再也填不进任何数字**，导致**大量排列丢失**。

> ### 形象的比喻
>
> 递归就像**在迷宫里探路，一边走一边用粉笔做标记**。
>
> 走到死路（或走完一条路）要**往回退**时，**必须把沿途的粉笔印擦掉**——否则你去探索另一条岔路时，会被自己之前留下的标记误导，以为那些地方"已经走过了"。
>
> **来时做标记，走时擦标记。** 这就是**回溯**。

### 为什么天然就是字典序？

因为在每个位置上，我们都是 `for (int v = 1; v <= n; v++)` ——**从小到大**尝试。

所以决策树的分支天然按从小到大排列，**先被走到的路径，字典序一定更小**。

**不需要额外排序。** 优雅吧？

### 复杂度

O(n! × n)。n = 8 时，8! = **40320** 个排列，每个输出 8 个数 → 约 32 万次输出。很快。

（但请注意：n! 增长极快。n = 12 时就有 4.79 亿个排列了——**全排列类问题，n 通常不会超过 10~12**。看到 n 很小，就该想到"可能要爆搜"。）

## 四、易错点

1. **漏掉 `used[v] = false`（撤销）** —— **头号杀手**。会导致只输出第一个排列，或大量排列丢失。
2. **撤销的位置放错** —— 必须放在 `dfs(pos+1)` **之后**（回来的时候撤销），不能放在递归之前。
3. **忘记 `if (used[v]) continue`** —— 会生成 `1 1 1` 这种非法的"排列"。
4. **边界条件写成 `pos == n`** —— 应该是 `pos > n`（填完第 n 位后，pos 变成 n+1 才算填满）。
5. **`path` 和 `used` 的下标搞混** —— `path` 的下标是**位置**，`used` 的下标是**数字**。这两者含义完全不同，别写混了。

## 五、小结

### 回溯框架（请背下来）

```
void dfs(当前进行到哪一步)
{
    if (走到底了) { 记录/输出答案; return; }

    for (每一个可能的选择) {
        if (这个选择不合法) continue;

        做出选择（记录 + 打标记）;      // ①
        dfs(下一步);                    // ②
        撤销选择（擦掉标记）;            // ③  ★别忘了★
    }
}
```

**这个框架，是下一章所有题目的骨架。** 迷宫、八皇后、连通块、组合枚举……全都是它的变体。

**三步曲**：**选择 → 递归 → 撤销**。

### 什么时候需要撤销？

**看你的"状态"存在哪里**：

| 状态存放方式 | 需要撤销吗？ |
|-------------|-------------|
| **全局变量 / 全局数组**（如本题的 `used[]`） | **必须撤销！** 它会被所有分支共享、污染 |
| **函数参数**（每层独立的局部变量） | **不用撤销**。函数返回时自动恢复 |

（下一题「自然数拆分」的状态全靠参数传递，你会看到那里就**不需要**显式撤销。**对比着看，体会这个区别。**）

### 递归 → 搜索

到这里，我们对递归的认识完成了一次升华：

- 前几题的递归是在**计算一个值**（斐波那契、快速幂）；
- 这一题的递归是在**穷举所有可能**——这就是**搜索**。

> **搜索（DFS）= 递归 + 枚举所有选择 + 回溯撤销**
