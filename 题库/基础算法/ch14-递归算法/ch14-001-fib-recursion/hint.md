**朴素递归为什么慢？——大量的重复计算**

我们画出 `fib(5)` 的调用树看看：

```
              fib(5)
            /        \
       fib(4)         fib(3)
      /      \        /     \
   fib(3)   fib(2) fib(2)  fib(1)
   /    \
fib(2)  fib(1)
```

数一数：**`fib(3)` 被算了 2 次，`fib(2)` 被算了 3 次！**

n 越大，重复越恐怖。朴素递归的复杂度是 **O(2^n)** ——指数级！n = 90 时约 2^90 次调用，宇宙毁灭都算不完。

**同一个子问题被反复计算**，这就是朴素递归的致命伤。

---

**解药：记忆化（Memoization）**

思路极其简单：**算过的结果，存下来；下次要用，直接取。**

```cpp
long long memo[95];        // memo[i] 存 F(i)，0 表示"还没算过"

long long fib(int n)
{
    if (n <= 2) return 1;                  // 递归边界

    if (memo[n] != 0) return memo[n];       // ★ 查表：算过就直接返回，不再递归

    memo[n] = fib(n - 1) + fib(n - 2);      // ★ 算完存表
    return memo[n];
}
```

**加了两行，复杂度从 O(2^n) 骤降到 O(n)！**

因为每个 `fib(i)` 现在**最多只会被真正计算一次**，之后都是查表 O(1)。

这个技巧叫**记忆化搜索**，它是**递归**与**动态规划**之间的桥梁——本质上，它就是"**用递归的写法，实现了递推的效率**"。

---

**数据范围提醒**：

- F(90) = **2880067194370816120**，约 2.9 × 10^18。
- `long long` 上限约 9.2 × 10^18 —— **刚好装得下**（但 F(93) 就会溢出了）。
- 用 `int` 必挂（F(47) 就超了）。

**易错点**：
- 用 `memo[n] != 0` 判断"是否算过"是可行的（因为 F(n) 恒 > 0），但更严谨的做法是用 `-1` 初始化。
- 边界 `n <= 2` 返回 1，别写成 `n <= 1`。
