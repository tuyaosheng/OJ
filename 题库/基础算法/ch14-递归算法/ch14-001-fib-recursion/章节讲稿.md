## 上课怎么开场

黑板上写一行大家都认识的东西：`F(1)=1, F(2)=1, F(n)=F(n-1)+F(n-2)`。"斐波那契数列，小学奥数班都学过，对吧？现在给你 n（1 到 90），求 F(n)，用递归写。"

有学生几乎不假思索就能写出来：

```cpp
long long fib(int n) {
    if (n <= 2) return 1;
    return fib(n - 1) + fib(n - 2);   // 看起来无比优雅
}
```

三行代码，工整得像一句数学定义的翻译。"提交上去，能过吗？" 让学生猜。公布答案：**超时**，而且不是差一点超时，是 n=90 的时候，这段代码大概要跑到天荒地老。三行代码，为什么会跑不动？这就是今天要搞明白的第一件事。

在往下讲之前，先把"递归"这个词钉死：**递归 = 函数在自己的函体里调用自己**，做法是**把一个大问题，变成一个一模一样、但规模更小的问题，一直变小，直到小到可以直接给出答案**。第 13 章的递推是"从小往大推"，递归恰好反过来，是"从大往小拆"，方向相反，本质上是同一件事的两种走法。但从今天开始你会发现：有一类问题（枚举所有方案、树形结构、汉诺塔），递归几乎是唯一顺手的写法，硬要写成循环反而别扭。

递归要写对，必须同时具备两样东西，缺一个都会出事：

1. **递归边界**：规模小到什么程度就不再往下调，直接给答案；
2. **递归式**：大问题怎么用规模更小的同类问题表示，而且规模必须**严格变小**——不然就是死循环，或者说得更准确一点，是**一直往下调用直到把函数调用栈耗尽，程序崩溃退出（Segmentation Fault）**。

## 递归的代价：把 fib(5) 的调用树画在黑板上

回到刚才超时的三行代码。别急着改，先画图看看它到底在干什么。黑板上画 `fib(5)` 的调用树，一层一层往下拆：

```
                      fib(5)
                     /      \
               fib(4)        fib(3)
              /     \        /    \
        fib(3)     fib(2) fib(2) fib(1)
        /    \
   fib(2)   fib(1)
```

现在带着学生一个节点一个节点地数：`fib(3)` 这个调用，出现了几次？——**两次**（一次在 `fib(4)` 下面，一次在 `fib(5)` 直接的右边）。`fib(2)` 呢？——**三次**。同一个值，被从头到尾**完全重复地算了好几遍**，而且这棵树画的还只是 n=5，n 稍微大一点，重复的部分会跟着指数级增长。数一数这棵树总共有多少个节点（也就是总共调用了多少次 `fib`）：把每个节点算一遍，一共是 **9 次调用**，而 n 每增加 1，调用次数大约变成原来的 1.6 倍左右，滚雪球一样滚下去——这就是为什么 n=90 会跑不完：**问题不在于数学公式错了，而在于同一个子问题被一遍又一遍地从头算起**。这类"看起来是多项式，实际是指数级"的复杂度，教科书里通常粗略地记作 **O(2ⁿ)**。

问题诊断出来了，药方也就呼之欲出：**已经算过的答案，为什么不存起来？** 开一个数组 `memo[]`，`memo[i]` 存 `F(i)` 算过的结果，算之前先看看是不是已经有了：

```cpp
long long memo[95];
long long fib(int n) {
    if (n <= 2) return 1;
    if (memo[n] != -1) return memo[n];      // 查过表了，直接交货，不再往下递归
    memo[n] = fib(n - 1) + fib(n - 2);      // 没算过，才真的往下拆
    return memo[n];
}
```

`memo` 数组初始化成 -1（表示"还没算过"，不能用 0，因为 0 有可能真的是某个子问题的正确答案）。加了这三行之后再画一遍 `fib(6)` 的调用树：`fib(4)` 第一次被 `fib(5)` 那条分支算出来、存进 `memo[4]`；等 `fib(6)` 自己的右边再问一次 `fib(4)` 的时候，直接从 `memo[4]` 里读，**连子调用都不用发生**，那一整片原本会重新展开的子树，直接被剪掉了。同样是 n=6，没有记忆化要调用 15 次，加上记忆化之后只要 9 次——n 越大，这个差距越夸张。

到这里切到 `递归调用树演示.html`：先把"记忆化"关掉，n 填 6，点"下一步"一步步展开，让学生亲眼看着调用数一路涨上去，被判定为"重复计算"的节点会标橙色；然后勾上"开启记忆化"重新生成一遍，同一个 n=6，看着树在该剪的地方直接停住，变成一个个"查表命中"的橙色虚线框，不再往下长。**一句话记住这一段**：递归本身只是一种思维方式，不是免费的午餐；一旦发现子问题在重复，第一反应就是"记下来，别再算第二遍"——这正是通往动态规划（第 19～21 章）的第一步桥梁。

## 归来的路上：为什么递归天然会"倒过来"

换一道题：把十进制数转成 k 进制。手算 `30` 转十六进制的过程大家都熟：

```
30 ÷ 16 = 1 余 14 → E
 1 ÷ 16 = 0 余 1
```

余数是**从低位往高位**一个个冒出来的：先得到个位 `E`，再得到高位 `1`。可是输出的时候，要**先写高位再写低位**：`1E`。顺序整个反了。如果用循环写，得先把每次的余数塞进一个数组，算完了再倒着从数组尾巴打印出来——这就是第 11 章高精度里"倒着存、倒着读"那一套麻烦事的翻版。

递归有个更省心的办法。请学生把这几行代码在脑子里跑一遍：

```cpp
void conv(int n, int k) {
    if (n == 0) return;
    conv(n / k, k);              // 先把高位的事情交给递归去办
    putchar(digit[n % k]);       // 这一句，是在"归"的路上才执行的
}
```

带着 `conv(30, 16)` 走一遍："递"的阶段（也就是不断往下调用、还没返回的阶段）：`conv(30,16)` 先调 `conv(1,16)`（30/16=1），`conv(1,16)` 又先调 `conv(0,16)`（1/16=0）。`conv(0,16)` 命中边界 `n==0`，直接 `return`，什么也不输出。**这时候开始"归"**——从最里面往外一层层退出去：先退回 `conv(1,16)`，它的递归调用已经结束，接着往下执行 `putchar(digit[1 % 16])`，也就是打印 `1`；再退回最外层 `conv(30,16)`，执行 `putchar(digit[30 % 16])`，打印 `digit[14]`，也就是 `E`。两次打印按"归"的顺序发生，先打印 `1` 再打印 `E`，屏幕上出现的就是 `1E`——**顺序天然就是对的，一次都没有手动倒过来**。

记住这句话：**写在递归调用之后的语句，是在"归"的路上执行的**。函数调用栈本身就是一个天然的"后进先出"结构，递归调用之后的代码，等价于"从栈里往外弹的时候顺便做一件事"——想明白这一点，后面看任何递归代码，你都能一眼分清哪部分是"去程"、哪部分是"回程"。

## 分治：把指数一劈两半的快速幂

再换一道题：算 `aᵇ mod p`，其中 b 可能大到 10¹⁸。朴素做法是一个循环乘 b 次，`for (int i=1;i<=b;i++) ans = ans*a%p;`——这个循环得跑 10¹⁸ 次，就算电脑一秒算十亿次，也得算上三十多年，**明摆着不可行**。

递归给出的方案很干脆：**把指数砍一半**。核心式子只有一条：

```
a^b = (a^(b/2))²          （b 是偶数）
a^b = (a^(b/2))² × a      （b 是奇数，多出来的那一次单独补上）
```

拿 `3¹³` 走一遍手算（先不取模，光看指数怎么往下砍）：

```
b=13（奇）→ 需要 3^6，算出来再平方、再补乘一个 3
  b=6（偶）→ 需要 3^3，算出来再平方
    b=3（奇）→ 需要 3^1，算出来再平方、再补乘一个 3
      b=1（奇）→ 需要 3^0=1，平方还是 1，再补乘一个 3 → 3^1 = 3
    3^3 = 3² × 3 = 3 × 3 × 3 = 27
  3^6 = 27² = 729
3^13 = 729² × 3 = 531441 × 3 = 1594323
```

对一下：`3¹³` 直接算确实是 `1594323`，没错。数一数上面一共递归了几层——`13 → 6 → 3 → 1 → 0`，**只有 5 层**，而不是乘了 13 次。指数每往下一层就减半，`b=10¹⁸` 时，`log₂(10¹⁸) ≈ 60`，也就是说**只要大约 60 次乘法**，比刚才的三十多年，是天壤之别。翻译成代码：

```cpp
long long qpow(long long a, long long b, long long p) {
    if (b == 0) return 1;
    long long half = qpow(a, b / 2, p);
    long long res = half * half % p;
    if (b % 2 == 1) res = res * a % p;
    return res;
}
```

**分治，其实就是递归的"提速"用法**：不是像斐波那契那样把问题拆成两个差不多大的子问题去枚举，而是每一步都把规模干脆利落地砍掉一半。取模版快速幂是数论章的标配写法，这里先把骨架焊牢，以后直接照搬。

## 回溯三步曲：全排列——本章最重要的一段

前面几道题，递归都是"算出一个值"。这道题不一样：要**穷举**——把 1~n 的所有排列全部找出来。这是本章的重头戏，因为下一章整整一章的"搜索与回溯"，都在反复使用今天要立住的这个模板。

拿 n=3 举例，先想清楚该怎么"试"：第一个位置可以放 1、2 或 3；不管第一个位置放的是谁，第二个位置只能从"剩下没放过的数"里选；第三个位置就只剩最后一个数了。画出这棵"选择树"：

```
第1位选1 → 第2位选2 → 第3位只能选3 → 输出 1 2 3
                 → 第2位选3 → 第3位只能选2 → 输出 1 3 2
第1位选2 → 第2位选1 → 第3位只能选3 → 输出 2 1 3
                 → 第2位选3 → 第3位只能选1 → 输出 2 3 1
第1位选3 → 第2位选1 → 第3位只能选2 → 输出 3 1 2
                 → 第2位选2 → 第3位只能选1 → 输出 3 2 1
```

六种排列，一个不多一个不少。现在把"试"这个动作拆成三个明确的步骤——这三步请学生跟着念，最好背下来：

```cpp
void dfs(int step) {
    if (step == n + 1) { 输出当前排列; return; }       // 边界：n 个位置都填满了
    for (int i = 1; i <= n; i++) {
        if (used[i]) continue;
        used[i] = true;  a[step] = i;                  // ① 选择：占用这个数
        dfs(step + 1);                                 // ② 递归：去填下一个位置
        used[i] = false;                                // ③ 撤销：把现场恢复原状
    }
}
```

**"选择 → 递归 → 撤销"**，念十遍。用 n=3 的例子对一下第③步为什么少不了：走完"第1位选1，第2位选2，第3位选3"这一整条路径后，代码要退回第2位这一层，尝试"第2位选3"——如果第①步选 2 的时候没有在③把 `used[2]` 改回 `false`，那么退回来之后，数字 2 会一直被标记成"已经用过"，导致后面**永远选不到它**，第2位就只能干瞪眼，整个分支断掉，只会打印出一条排列就结束。**撤销的意义就是让"退回上一层"和"从来没走过这条路"看起来一模一样**，这样兄弟分支才能公平地重新尝试每一种可能。

这一段务必讲透、讲熟，最好当堂让学生对着黑板默写一遍这三行骨架——因为下一章的组合、迷宫、N 皇后，全都是在这个骨架上加东西，不会有第二个新模板。

## 递归信仰：汉诺塔

三根柱子 A、B、C，n 个盘子按大小顺序摞在 A 柱上，要求一次挪一个、任何时候大盘不能压小盘，全部挪到 C 柱。新手写这题最容易掉进的坑，是**想在脑子里全程跟踪每一个盘子此刻在哪根柱子上**——盘子一多，脑子直接死机。

递归给出的思路完全不用跟踪细节，只需要想清楚"一层"该怎么拆：

1. 先把上面 n−1 个盘子，想办法（不管具体怎么挪）从 A 挪到 B（借助 C 做中转）；
2. 这时候 A 上只剩最大的那个盘子，直接把它从 A 挪到 C；
3. 再把刚才那 n−1 个盘子，想办法从 B 挪到 C（借助 A 做中转）。

第 1 步和第 3 步里"想办法挪过去"，其实就是**同一个问题、规模从 n 变成了 n−1**——原地又递归了一次。代码只有三行核心逻辑：

```cpp
void hanoi(int n, char from, char to, char via) {
    if (n == 0) return;
    hanoi(n - 1, from, via, to);   // 先把上面 n-1 个，从 from 挪到 via（借助 to）
    printf("%c -> %c\n", from, to);// 挪走最底下最大的这一个
    hanoi(n - 1, via, to, from);   // 再把 n-1 个，从 via 挪到 to（借助 from）
}
```

拿 n=3 手动展开一遍，看看这三行到底会打印出什么。调用 `hanoi(3, A, C, B)`：

```
hanoi(3,A,C,B)
├─ hanoi(2,A,B,C)
│   ├─ hanoi(1,A,C,B)
│   │   ├─ hanoi(0,...) 直接返回
│   │   ├─ 打印：A -> C     ← 第1步
│   │   └─ hanoi(0,...) 直接返回
│   ├─ 打印：A -> B         ← 第2步
│   └─ hanoi(1,C,B,A)
│       ├─ hanoi(0,...) 直接返回
│       ├─ 打印：C -> B     ← 第3步
│       └─ hanoi(0,...) 直接返回
├─ 打印：A -> C             ← 第4步（最大的盘子，A 直接到 C）
└─ hanoi(2,B,C,A)
    ├─ hanoi(1,B,A,C)
    │   └─ 打印：B -> A     ← 第5步
    ├─ 打印：B -> C         ← 第6步
    └─ hanoi(1,A,C,B)
        └─ 打印：A -> C     ← 第7步
```

一共 7 步：`A→C, A→B, C→B, A→C, B→A, B→C, A→C`。拿真实的三个盘子（或者三摞硬币）当堂摆一遍，跟黑板上这 7 步逐条对照，验证确实每一步都没有大压小——**全对**。

初学者最大的心理障碍是"总想在脑子里全程盯着每一步"，这道题恰恰是要**戒掉**这个习惯：只想清楚"一层"该怎么拆（第 1、2、3 步），然后**选择相信递归会正确地处理规模更小的那部分**（这是有数学归纳法背书的：n=0 边界对，假设 n−1 时递归调用一定正确，就能推出 n 时也正确）。建立起这份"递归信仰"，你才能写出稍微复杂一点的递归代码而不崩溃。

顺带留一个尾巴：总步数 `T(n) = 2·T(n-1) + 1`，算出来是 `T(n) = 2ⁿ - 1`（n=3 时 `2³-1=7`，跟黑板上数出来的步数对上了），这是一个标准的递推式，跟第 13 章正好握手。

## 带约束的枚举：自然数拆分

最后一道练习，回到"回溯"这条线上，但多了一个新麻烦。把 n 拆成若干个正整数之和（至少两个数），规定拆出来的数**非递减**，这样 `1+3` 和 `3+1` 就只算一种，不会被数两次。

拿 n=5 举例，先想：如果直接照抄全排列的写法——每次可以从 1 到 n 里任选一个数，直到凑够 n——会出什么问题？`1+1+3` 和 `1+3+1` 会被当成两种不同的方案，可它们其实是同一种拆分，重复了。

解决办法是给递归传一个 `start` 参数，**规定这一次选的数，必须不小于上一次选的数**：

```cpp
void dfs(int sum, int start) {
    if (sum == n) { 输出当前方案（数的个数≥2才算）; return; }
    for (int i = start; sum + i <= n; i++) {
        a[len++] = i;
        dfs(sum + i, i);      // 注意：下一层的 start 还是 i，不是 i+1——因为同一个数可以重复选
        len--;                 // 撤销，和全排列的第③步一模一样
    }
}
```

拿 n=5 走一遍，凡是"这次选的数 ≥ 上次选的数"的路径才会被尝试，最终会依次得到：`1+1+1+1+1`、`1+1+1+2`、`1+1+3`、`1+2+2`、`1+4`、`2+3`，一共 **6 种**——重复方案根本不会被生成出来，不用算完再去重。**用参数携带约束，把"不重不漏"从"事后去重"变成"从一开始就不产生"**，这个技巧下一章讲组合问题时还会再用一次，是本章埋的一个伏笔。

## 学生最容易栽的坑

1. 忘写边界，或者边界写了但永远走不到 → 无限递归 → 爆栈（Segmentation Fault）；
2. 递归参数没有真的"变小"（比如快速幂传错了指数），效果等同于没边界；
3. 全排列/自然数拆分忘记**撤销**（`used[i]=false` 或 `len--`）→ 只输出一条链就没了；
4. 记忆化数组忘了初始化成"未计算"标记（比如误用 0，而 0 恰好是某个合法答案）；
5. 快速幂的奇偶分支写反或漏写（b 为奇数时别忘了多补乘一次 a）；
6. 递归深度没数：n=10⁵ 这种线性递归可能直接爆栈，这种场合应该改回循环/递推来写。
