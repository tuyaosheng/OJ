# 讲解稿：自然数拆分（ch14-006）

## 一、题目解读

把自然数 n 拆成**若干个（至少 2 个）正整数之和**，输出所有方案。

要求：每个方案内**从小到大**排列，方案之间按**字典序**输出。

n = 5 时有 6 种：
```
1 1 1 1 1
1 1 1 2
1 1 3
1 2 2
1 4
2 3
```

**注意**：`2 3` 和 `3 2` 算**同一种**拆分（顺序无关）。

**本题的核心挑战，是一个全新的问题**：

> ### **如何做到"不重不漏"？**

## 二、思路分析

### 问题：天真的枚举会重复

假如我们不加任何限制，每一层都从 1 到 rest 随便选：

- 一条路径选出 `2, 3` → 输出 `2 3`
- 另一条路径选出 `3, 2` → 输出 `3 2`

**它们是同一种拆分，却被数了两次！** n 一大，重复会多到失控。

### 妙招：强制「非递减」

解决办法极其巧妙，也极其简单：

> ### **规定：后选的数，必须 ≥ 先选的数。**

这样一来：

- `2 3` ✓ 合法（3 ≥ 2），会被生成；
- `3 2` ✗ 非法（2 < 3），**根本不会被生成**。

于是**每一种拆分，有且仅有一个合法的表示形式**（就是它从小到大排列的那个）——

### **天然不重不漏！** ✓

**而且顺便还满足了题目"每个方案内从小到大排列"的要求。** 一石二鸟。

### 怎么实现"非递减"？——加一个 `start` 参数

给递归函数加一个参数 `start`，含义是：**这一层，最小只能从 start 开始选**。

```cpp
// rest  = 还剩多少没拆
// start = 这一层最小能选的数（这就是"非递减"的守门员）
// cnt   = 已经选了几个数
void dfs(int rest, int start, int cnt)
{
    if (rest == 0)                  // 拆完了
    {
        if (cnt >= 2)               // 题目要求至少 2 个数
        {
            for (int i = 0; i < cnt; i++)
                cout << path[i] << (i == cnt - 1 ? "\n" : " ");
        }
        return;
    }

    for (int v = start; v <= rest; v++)     // v 从 start 起，保证非递减
    {
        path[cnt] = v;                      // 选择：把 v 记进方案
        dfs(rest - v, v, cnt + 1);          // 递归
    }
}
```

从 `dfs(n, 1, 0)` 开始。

### 关键的一行：`dfs(rest - v, v, cnt + 1)`

请注意第二个参数传的是 **`v`**，**不是 `v + 1`**！

**为什么？** 因为**允许重复使用同一个数**（比如 `1 1 1 1 1`）。传 `v` 意味着"下一层最小还可以选 v"。

> **如果传 `v + 1`**，就变成"每个数最多用一次"了 —— 那会得到 `1 4`、`2 3` 但没有 `1 1 3`。
> 那是另一类问题（叫"**不重复的拆分**"）。**一个字符之差，问题完全不同。**

## 三、代码讲解

### 为什么这题【不需要】显式撤销？

上一题（全排列）里，我们反复强调**必须**写 `used[v] = false`（撤销）。

**这题为什么没有撤销那一行？** 是我忘了写吗？

**不是。请对比两题的"状态存放方式"**：

| | 全排列 | 自然数拆分（本题）|
|---|--------|------------------|
| **状态怎么存** | 全局数组 `used[]` | **函数参数** `rest`、`start`、`cnt` |
| **会被污染吗** | **会！** 所有递归分支**共享**同一个 `used[]` | **不会**。参数是**每层独立**的局部变量 |
| **需要撤销吗** | **必须！** 手动 `used[v] = false` | **不需要**，返回时自动恢复 |

**关键理解**：

- `used[]` 是**全局的**——你在深层改了它，回到浅层它还是被改过的状态。**必须手动擦。**
- `rest` / `start` / `cnt` 是**参数**——每一层调用都有自己的一份副本。深层怎么折腾，都不影响浅层。**函数返回时，浅层的参数原封不动。**

那 `path[cnt]` 呢？它是全局数组啊，为什么不用撤销？

因为我们**只使用 `path` 的前 `cnt` 个元素**（输出时 `for i < cnt`）。后面残留的"脏数据"根本不会被读取，且下一轮循环会直接把 `path[cnt]` 覆盖掉。**无害。**

> ### 经验总结（重要！）
>
> **状态用【参数】传递 → 不用撤销**（每层独立，自动恢复）
> **状态用【全局变量】记录 → 必须撤销**（全局共享，会被污染）
>
> **能用参数传就用参数传**——代码更安全，不容易忘记撤销。

### 其余细节

**至少 2 个数**：在边界处判断 `if (cnt >= 2)`。

若不判断，`dfs(5, 1, 0)` 会走出一条路径：直接选 `5` → `rest = 0`, `cnt = 1` → 输出 `5`。但题目说"至少两个数"，`5 = 5` 不算拆分。**必须排除。**

**为什么天然是字典序？** 每层都 `for (v = start; ...)` **从小到大**枚举。

**复杂度**：等于方案数（n=30 时 **5603** 种）。完全能承受。

## 四、易错点

1. **不加 `start` 参数** —— 生成大量重复方案（`2 3` 和 `3 2` 都输出）。**头号问题。**
2. **递归传 `v + 1` 而不是 `v`** —— 无法重复使用同一个数，丢失 `1 1 3` 这类方案。
3. **忘记 `cnt >= 2` 的判断** —— 多输出一行 `n` 本身。
4. **`v <= rest` 的上界写错** —— 写成 `v <= n` 会导致拆超（rest 变成负数），无限递归。
5. **画蛇添足地"撤销"** —— 虽然多写不会错，但说明没理解参数与全局变量的区别。

## 五、小结

### 本题的三大收获

**① 用「非递减」约束实现"不重不漏"**

这是组合枚举的**万能套路**：

> **当"顺序无关"时（`2 3` 和 `3 2` 算同一个），就强制规定一个顺序（如非递减），只生成"标准形式"的那一个。**

这个技巧在**组合枚举、子集枚举**中会反复出现。下一章的「选数」问题，用的正是同一招。

**② 理解"何时需要撤销"**

| 状态载体 | 撤销 |
|---------|------|
| 函数参数 | 不用（自动恢复）|
| 全局变量/数组 | **必须**（会被污染）|

**③ `v` 还是 `v+1`：一字之差，两种问题**

- 传 `v` → **可重复选**（本题：`1 1 1 1 1` 合法）
- 传 `v+1` → **每个数只能选一次**（组合问题）

### 第 14 章总结：递归的五张面孔

| 题 | 递归在做什么 | 核心技巧 |
|---|-------------|---------|
| 1 斐波那契 | 计算一个值 | **记忆化**（避免重复计算，O(2^n) → O(n)）|
| 2 进制转换 | 利用返回顺序 | **`cout` 放递归后 → 自动倒序** |
| 3 快速幂 | 分治加速 | **每层砍半**，O(log n)；**存变量复用** |
| 4 全排列 | 穷举所有可能 | **回溯三步曲**：选择 → 递归 → **撤销** |
| 5 汉诺塔 | 分治 + 抽象 | **递归信仰**：只想一层，信任其余 |
| 6 自然数拆分 | 组合枚举 | **非递减约束** → 不重不漏 |

### 递归的三要素（务必牢记）

> **① 递归边界**：什么时候停？（**没有它 = 无限递归 = 爆栈**）
> **② 递归式**：如何把大问题拆成同类的小问题？
> **③ 返回/记录**：每层返回什么？或者把答案记在哪里？

### 递推 vs 递归：一体两面

| | 递推（第 13 章） | 递归（第 14 章） |
|---|-----------------|-----------------|
| **方向** | 自底向上（小 → 大） | 自顶向下（大 → 小） |
| **形式** | 循环 + 数组 | 函数调用自己 |
| **优点** | 高效，无栈开销 | 思路自然，贴近问题定义 |
| **缺点** | 有时难以想清"推的顺序" | 有栈开销，可能爆栈 |

**它们描述的是同一个递推关系，只是"走"的方向相反。** 而**记忆化搜索**，正是连接两者的桥梁。
