# 讲解稿：快速幂（ch14-003）

## 一、题目解读

求 **a^b mod p**，其中 **b 可达 10^18**。

**朴素做法**：循环 b 次，每次乘一个 a。

```cpp
for (long long i = 1; i <= b; i++)
    ans = ans * a % p;
```

复杂度 O(b)。b = 10^18 时——就算电脑每秒算 10 亿次，也要跑 **10^9 秒 ≈ 32 年**。

**快速幂**能把它压到 **O(log b)**：10^18 只需约 **60 次**乘法。

**32 年 → 60 次。** 这就是算法的力量。

## 二、思路分析

### 核心：分治

普通的幂运算是"一个一个乘"：`a^8 = a·a·a·a·a·a·a·a`（7 次乘法）。

但我们可以**成倍地跳**：

```
a^1 = a
a^2 = (a^1)²      ← 平方一次
a^4 = (a^2)²      ← 再平方
a^8 = (a^4)²      ← 再平方
```

**只用 3 次乘法就得到了 a^8！**

**关键洞察**：

### **a^b = (a^(b/2))²**

只要算出**一半**的幂，**平方一下**就得到了全部。而"一半的幂"又可以用同样的方法去算——**这就是递归**。

每递归一层，**指数砍掉一半**。从 10^18 砍到 1，只需 **log₂(10^18) ≈ 60 层**。

### 处理奇数：别忘了那个"零头"

如果 b 是奇数呢？比如 `a^9`。

整数除法 `9 / 2 = 4`（**余数 1 被丢掉了**）。所以 `(a^4)² = a^8`，比 `a^9` **少乘了一个 a**。

**补回来**：

### **b 是偶数：a^b = (a^(b/2))²**
### **b 是奇数：a^b = (a^(b/2))² × a**

**递归边界**：`a^0 = 1`。

## 三、代码讲解

```cpp
long long power(long long a, long long b, long long p)
{
    if (b == 0) return 1 % p;               // 边界

    long long half = power(a, b / 2, p);    // ★ 只算一次！
    long long res = half * half % p;        // 平方

    if (b % 2 == 1)                         // 奇数，补乘一个 a
        res = res * a % p;

    return res;
}
```

### 致命陷阱一：`half` 必须只算一次！

**千万不要**写成这样：

```cpp
return power(a, b/2, p) * power(a, b/2, p) % p;    // ✗ 大错特错！
```

看起来只是"写开了"，实际上**调用了两次递归**！

于是递归树又变成了每层分裂成 2 个分支的**指数级爆炸**——复杂度退化回 **O(b)**，快速幂完全白写。

**必须先把结果存进变量，再平方**：

```cpp
long long half = power(a, b/2, p);      // ✓ 只调用一次
long long res = half * half % p;        // 复用它
```

> **这个坑和第 1 题的斐波那契是同一个病根：重复计算。**
>
> 递归的效率杀手永远是"**同一个子问题被算了多次**"。斐波那契用**记忆化**解决，快速幂用**存变量复用**解决——本质都是"**算过的别再算**"。

### 致命陷阱二：`return 1 % p`，不是 `return 1`！

边界返回的是 `a^0 = 1`。看起来 `return 1` 天经地义。

**但如果 p = 1 呢？**

任何数 mod 1 都等于 **0**。所以 `a^0 mod 1 = 0`，**不是 1**！

如果你写 `return 1`，当 p=1 时答案就错了。正确写法是 **`return 1 % p`**（当 p=1 时它自动变成 0）。

> **测试数据里专门放了 p = 1 的一组，专治这个 bug。** 这种"取模为 1"的边界，是竞赛中经典的坑。

### 致命陷阱三：乘法溢出

`half * half` 时，`half` 最大接近 p，而 p ≤ 10^9。

`10^9 × 10^9 = 10^18`

`long long` 上限 ≈ **9.2 × 10^18** —— **刚好装得下** ✓

**但请注意这是"刚好"**。如果题目把 p 放宽到 10^18，那么 `half * half` 会达到 10^36，`long long` **必爆**。那时就需要 `__int128` 或者"**龟速乘**"（用加法模拟乘法）。

**本题 p ≤ 10^9，用 `long long` 安全。** 但要有这根弦。

### 别忘了先给 a 取模

```cpp
a %= p;     // 防止 a 本身就比 p 大
```

## 四、易错点

1. **递归调用两次** —— `power(...) * power(...)`，复杂度退化成 O(b)，超时。**头号杀手。**
2. **`return 1` 而不是 `return 1 % p`** —— p=1 时答案错。
3. **b 用 int** —— b 可达 10^18，必须 `long long`。
4. **忘记每步取模** —— 数值爆炸。
5. **忘记 `a %= p`** —— a 本身可能就比 p 大。

## 五、小结

### 快速幂的本质

> **把"乘 b 次"变成"平方 log b 次"。**

每次递归，指数减半。这是典型的**分治**——和第 12 章的快速排序、归并排序是同一家族。

| 做法 | 复杂度 | b = 10^18 |
|------|--------|-----------|
| 朴素循环 | O(b) | 10^18 次（32 年）|
| **快速幂** | **O(log b)** | **约 60 次** |

### 递归的两大效率杀手（复习）

到这里，我们已经见过递归的两个经典陷阱，它们其实是**同一个问题**：

| 题目 | 病症 | 解药 |
|------|------|------|
| 斐波那契 | 同一个 `fib(i)` 被算了无数次 | **记忆化**（存表查表）|
| 快速幂 | `power(a, b/2)` 被调用了两次 | **存进变量复用** |

> **递归的效率，取决于你有没有"重复劳动"。**

### 快速幂的广泛应用

- **求模意义下的幂**（本题）——密码学、组合数学的基础工具
- **矩阵快速幂** —— 把递推式（如斐波那契）加速到 O(log n)！
- **求逆元**（费马小定理：`a^(p-2) mod p` 就是 a 的逆元）

**它是竞赛中最常用的模板之一，请务必背熟。**
