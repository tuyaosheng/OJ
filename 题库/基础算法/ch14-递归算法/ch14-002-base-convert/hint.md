**递归为什么能"自动倒序"？**

关键在于：**先递归，后输出**。

```cpp
void convert(int n, int k)
{
    if (n == 0) return;             // 递归边界：除到 0 就停

    convert(n / k, k);              // ★ 先递归处理【高位】

    int r = n % k;                  // 当前这一位（最低位）
    cout << digit(r);               // ★ 后输出【当前位】
}
```

**执行顺序推演**（以 n=30, k=16 为例）：

1. `convert(30)` 被调用 → 它**先**去调用 `convert(1)`（还没输出任何东西！）
2. `convert(1)` 被调用 → 它**先**去调用 `convert(0)`
3. `convert(0)` → 触发边界，直接返回
4. 回到 `convert(1)` → 现在才输出 `1 % 16 = 1` → 打印 **`1`**
5. 回到 `convert(30)` → 现在才输出 `30 % 16 = 14` → 打印 **`E`**

最终输出：**`1E`** ✓

**看明白了吗？** 因为"输出"这个动作被放在了递归调用**之后**，所以它会在**递归返回的路上**执行——而返回的顺序，恰好和调用的顺序**相反**！

> **这就是递归的"回溯"特性**：去的时候一路深入（拆解问题），回来的时候一路执行（处理结果）。
> **想正序输出，就把 `cout` 放在递归【前面】；想倒序输出，就放在递归【后面】。** 一行代码的位置，决定了顺序。

**数位转字符**：

```cpp
char digit(int r)
{
    if (r < 10) return '0' + r;     // 0-9 → 字符 '0'-'9'
    else return 'A' + (r - 10);     // 10-15 → 字符 'A'-'F'
}
```

**特判 n = 0**：递归边界是 `n == 0` 时直接返回，所以 n 本身就是 0 时，**什么都不会输出**！必须**单独特判**，直接打印 `0`。这是本题最容易漏的坑。
